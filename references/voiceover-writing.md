# 完整口播写作与审查

用于新写、扩写、实质重组、审查或审查后改写完整口播、旁白、播客独白和主持连接语。它消费已经确认的内容真源、媒体文案合同、现实材料、作者声音证据、完整案例与钩子，不选择媒体载体、不研究新的核心结论、不维护参考库，也不进入配音、字幕和画面制作。

## 一、先锁定动作和停止位置

先区分本次动作：

- **只审查**：判断现稿是否可用，指出应保留的内容和造成问题的根因，给出有代表性的原句与修改方向；不交付替代全文，不改活动文案，完成诊断后停止。
- **审查后改写**：先判断问题位于内容、结构、作者位置、听众关系还是句子，再更新唯一活动文案。保留仍然成立的事实、判断和自然句子，不把“有 AI 痕迹”解释成整稿失败。
- **新写、扩写或实质重组**：从干净材料和实际声音证据直接成稿，不先生成提纲式套话再做表面润色。
- **逐字修订、等义压缩或确定性派生**：不进入本流程，交给轻量媒体文字路径。

用户已经确认的全文只有在用户明确要求改写时才能改变。要求改写但没有说明范围时，默认只改变表达组织和声音，不改变事实、主张、引语、数字与必要边界。

## 二、建立本次输入

至少接收：

- 当前内容真源及其确认状态；
- 本次动作、听众、载体、语言、时长、信息职责和必须保留内容；
- 适用时的 `editorial_position`；
- 当前指令、当前有效声音样稿、口播声音真源和声音候选的实际路径；
- 当前任务、用户、上游或口播私人库提供的完整案例与钩子实际路径；
- 允许使用的现实材料与可核对来源。

内容真源决定能说什么，`editorial_position` 决定强调什么和说到哪里，声音证据决定怎样说，创作参考只提供进入、推进、节奏和收束的可能性。外部案例、钩子、AI 草稿、来源不明文本和题材相似作品不证明作者身份、经历、立场或声音。

“根据字幕、采访稿或原文写”默认表示直接引语、数字、归因和事实边界可追溯，不表示只能逐句换词。只要没有改变事实，成稿可以重排问答、合并重复铺垫、概括当前片段中可观察的表现，并把证据支持的含义说得更清楚；用户明确要求逐字翻译、严格摘要或只用原句时才采用更窄动作。

## 三、声音证据与创作参考分开读取

作者声音按以下顺序取证：

```text
当前明确指令 → 当前有效声音样稿 → 当前口播声音真源 → 同成品语境、同职责且 voice_eligible 的口播 → 通用自然表达
```

高优先级输入改变本次声音时服从当前输入，不反向修改长期声音真源。没有可靠声音证据时保持普通、直接、具体，不伪造第一人称经历，也不声称成稿已经贴近某位作者。用户明确要求“像我”“延续我的声音”但上述证据都不存在时，返回缺少的声音样稿并停止；普通口播写作不因此停止。

声音检索只比较成品语境、表达职责和已经确认的声音资格，不用当前主题词寻找“像作者”的作品。题材检索属于内容查重或创意参考，不能替代声音取证。

创作参考按当前写作任务和成品语境选择。打开多份方向不同且真正相关的完整口播原文，以及多份钩子来源的开头和紧接内容；索引只用于定位，不选择唯一模仿对象，不固定数量，不登记逐句采用。没有合适参考时沿当前材料继续，不能用无关案例凑数。

## 四、只把可写材料交给成稿

用户没有限制只用给定材料时，可以围绕已经确认的主张寻找真实场景、动作、结果、比较、反应和自然说法。材料发现只增加表达可能性；发现会改变主题、结论或事实边界的新信息时返回上层，不在写作中暗中吸收。

成稿上下文只保留：

- 当前口播可能真正使用的对象、动作、数字、结果、比较、原话和少量必要解释；
- 作者为什么要讲、知道什么、怎样评价，以及听众听完应当发生什么变化；
- 必须保留的边界、引语、称呼和来源；
- 实际有效的声音证据、完整案例和钩子全文。

官方套话、通用免责声明、边缘限制、无关功能、为了显得完整而加入的背景和只供备查的信息继续留在来源里，不连同摘要交给写作者。

## 五、让事实和判断承担推进

动笔前先回答四个问题，但不把答案直接变成小标题：

1. 作者为什么现在要讲这件事？
2. 听众最先需要看见哪个具体对象、动作、结果、问题或反常事实？
3. 哪些材料真正使核心判断成立？
4. 说到哪里已经完成，不再需要总结？

开头尽快接触具体内容。可以从结果、场景、动作、问题、比较、判断或原话进入；第一句本身要承担信息，后文能够自然承接。除非内容确实需要导航，不宣布“接下来分几点讲”，也不为了完整感先搭背景、再写定义、再列框架。

必要背景必须短而完整，不能因为追求钩子直接丢掉人物、场景和问题。能够写成“谁在什么场景连续追问了什么”的内容合并成一句；只重复“又问了一遍”“这个问题被追问多次”的独立句删除。使用原声片段开场时，片段只负责建立悬念，紧接的旁白仍要用最短必要信息告诉听众刚才是谁、在问什么以及答案尚缺哪一块，但不复述整段原声。

正文的顺序由听众理解当前问题的需要决定。数字、人物、产品、动作和结果承担主要信息，判断紧贴证据出现。需要并列时可以列举，需要区分时可以对照，需要总结时可以概括；这些结构必须解决真实理解任务，不能只是让段落看起来整齐。

口播允许自然停顿、短句、不规则句长、适量重复、明确好恶和口语毛边。句子首先要能被说出来和听明白，不能为了书面完整塞入连续定语、抽象名词和编辑说明。

## 六、先核查事实，再做根因回读

第一遍只核查正文实际写出的重要事实。对象、名称、数字、日期、价格、链接、引语、因果和会改变听众理解或行动的说法必须能够回到内容真源或本次保留的来源。错误直接修正、收窄或删除；核心前提不成立时重写受影响内容，不靠结尾免责声明维持原稿。

第二遍按以下顺序检查，发现上层问题时先修上层，不从换词开始：

### 1. 内容贡献

- 每段是否新增事实、解释、判断、体验、证据、边界或必要推进？
- 是否有两段在重复同一结论，只是换了更漂亮的说法？
- 具体对象、动作、数字和结果是否承担主要信息，还是被大量评论性总结包围？
- 口播是否兑现了开头承诺，重要边界是否出现在真正影响理解的位置？

没有边际贡献的段落删除或并入承载真实信息的位置。不要为保留节奏而给空段落另换一句套话。

### 2. 结构关系

- 段落顺序是否来自听众理解需要，还是为了凑成“第一、第二、第三、最后”？
- 小标题、列表、对照和总结是否对应真实并列、步骤或边界？
- 是否每个事实后都补一句“这说明了什么”，导致证据不能自己推进？
- 开头是否先宣布表达计划，结尾是否在内容已经说完后再次升华全文？

对称结构本身没有问题；只有它压平材料之间真实轻重、制造重复解释或迫使结尾收口时才拆掉。

### 3. 作者与听众

- 作者为什么在意、怎样判断、知道什么，是否都有当前证据？
- 第一人称是否来自真实经历，而不是用“我认为”给通用结论加身份？
- 评价是否有比较对象和事实支撑，还是“重要、真正、核心、值得关注”一类悬空判断？
- 听众第一次接触当前对象时能否听懂称呼、关系和数字，背景是否刚好够用？
- 全文是否像同一个人在当前场景里说话，而不是中途变成报告、教程或广告？

### 4. 句子和听感

- 连续朗读时停顿是否自然，数字与专名是否容易听清？
- 是否反复使用相同的提示框架，例如不断宣布“重点”“真正的问题”“说白了”或“不要忘记”？
- 对照句两边是否都真实存在且必须区分，还是只用“不是……而是……”制造力度？
- 是否存在翻译腔、官方搭配、抽象名词堆叠、装饰性排比或格言式收尾？

不建立固定禁词表。同一句式在承担真实比较、转折或停顿时可以保留；只在它替代事实、制造虚假关系或重复已有判断时修改。已经准确、自然、有作者辨识度时停止，不继续磨成无菌文本。

## 七、交付

只审查时先给总体判断，再说明应保留什么、根因在哪里、哪些原句最能代表问题，以及建议从哪一层修改。区分“可用但有明显模型组织痕迹”“需要结构重写”和“事实或立场尚未成立”，不把所有问题统称为 AI 味。

新写或改写时先交付可以直接朗读的纯正文。正文较短时放在一个代码块中，过长时写入当前项目的 `.md` 文件并提供可打开路径；制作备注、画面动作和来源说明不混入正文。除非用户只要正文，再简要说明本次使用的内容真源、声音证据和创作参考实际路径，以及哪些地方因证据不足保持普通表达。不要展示隐藏推理、逐句模仿账本或机械评分。

用户确认后，这份活动口播成为配音文本、字幕文本和画面文字的唯一语义真源。后续制作只能从它派生；确认不会自动把全文写入口播私人库，只有用户明确要求保存时才进入库维护路径。
