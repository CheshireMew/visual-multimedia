# 视觉与动效制作配方

用于在用户没有逐项描述风格时，根据内容关系、载体、现有素材和项目历史选择一套可以直接执行的视觉制作方法。制作配方不是只换颜色和字体的皮肤，而是把适用条件、视觉语法、构图、素材处理、动效结构和验收标准作为一个完整能力保存。

## 一、选择与继承

按以下顺序确定配方：

1. 当前项目已经确认的风格档案继续作为唯一风格来源。
2. 用户提供品牌规范或参考样本时，只提取用户要求的视觉、运动或包装层，并形成项目风格档案。
3. 没有既有来源时，根据内容与载体选择本文件中的内置配方。
4. 没有配方适用时，根据内容关系形成中性方向，不为了使用配方扭曲内容。

Agent 默认直接选择一个方向并用一句话说明理由。只有两个方向会造成明显不同的受众理解、品牌气质、素材要求或制作成本，而且现有上下文无法判断时，才询问用户。用户否定方向时保留内容真源，回到风格样稿，不重新发明媒体文案。

首次确认后，在项目制作真源中集中保存一份 `style-profile.json`。共享视觉核心回答“这个系列看起来是谁”，各实现层回答“在这次载体中怎样成立”：

```json
{
  "profile_id": "",
  "source": "built-in | brand | reference | custom",
  "applicability": {
    "shared_visual_core": [],
    "static_composition": [],
    "time_motion": [],
    "interaction": []
  },
  "shared_visual_core": {
    "typography": {},
    "color": {},
    "material": {},
    "shape_and_line": {},
    "image_treatment": {},
    "hierarchy_and_rhythm": {}
  },
  "realizations": {
    "static_composition": null,
    "time_motion": null,
    "interaction": null
  }
}
```

`applicability` 使用当前项目能够直接消费的成品类型，例如 `static-card`、`cover`、`carousel`、`web-animation`、`gif`、`web-derived-video`、`manual-html` 或 `hybrid-html`。字段只保存当前项目实际使用的规则，不复制参考样本的案例内容；某一实现层不成立时保存 `null`，不写假定默认值。

同一项目或系列的新成品先继承 `shared_visual_core`，再按内容关系和载体决定实现层：

- 静态卡片、封面和轮播页读取 `static_composition`，重新确定页面职责、容量、画布比例、裁切和缩略图阅读；不同输出比例仍分别构图。
- 网页动画、GIF 和从同一网页时间线直接捕获的视频读取 `time_motion`，重新确定语义片段、运动载体、开始—变化—结果、循环、结果保持和降低运动方案。静态卡式短动画同时读取已经成立的静态构图，把它作为关键帧合同。
- 手动或混合播放的 HTML 在前两层之后按需读取 `interaction`；控件、命中区域和操作反馈不成为画布内语义运动的第二条时间线。
- 实拍、访谈、录屏和剪辑型视频只把共享核心用于标题、字幕、卡片、图表和网页动画包装；人物构图、镜头、剪辑、声音与素材处理由视频制作路径决定。嵌入其中的网页动画仍按自己的时间运动层制作。

目标载体不在某层 `applicability` 中，或内容关系已经改变时，只继承共享核心并为本次成品建立新的实现层；不能把静态页面坐标当成通用动画构图，也不能把动画时间线压成静态卡片。调整时修改这份档案及网页中的对应变量、结构或时间线，再重新预览。档案描述和网页实现必须一致，不能各自形成一套风格真源。

`style-profile.json` 不保存声音身份、音乐、环境声、音效选择、ducking 或响度规则。项目确实需要复用声音语言时，另按 `sound-production-profiles.md` 建立 `sound-profile.json`；视觉与声音可以分别确认、修改和晋升，不从其中一方推导另一方。

共享视觉核心规定可用的字体角色、色彩职责、材质、图形、图片处理和层级节奏；各实现层只规定本载体可用的构图、运动或交互语言，不替具体成品决定同一种结构。每个页面仍从当前内容关系构图，每个语义片段仍按它正在表达的关系选择持续循环、单向演化、结果保持、累积反馈、并列比较或共享对象转场；风格一致不等于布局、镜头和动作相同。

## 二、内置配方：编辑纸拼贴组装

`profile_id`: `editorial-paper-collage-assembly`

本配方提供共享视觉核心和时间运动实现，适用于网页动画、GIF 与从同一网页时间线派生的视频；需要静态封面时只继承共享核心并另建静态构图实现。

### 用户得到什么

把短口播、抽象观点、反差或评论性内容转成一幅能够逐件组装的编辑纸拼贴画面。最终交付仍以可编辑 HTML 为制作真源；需要 GIF 或视频时从同一网页时间线派生，不默认调用视频生成模型。

### 什么时候选择

- 内容主要通过一个可见隐喻或对象关系表达，而不是依赖精确数据、真实人物表演或界面操作。
- 成品是短 B-roll、无实拍动画、观点配画、章节过场或具有评论感的动态图解。
- 用户明确提出纸拼贴、半调剪贴、编辑杂志感、stop-motion 纸片组装，或同一项目已经确认该配方。

以下情况不选择：精确数据图表、真实产品操作、需要连续人物表演的故事、复杂镜头穿越、需要大量可读文字的卡片，或需要严格模拟真实空间和遮挡的动画。它们继续使用数据图表、技术图解、实拍后期或当前内容更合适的方法。

### 构成性视觉语法

- 使用强烈、平坦、均匀的纸面色场作为底面，保留细微的非涂布纸纤维，避免写实环境和玻璃质感背景。
- 主体以黑白照片式半调剪贴、剪影或高反差图形为骨架；关键卡片、工具、连接件和结果对象可以使用彩色卡纸建立信息层级。
- 每个纸片组具有清晰裁切边、暖奶油色细描边、低透明度柔和阴影和可见但不过量的纸张颗粒。
- 一个短镜头只保留少量能够独立移动和编辑的大组块。约五秒的单一视觉命题通常使用 3–6 组；时长和信息确实增加时可以调整，但每组都必须承担可说明的信息。
- 构图围绕一个主要关系组织，主体集中在安全区域，外围保留足够纯色负空间，使空场、逐件进入和完成状态都能读清。
- 画面中的准确标题、数字、来源和字幕由 HTML 文本图层承担。生成或照片素材中的假字、标识、界面和水印不承担信息职责。

颜色由语义和系列风格共同决定，不固定蓝底。可以优先把焦橙或红用于劳动、时间和紧迫；芥末黄用于工具、警示和漏失；墨绿用于认知和重置；深紫用于规范和长期记忆；青绿用于判断、协作和执行。它们是当前配方的选择线索，不是跨项目的固定含义。

### HTML 图层与素材

- 背景色场、每个主要纸片组、连接件、动作结果和必要文字分别使用稳定的 `data-editable-id`。
- 每个可移动组块内部可以包含照片、半调滤镜、描边和阴影，但对外保持一个清楚的移动与层级单位。
- 半调效果优先使用 CSS、SVG filter、遮罩或本地预处理图片实现。用户提供、许可素材或本地资源优先；只有用户明确授权时才搜索外部素材或调用图片模型。
- 图片模型只生成可替换的背景、剪贴主体或纹理，不生成必须准确读取的文字，也不接管动画时间线。
- 背景色、纸张纹理、描边、阴影、半调密度和点色集中为视觉变量；具体对象、位置和组装顺序由当前视觉命题决定。

### 构图与动作顺序

先从 `content-to-media.md` 得到视觉命题，再把必要对象分成可编辑大组。当前片段的含义确实是“对象逐步出现并组成一个关系”时，默认动作结构是：

```text
空白纸面
→ 基础结构或承载物进入
→ 主体与关键卡片滑入并卡位
→ 连接件或动作对象补全关系
→ 结果对象完成
→ 保持完整构图供观众阅读
```

动作使用短促的滑入、轻微旋转、压下、卡位和有限回弹，体现实体纸片的 stop-motion 节奏。主时间线控制所有状态；相同时间必须得到相同画面。不要用整体淡入、持续漂移、慢速缩放、镜头运动、形体融化或自动新增对象代替组装过程。用户要求循环时，从完成状态设计可解释的拆解或重置，不直接让末帧跳回空场。

当前片段表达持续摆动、逐渐同步、累积反馈、数值对比或结论保持时，保留本配方的纸张材质、图层组织和短促动作质感，但改用与该含义一致的运动结构，不强行套用“空场到组装完成”的顺序。

### 样稿和通过标准

视觉命题尚未确认时，先交付核心意思、可见关系、必要对象、底色方向和组装顺序。方向确认后，在同一网页真源中制作完成构图和一个代表性组装动作；用户明确授权一次完成时可以连续制作。

完成时检查：

- 不听口播时，最终构图能否表达主要关系。
- 每个组块是否承担信息，是否存在只增加噪音的碎片。
- 空场、组装中段和完成状态是否都能清楚读取，动作是否真的逐件发生。
- 半调、纸张、裁切边、描边和阴影是否形成一致材质，而不是普通卡片加噪点。
- 关键文字是否仍由 HTML 正确渲染，没有假字、标识、水印或界面残片。
- 完成状态是否稳定保持，实际末帧是否与网页预期结束状态一致。
- 项目 `style-profile.json`、网页视觉变量、图层和时间线是否表达同一套配方。

实际导出时继续按 `review-and-export.md` 生成关键状态检查图并检查最终媒体。某个条目失败时修改对应视觉命题、组块、素材或时间线，只重新预览和导出受影响条目；共享配方发生变化时先说明对已通过条目的影响。

## 三、内置配方：编辑证据卡

`profile_id`: `editorial-evidence-card`

本配方提供共享视觉核心与静态构图实现；当“主张—证据—解释”的关系需要通过对象重新排列或逐步成形来表达时，可以在同一核心上增加时间运动实现，不能只让整页淡入。

### 用户得到什么

把观点、项目介绍、评论、案例或生活方式内容制作成带有编辑出版感的社交卡。它强调“主张—证据—解释”的阅读关系，适合静态卡、封面和轮播页；不是把普通卡片换成米色背景。

### 什么时候选择

- 内容有明确观点，同时有照片、截图、原句、来源或具体事实可以支撑。
- 需要人文、评论、文化、旅行、生活方式或独立出版物气质。
- 信息需要分层阅读，但不依赖严密数据网格或产品仪表盘语言。

纯产品参数表、密集数据比较、需要强技术秩序的流程不选择；图片质量不足时使用文字证据、截图或分栏版式，不伪造生活方式照片。

### 视觉语法

- 使用暖白或低饱和纸面、细线、页码、栏目标签和克制点色建立编辑层级；不使用多层圆角卡片和大面积悬浮阴影。
- 标题可以使用宋体、衬线体或高质量中文正文体，字重以常规到中等为主；正文与元信息使用清楚的无衬线或等宽体。
- 一页只保留一个主要视觉重心。照片是证据时让照片承担足够面积；没有合格照片时用文字、线条、数据或截图形成结构。
- 来源、日期、署名和图注作为真实阅读锚点，不为了装饰编造期号、栏目或引语。
- 图片与文字叠放严格读取 `visual-asset-placement.md`；先选安全区和裁切，局部色调只作为最后补救。

### 常用结构

优先使用主张封面、图文分栏、图片证据、截图证明、边栏解释、引用、清单和总结。轮播中让图片页与解释页按论证需要交替，不连续复制同一张“杂志封面”。每种结构按 `social-card-production.md` 写明容量和页面职责。

### 通过标准

- 去掉纹理后，标题、证据、解释和来源仍形成清楚层级。
- 照片不是装饰库存图；截图、图注和来源能够说明它为什么在这一页。
- 缩略图中标题与主体可识别，放大后正文和来源可读。
- 纸张、线条、字体和图片色调来自同一风格档案，没有临时增加的玻璃、霓虹或 SaaS 面板。
- 项目清单中的量化检查只约束当前版式声明的字号、间距、安全区和内容跨度。

## 四、内置配方：瑞士信息网格

`profile_id`: `swiss-information-grid`

本配方提供共享视觉核心与静态构图实现。用于多场景演示或数据动画时保留网格、字号与点色职责，但按实际变化另建时间运动实现。

### 用户得到什么

把产品、工具、技术说明、比较、数据和流程制作成高秩序、强对齐的社交卡。画面依靠网格、字号尺度、留白和一个点色建立识别，而不是依靠装饰图形。

### 什么时候选择

- 内容包含清楚的字段、指标、步骤、对比或界面证据。
- 成品需要理性、现代、技术或公共信息设计气质。
- 多页内容需要共享列、编号、尺度和阅读顺序。

内容主要依赖情绪照片、散文式叙述或手作质感时不选择。字段之间没有共同维度时，不为了网格整齐强行做成比较。

### 视觉语法

- 使用明确的列网格、基线、细线和大尺度字号差。容器默认平面化，不使用嵌套圆角面板或统一阴影。
- 全项目只使用一个主要点色；其余依靠黑、白、灰或低饱和底面形成层级。
- 大标题和关键数字“越大越轻”，避免大号粗黑字堵住画面；正文、标签和数据保持足够字重与对比度。
- 用于现场演示时按投影后的观看距离确定字号，不直接沿用社交卡的小字。同一场景中较小文字的字重不低于较大文字；标题过长时先改写，再降字号。
- 图片以产品图、图表或界面截图为主。截图完整性优先，默认正投影和 `contain`，不制造倾斜设备场景。
- 对齐关系必须能说清：同一基线、顶部、底部、中心或共享列。绝对定位只处理独立装饰和已经确认的叠放。

### 常用结构

优先使用点色封面、巨型数字、两列比较、矩阵、时间线、流程、清单、截图舞台和总结。每页先确定共享字段，再决定列数；字段过多时删减信息或拆页，不缩成仪表盘缩略图。

### 通过标准

- 隐去点色后，信息仍可仅靠网格和字号层级读取。
- 大标题没有使用不必要的粗重字重；正文在整图缩放后仍清楚。
- 全页只有一个主点色，线条、列和间距遵循同一尺度。
- 截图没有被 `cover` 裁掉关键界面，也没有无请求的透视、3D 或设备装饰。
- 清单中的 `minimum_font_px`、`minimum_gaps` 和其它规则与实际风格档案一致，并由真实浏览器结果验证。
- 多场景演示在 `quality` 中声明标题到第一块内容的距离、导航安全区和允许的底部空白；真实浏览器逐场景测量，不能只看默认场景。

## 五、内置配方：真人创作者高冲击封面

`profile_id`: `creator-led-impact-cover`

本配方提供共享视觉核心与静态构图实现。需要短动态图时先把确认封面作为静态构图合同，再为人物、证据或结果的真实变化增加时间运动实现。

### 用户得到什么

把已经确认的文章、观点、产品、工具或经验内容制作成一张以创作者本人为注意力入口、在缩略图中仍能立即读懂的封面。人物表情和动作负责吸引视线，产品、截图、对比物或叙事道具负责说明“这件事为什么值得点开”，准确标题、标签和证据继续由可编辑网页排版。

这项配方交付的是可继续修改的网页封面。需要图片模型时，它只生成已经确定职责的人物、道具、场景或背景素材；生成图不是标题、准确界面和最终版式的第二个真源。

### 什么时候选择

- 用户明确需要个人 IP、知识分享、产品介绍、经验复盘或强缩略图识别的社交封面，并且真人形象会增加注意力、信任或情绪表达。
- 内容可以压缩为一个直接主张、结果、反差、问题或行动，人物能够与一项证据或道具形成清楚关系。
- 用户已经提供可使用的人物素材，项目已经显式采用相应 `creator-media`，或者当前任务明确允许根据身份参考生成新的视觉素材。

纯数据报告、需要克制阅读的正式说明、没有人物授权的内容、人物与主张没有实际关系的封面不选择。产品截图或原句本身是主要证据时，可以继续采用人物引导构图，但证据必须作为独立可核对图层保留，不能融进生成场景后失去准确性。

### 信息与素材职责

- 标题承担封面的核心承诺，先从已确认媒体文案提炼，再根据当前比例决定分行、强调块和可选副标题；不固定字数。标题在目标缩略图中必须先于次要装饰被读到。
- 人物承担情绪、身份和视线引导。使用当前用户提供或当前项目显式采用的创作者素材；署名头像只负责署名，不能代替出镜素材，也不能因为库中只有一位创作者就自动采用。
- 产品图、界面截图、数据、前后对比物和原句承担证据。准确界面使用独立素材槽位并保留可读区域；只有不要求逐项核对的概念性物件才可以随人物一起生成。
- 点缀元素只加强主题、方向或动势。删去后不影响封面主张的碎片、图标和光效不进入画面。

### 构图语法

先用一句可见关系说明这张封面：谁以什么动作对待哪个对象，观众首先看到什么，随后理解什么。人物姿势具体到身体位置、视线、双手和道具关系；画面明确前景、中景和背景，以及人物、标题和证据之间允许发生的遮挡。遮挡可以建立层次，但不能盖住眼睛、嘴部、标题关键字或证据中的必要信息。

常见关系按当前内容选择，不形成固定风格菜单：

- 内容主要依赖判断、反应或人物态度时，让脸部和眼神成为主视觉，标题在上方、侧方或人物周围形成清楚框架。
- 产品、界面或作品成果是核心证据时，让证据占据主要面积，人物缩小到一侧，通过视线或手势把注意力引向证据。
- 内容是前后、好坏、新旧或两种方案的比较时，让人物同时控制两个可并读对象，用面积、距离、明暗或方向说明差异，不用两张无关卡片假装对比。
- 抽象概念需要具象化时，让人物与一个可识别道具或场景发生动作，动作本身说明因果、冲突、选择或结果，不用一圈主题图标替代叙事。
- 标题、产品或场景应当成为绝对主角时，人物可以侧置、局部出镜或背向镜头，为主要信息留下连续空间；这种处理必须由内容关系决定，不作为装饰性变化。

视觉表面可以使用高对比深色、干净纯色、纸张拼贴或克制留白，但一张封面只选择一套主表面。颜色先建立大面积明暗关系，再使用一个高识别点色强调关键词或关键证据；标题块、人物、证据和背景不能各自使用一套互相竞争的效果。

### 生成与网页装配

生成视觉素材前先确定目标输出变体、人物槽位、证据槽位、标题安全区和最终遮挡关系。身份参考只负责保持创作者外貌，证据参考只负责保留产品、界面或对象事实，风格参考只影响允许提取的视觉层；任务说明使用稳定 source id 和这三项职责，消费者不依赖上传顺序理解素材。

生成要求写清人物朝向、表情、手势、与道具的距离、需要保留的标题空间以及背景明暗。生成结果保持标题区无文字、无水印和无伪造界面；准确标题、数字、标签、产品截图和来源由网页图层完成。生成文件进入项目素材账本并由场景素材槽位显式采用后，才算进入封面。

不同输出比例共享同一主张、人物身份、证据和风格档案，但分别重新安排人物、标题和证据。横版、竖版和方形不能从同一张生成合成图机械裁切；需要复用生成素材时，人物和主要道具必须位于各目标槽位都能成立的安全区域，否则为受影响比例重新生成或改用分层素材。

### 样稿和通过标准

构图尚未确认时，先用真实标题、人物素材和主要证据制作一张目标比例构图样稿。需要外部生成时，先生成一个能暴露身份、手势、遮挡和标题空间风险的代表素材；它只确认人物与生成层，不自动批准标题、全部比例或最终封面。

完成时检查：

- 缩到目标平台实际缩略图或约 360 像素宽后，标题、人物和核心证据是否仍能按预期顺序识别。
- 人物身份、视线、手势和表情是否自然，人物是否真的把注意力引向当前主张或证据。
- 标题、人物、道具和证据之间是否形成一个可复述的关系，而不是高饱和元素的堆叠。
- 准确中文、数字、标签和界面是否仍来自可编辑网页，生成图中的偶然文字是否已经退出信息职责。
- 每个用户要求的输出比例是否独立通过构图、裁切、安全区和缩略图检查。
- `style-profile.json`、网页视觉变量、素材槽位和最终画面是否表达同一套配方。
