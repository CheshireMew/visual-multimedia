# 视觉与动效制作配方

用于在用户没有逐项描述风格时，根据内容关系、载体、现有素材和项目历史选择一套可以直接执行的视觉制作方法。制作配方不是只换颜色和字体的皮肤，而是把适用条件、视觉语法、构图、素材处理、动效结构和验收标准作为一个完整能力保存。

## 一、选择与继承

按以下顺序确定配方：

1. 当前项目已经确认的风格档案继续作为唯一风格来源。
2. 用户提供品牌规范或参考样本时，只提取用户要求的视觉、运动或包装层，并形成项目风格档案。
3. 没有既有来源时，根据内容与载体选择本文件中的内置配方。
4. 没有配方适用时，根据内容关系形成中性方向，不为了使用配方扭曲内容。

Agent 默认直接选择一个方向并用一句话说明理由。只有两个方向会造成明显不同的受众理解、品牌气质、素材要求或制作成本，而且现有上下文无法判断时，才询问用户。用户否定方向时保留内容真源，回到风格样稿，不重新发明媒体文案。

首次确认后，在项目制作真源中集中保存一份 `style-profile.json`，至少记录：

```json
{
  "profile_id": "",
  "source": "built-in | brand | reference | custom",
  "visual_rules": {},
  "image_treatment": {},
  "motion_rules": {},
  "typography_rules": {},
  "overrides": {}
}
```

字段保存当前项目实际使用的规则，不复制参考样本的案例内容。同一系列后续任务先读取并继承；调整时修改这份档案及网页中的对应变量，再重新预览。档案描述和网页实现必须一致，不能各自形成一套风格真源。

配方只规定可用的材质、构图语言和运动词汇，不替整条媒体时间线决定同一种动作。每个语义片段仍按它正在表达的关系选择持续循环、单向演化、结果保持、累积反馈、并列比较或共享对象转场；风格一致不等于所有片段用相同结构。

## 二、内置配方：编辑纸拼贴组装

`profile_id`: `editorial-paper-collage-assembly`

### 用户得到什么

把短口播、抽象观点、反差或评论性内容转成一幅能够逐件组装的编辑纸拼贴画面。最终交付仍以可编辑 HTML 为制作真源；需要 GIF 或视频时从同一网页时间线派生，不默认调用视频生成模型。

### 什么时候选择

- 内容主要通过一个可见隐喻或对象关系表达，而不是依赖精确数据、真实人物表演或界面操作。
- 成品是短 B-roll、无实拍动画、观点配画、章节过场或具有评论感的动态图解。
- 用户明确提出纸拼贴、半调剪贴、编辑杂志感、stop-motion 纸片组装，或同一项目已经确认该配方。

以下情况不选择：精确数据图表、真实产品操作、需要连续人物表演的故事、复杂镜头穿越、需要大量可读文字的卡片，或需要严格模拟真实空间和遮挡的动画。它们继续使用数据图表、技术图解、实拍后期或当前内容更合适的方法。

### 构成性视觉语法

- 使用强烈、平坦、均匀的纸面色场作为底面，保留细微的非涂布纸纤维，避免写实环境和玻璃质感背景。
- 主体以黑白照片式半调剪贴、剪影或高反差图形为骨架；关键卡片、工具、连接件和结果对象可以使用彩色卡纸建立信息层级。
- 每个纸片组具有清晰裁切边、暖奶油色细描边、低透明度柔和阴影和可见但不过量的纸张颗粒。
- 一个短镜头只保留少量能够独立移动和编辑的大组块。约五秒的单一视觉命题通常使用 3–6 组；时长和信息确实增加时可以调整，但每组都必须承担可说明的信息。
- 构图围绕一个主要关系组织，主体集中在安全区域，外围保留足够纯色负空间，使空场、逐件进入和完成状态都能读清。
- 画面中的准确标题、数字、来源和字幕由 HTML 文本图层承担。生成或照片素材中的假字、标识、界面和水印不承担信息职责。

颜色由语义和系列风格共同决定，不固定蓝底。可以优先把焦橙或红用于劳动、时间和紧迫；芥末黄用于工具、警示和漏失；墨绿用于认知和重置；深紫用于规范和长期记忆；青绿用于判断、协作和执行。它们是当前配方的选择线索，不是跨项目的固定含义。

### HTML 图层与素材

- 背景色场、每个主要纸片组、连接件、动作结果和必要文字分别使用稳定的 `data-editable-id`。
- 每个可移动组块内部可以包含照片、半调滤镜、描边和阴影，但对外保持一个清楚的移动与层级单位。
- 半调效果优先使用 CSS、SVG filter、遮罩或本地预处理图片实现。用户提供、许可素材或本地资源优先；只有用户明确授权时才搜索外部素材或调用图片模型。
- 图片模型只生成可替换的背景、剪贴主体或纹理，不生成必须准确读取的文字，也不接管动画时间线。
- 背景色、纸张纹理、描边、阴影、半调密度和点色集中为视觉变量；具体对象、位置和组装顺序由当前视觉命题决定。

### 构图与动作顺序

先从 `content-to-media.md` 得到视觉命题，再把必要对象分成可编辑大组。当前片段的含义确实是“对象逐步出现并组成一个关系”时，默认动作结构是：

```text
空白纸面
→ 基础结构或承载物进入
→ 主体与关键卡片滑入并卡位
→ 连接件或动作对象补全关系
→ 结果对象完成
→ 保持完整构图供观众阅读
```

动作使用短促的滑入、轻微旋转、压下、卡位和有限回弹，体现实体纸片的 stop-motion 节奏。主时间线控制所有状态；相同时间必须得到相同画面。不要用整体淡入、持续漂移、慢速缩放、镜头运动、形体融化或自动新增对象代替组装过程。用户要求循环时，从完成状态设计可解释的拆解或重置，不直接让末帧跳回空场。

当前片段表达持续摆动、逐渐同步、累积反馈、数值对比或结论保持时，保留本配方的纸张材质、图层组织和短促动作质感，但改用与该含义一致的运动结构，不强行套用“空场到组装完成”的顺序。

### 样稿和通过标准

视觉命题尚未确认时，先交付核心意思、可见关系、必要对象、底色方向和组装顺序。方向确认后，在同一网页真源中制作完成构图和一个代表性组装动作；用户明确授权一次完成时可以连续制作。

完成时检查：

- 不听口播时，最终构图能否表达主要关系。
- 每个组块是否承担信息，是否存在只增加噪音的碎片。
- 空场、组装中段和完成状态是否都能清楚读取，动作是否真的逐件发生。
- 半调、纸张、裁切边、描边和阴影是否形成一致材质，而不是普通卡片加噪点。
- 关键文字是否仍由 HTML 正确渲染，没有假字、标识、水印或界面残片。
- 完成状态是否稳定保持，实际末帧是否与网页预期结束状态一致。
- 项目 `style-profile.json`、网页视觉变量、图层和时间线是否表达同一套配方。

实际导出时继续按 `review-and-export.md` 生成关键状态检查图并检查最终媒体。某个条目失败时修改对应视觉命题、组块、素材或时间线，只重新预览和导出受影响条目；共享配方发生变化时先说明对已通过条目的影响。

## 三、内置配方：编辑证据卡

`profile_id`: `editorial-evidence-card`

### 用户得到什么

把观点、项目介绍、评论、案例或生活方式内容制作成带有编辑出版感的社交卡。它强调“主张—证据—解释”的阅读关系，适合静态卡、封面和轮播页；不是把普通卡片换成米色背景。

### 什么时候选择

- 内容有明确观点，同时有照片、截图、原句、来源或具体事实可以支撑。
- 需要人文、评论、文化、旅行、生活方式或独立出版物气质。
- 信息需要分层阅读，但不依赖严密数据网格或产品仪表盘语言。

纯产品参数表、密集数据比较、需要强技术秩序的流程不选择；图片质量不足时使用文字证据、截图或分栏版式，不伪造生活方式照片。

### 视觉语法

- 使用暖白或低饱和纸面、细线、页码、栏目标签和克制点色建立编辑层级；不使用多层圆角卡片和大面积悬浮阴影。
- 标题可以使用宋体、衬线体或高质量中文正文体，字重以常规到中等为主；正文与元信息使用清楚的无衬线或等宽体。
- 一页只保留一个主要视觉重心。照片是证据时让照片承担足够面积；没有合格照片时用文字、线条、数据或截图形成结构。
- 来源、日期、署名和图注作为真实阅读锚点，不为了装饰编造期号、栏目或引语。
- 图片与文字叠放严格读取 `visual-asset-placement.md`；先选安全区和裁切，局部色调只作为最后补救。

### 常用结构

优先使用主张封面、图文分栏、图片证据、截图证明、边栏解释、引用、清单和总结。轮播中让图片页与解释页按论证需要交替，不连续复制同一张“杂志封面”。每种结构按 `social-card-production.md` 写明容量和页面职责。

### 通过标准

- 去掉纹理后，标题、证据、解释和来源仍形成清楚层级。
- 照片不是装饰库存图；截图、图注和来源能够说明它为什么在这一页。
- 缩略图中标题与主体可识别，放大后正文和来源可读。
- 纸张、线条、字体和图片色调来自同一风格档案，没有临时增加的玻璃、霓虹或 SaaS 面板。
- 项目清单中的量化检查只约束当前版式声明的字号、间距、安全区和内容跨度。

## 四、内置配方：瑞士信息网格

`profile_id`: `swiss-information-grid`

### 用户得到什么

把产品、工具、技术说明、比较、数据和流程制作成高秩序、强对齐的社交卡。画面依靠网格、字号尺度、留白和一个点色建立识别，而不是依靠装饰图形。

### 什么时候选择

- 内容包含清楚的字段、指标、步骤、对比或界面证据。
- 成品需要理性、现代、技术或公共信息设计气质。
- 多页内容需要共享列、编号、尺度和阅读顺序。

内容主要依赖情绪照片、散文式叙述或手作质感时不选择。字段之间没有共同维度时，不为了网格整齐强行做成比较。

### 视觉语法

- 使用明确的列网格、基线、细线和大尺度字号差。容器默认平面化，不使用嵌套圆角面板或统一阴影。
- 全项目只使用一个主要点色；其余依靠黑、白、灰或低饱和底面形成层级。
- 大标题和关键数字“越大越轻”，避免大号粗黑字堵住画面；正文、标签和数据保持足够字重与对比度。
- 用于现场演示时按投影后的观看距离确定字号，不直接沿用社交卡的小字。同一场景中较小文字的字重不低于较大文字；标题过长时先改写，再降字号。
- 图片以产品图、图表或界面截图为主。截图完整性优先，默认正投影和 `contain`，不制造倾斜设备场景。
- 对齐关系必须能说清：同一基线、顶部、底部、中心或共享列。绝对定位只处理独立装饰和已经确认的叠放。

### 常用结构

优先使用点色封面、巨型数字、两列比较、矩阵、时间线、流程、清单、截图舞台和总结。每页先确定共享字段，再决定列数；字段过多时删减信息或拆页，不缩成仪表盘缩略图。

### 通过标准

- 隐去点色后，信息仍可仅靠网格和字号层级读取。
- 大标题没有使用不必要的粗重字重；正文在整图缩放后仍清楚。
- 全页只有一个主点色，线条、列和间距遵循同一尺度。
- 截图没有被 `cover` 裁掉关键界面，也没有无请求的透视、3D 或设备装饰。
- 清单中的 `minimum_font_px`、`minimum_gaps` 和其它规则与实际风格档案一致，并由真实浏览器结果验证。
- 多场景演示在 `quality` 中声明标题到第一块内容的距离、导航安全区和允许的底部空白；真实浏览器逐场景测量，不能只看默认场景。
