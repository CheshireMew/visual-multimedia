# 视觉与动效制作配方

本文件只为技术图解、结构化网页、网页动画、GIF、视频内稳定阅读场景和其它受支持媒体提供可迁移视觉层。下文保留的 `static_composition`、`static-card`、`cover` 与 `carousel` 是既有合同、案例和风格档案的兼容词汇，不构成独立静态卡、社交卡、纯文字卡、轮播图或独立封面的制作入口；相关配方只能用于受支持成品内的关键状态、标题场景、技术图解或视觉包装。

用于在用户没有逐项描述风格时，根据内容关系、载体、现有素材和项目历史选择一套可以直接执行的视觉制作方法。制作配方不是只换颜色和字体的皮肤，而是把适用条件、视觉语法、构图、素材处理、动效结构和验收标准作为一个完整能力保存。

## 一、选择与继承

先把当前材料分成内容来源、用户已授权查看的素材和已经采用的视觉来源。仓库中的 README 与文本可以提供事实；旧封面、其它成品、相邻目录图片、案例预览和任何视觉文件只有被用户明确点名或授权查看后，才可以成为素材或证据。文件与任务位于同一仓库、内容相关或曾被其它项目使用，都不构成打开、预览、比较和提取风格的许可。同一项目或系列的风格档案只有在已经为这项媒体工作确认或明确采用时才是视觉来源；用户提供的品牌规范或参考样本，也只在用户要求采用的视觉层生效。

按以下顺序确定配方：

1. 当前媒体项目或系列已经确认并采用的风格档案继续作为唯一风格来源。
2. 用户提供品牌规范、参考样本或明确授权查看指定视觉文件时，只提取用户要求的视觉、运动或包装层，并形成项目风格档案。
3. 没有既有来源时，根据内容与载体选择本文件中的内置配方。
4. 没有配方适用时，根据内容关系形成中性方向，不为了使用配方扭曲内容。

用户明确点名某个外部样本并只说“看看、参考、分析、借鉴、比较”时，样本只用于发现当前作品的质量缺口，不成为视觉来源，也不得修改活动 `style-profile.json`。没有点名具体视觉文件或授权范围时，不自行去仓库和相邻目录寻找样本。先保留已经确认的内容、活动风格、项目身份和未受反馈影响的约束；案例资源只读取目录中已经提炼的文字机制与验收证据，不打开视觉预览。只有明确采用后，才按采用层读取完整预览、网页或风格档案。无论是否采用，都根据当前内容重新决定信息分区、阅读顺序、比例、坐标和装饰，不能用替换文字和截图的方式原样复用参考画面。

内置配方规定使某类内容成立的视觉关系、材质、色彩职责和实现方法；案例中的具体色值、文字、坐标、比例和装饰只是该案例的取值。实际颜色按用户、品牌、参考、已确认项目档案、内置配色卡的顺序选择。前四项都没有时，从 `assets/color-palette-library/catalog.json` 选择一张卡，只继承其中的颜色职责和原始色值，不继承构图、字体、容器或题材模板，也不跨卡拼色。用户说“纯色”只表示不使用纹理、渐变和照片；没有其它视觉来源的极简文字提取使用“中性黑白红”的纯白背景，不再把暖白当作默认中性色。最终颜色与构图保存在本项目的风格档案中；未被当前项目采用的案例、starter 或旧作品不参与选择。

没有已确认视觉方向时，受支持的结构化网页、动画、视频包装或技术图解在作图前确认中说明准备使用的配方或中性方向，并同时提交最终文字、信息顺序、必要元素与来源、内容决定的宽高、字体和配色。确认前不创建网页、实例化模板、调用图像生成或绘制画布。项目按对应流程制作必要样稿。用户否定方向时保留内容真源、项目身份和未被否定的层，修改最早受影响部分，不重新发明媒体文案或自动整体重做。

作图前确认通过后，文字主导的网页视觉用真实标题、正文、分区、身份标记和确认宽高完成画布。成品必须落实已确认字体、正文密度、底色与点色面积、重心、留白和标题分行，并同时在目标尺寸与清单声明的实际展示宽度检查；主要阅读文字以 16px 左右为舒适目标、14px 为下限。用户否定配色、字体或表面质感时，保留已确认文字与内容关系，只修改受影响视觉层。

系列复用、结构化网页或跨成品继承确实需要时，在项目制作真源中保存 `style-profile.json`；共享视觉核心回答“这个系列看起来是谁”，各实现层回答“在这次载体中怎样成立”：

```json
{
  "profile_id": "",
  "source": "built-in | brand | reference | custom",
  "applicability": {
    "shared_visual_core": [],
    "static_composition": [],
    "time_motion": [],
    "interaction": []
  },
  "shared_visual_core": {
    "typography": {},
    "color": {},
    "material": {},
    "shape_and_line": {},
    "image_treatment": {},
    "hierarchy_and_rhythm": {}
  },
  "realizations": {
    "static_composition": null,
    "time_motion": null,
    "interaction": null
  }
}
```

`applicability` 使用当前项目能够直接消费的成品类型，例如 `web-animation`、`gif`、`web-derived-video`、`manual-html` 或 `hybrid-html`。既有档案中的 `static-card`、`cover` 和 `carousel` 只作为兼容词汇读取，不据此创建独立静态成品。字段只保存当前项目实际使用的规则，不复制参考样本的案例内容；某一实现层不成立时保存 `null`，不写假定默认值。

同一项目或系列的新成品先继承 `shared_visual_core`，再按内容关系和载体决定实现层：

- 受支持媒体内的稳定阅读场景、标题场景和技术图解可以读取 `static_composition`，重新确定页面职责、容量、画布比例、裁切和缩略图阅读；不同输出比例仍分别构图。
- 网页动画、GIF 和从同一网页时间线直接捕获的视频读取 `time_motion`，重新确定语义片段、运动载体、开始—变化—结果、循环、结果保持和降低运动方案。需要稳定阅读关键帧的短动画同时读取已经成立的静态构图，把它作为关键帧合同。
- 手动或混合播放的 HTML 在前两层之后按需读取 `interaction`；控件、命中区域和操作反馈不成为画布内语义运动的第二条时间线。
- 实拍、访谈、录屏和剪辑型视频只把共享核心用于标题、字幕、卡片、图表和网页动画包装；人物构图、镜头、剪辑、声音与素材处理由视频制作路径决定。嵌入其中的网页动画仍按自己的时间运动层制作。

目标载体不在某层 `applicability` 中，或内容关系已经改变时，只继承共享核心并为本次成品建立新的实现层；不能把稳定阅读场景的坐标当成通用动画构图，也不能把动画时间线压成独立静态卡片。调整时修改这份档案及网页中的对应变量、结构或时间线，再重新预览。档案描述和网页实现必须一致，不能各自形成一套风格真源。

`style-profile.json` 不保存声音身份、音乐、环境声、音效选择、ducking 或响度规则。项目确实需要复用声音语言时，另行建立 `sound-profile.json`；视觉与声音可以分别确认、修改和晋升，不从其中一方推导另一方。

风格档案也不复制 `editable-media.json` 已经负责的具体画布宽高、当前场景文案、分区顺序、字段值和来源版本。共享视觉核心保存字体角色、色彩职责、材质、图形、图片处理和层级节奏；静态构图实现只说明这些关系在该类载体中怎样重组。画布尺寸与安全区由输出变体负责，当前内容顺序由场景和版式合同负责。用户改变比例、删掉分区或替换内容后先更新这些唯一真源，再让风格实现重新适配，不能留下另一份文字描述继续声称旧画布或旧顺序成立。

共享视觉核心规定可用的字体角色、色彩职责、材质、图形、图片处理和层级节奏；各实现层只规定本载体可用的构图、运动或交互语言，不替具体成品决定同一种结构。每个页面仍从当前内容关系构图，每个语义片段仍按它正在表达的关系选择持续循环、单向演化、结果保持、累积反馈、并列比较或共享对象转场；风格一致不等于布局、镜头和动作相同。
