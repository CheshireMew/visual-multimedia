# 技术图解制作

用于把已经确认的技术概念、接口、工具、协议、系统关系或人机流程制作成真正依靠图形解释的静态技术卡、对比图和稳定全貌动态图。主入口必须同时提供已经确认的媒体文案、视觉配方、网页制作与必要的导出规则；本文件只处理技术图解特有的结构、连线与运动问题，网页合同、身份判断、素材来源和通用导出规则仍由各自正式流程负责。

## 一、先划清内容与通道

先把当前内容拆成四类：观众必须在画面中直接理解的机制；只需作为标题、标签或节点名出现的文字；适合放进配套帖、封面文案或发布文案的传播句；仅供制作者使用的备注。传播句不能因为醒目就自动进入图内，制作备注也不能成为观众可见字段。

再检查范围。通用科普图只使用跨产品成立的节点、动作和结果；项目名、内部模块、专有操作和一次性业务词留在项目案例，不冒充普遍定义。全部可见文案服从当前媒体语言合同；中文成品使用中文标题、节点、栏头、元信息和微文案，只有合同已经允许的标准缩写、协议名、函数名、命令、字段或翻译后会失真的专用名词保留英文。标题说“一图看懂”时，主体必须提供可沿线阅读的机制，不能只把三个文字定义装进三个框。

## 二、选择真正的图解结构

- 并列概念、接口或工作方式采用静态对比图：每栏保持同一解释层级，用微型机制图展示调用者、入口、过程、结果或状态，再用一条共享底座说明它们共同连接的能力。共享底座必须使用与当前主题无关的通用词；栏数、顺序、画布和表面风格由本次内容决定。
- 系统、反馈、人机协同或状态变化采用稳定全貌图：第一帧显示完整节点、文字、分区和连接，时间只让代表当前事件的光点、短轨迹或局部强调沿既有路径移动。节点、标题、布局和框线不在过程中换字、缩放、变亮或重排。
- 普通流程按因果顺序建立路径；同一条边在一个时间窗口只表达一个语义事件。相同起止点再次运动时必须代表不同且能够命名的事件，否则删除重复动画。

参考图只提供被明确采用的风格层。只要求看看、分析或借鉴时，分别记录当前作品在结构分区、信息密度、字体气质、图标家族、线宽层级、连接方式、色彩明度和运动规则上的质量缺口，不把参考图变成视觉来源。案例目录中的 `technical-interface-comparison` 提供横向机制对比证据，`handdrawn-system-collaboration-flow` 提供稳定全貌动态图证据；默认只读取各自 `transferable_mechanisms` 与 `verify`，当前内容、节点、配色、字体、画布、时间和署名全部重新决定。只有明确采用案例视觉语言后，才读取对应视觉文件和指定层，并把采用层落实到真实画布；验收时直接对照参考检查这些层，不能用文字记录、风格档案或技术通过代替画面结果。参考中的品牌、标识、文案和未点名层不随风格采用进入当前作品。

## 三、建立图形与连线系统

节点内部先分出图标、标题、说明、参数或状态，再给每个区域留出独立边距。采用一个来源清楚、许可证允许的统一图标家族；同一作品不混用线性、填充、拟物和临时手画图标。每个形状内标签都对应一个实际可见的承载形状；等待字体加载后，分别读取文字块与承载形状的浏览器边界，SVG 圆、路径和多边形还要把可见几何边界换算到同一画布坐标，先比较水平与垂直中心，再在目标尺寸和缩略图检查光学中心。清单 `default_bounds`、文字自身没有越界或 CSS 数学居中都不能代替这项关系检查。没有合适图标时使用简单几何符号，不用复杂但语义含糊的装饰代替。

已对齐节点之间直接连接；需要绕行时只使用必要数量的水平、垂直线段和直角转折，形成最短可读的正交路径。路径从节点边框出发并落到目标边框，不穿过文字、图标或无关节点。虚线只表示明确命名的反馈、可选、异步或间接关系；不能与容器边框重合，也不能出现没有语义的半截横条、彩色短线、下划线或悬空连接。每一条线都应能回答“从哪里到哪里、传递什么”。

先确定线宽层级，再在最终输出尺寸验收：外框与分区、节点框、连接线、图标线条和装饰线有稳定的相对关系，同类元素全程保持同一宽度、颜色和亮度。不要把某个案例的像素值写成全局常数；画布变化时按显示比例重新计算。深色画面避免依靠接近黑色的细线维持结构，编码后仍必须可见；强调色承担分类和路径职责，不用全局高饱和发光补救层级不足。

字体按当前风格选择一套能覆盖中英文与符号的家族，并在网页包内携带许可证允许的字体文件。标题、分区名、节点名和正文可以用不同字重或字号，但不能无故在“正式字体”和“手绘字体”之间切换。等待 `document.fonts.ready` 后检查实际字体、回退字体、字形颜色和透明度；局部单字发灰时先排查回退、嵌套透明度、抗锯齿和覆盖样式，不用逐字涂色掩盖。

## 四、制作确定性运动

动态图的静态结构从第 0 帧起完整可读，并作为不可变量保持到结束。把每个语义事件绑定到一条固定路径和一个不重叠的时间窗口；运动层只绘制光点、短尾迹或必要的局部强调。光点和尾迹必须继承所在路径的颜色：每条语义路径只定义一个基础颜色源，连接线、箭头、光点和尾迹共同引用；明暗、透明度与尾迹衰减只调整各自的 opacity，不另设“活动信号色”覆盖色相。固定边框不随事件脉冲。

光点和尾迹只是方向提示，不是主视觉对象。根据最终观看尺寸、连接线宽、路径长度和信息节奏确定它们的视觉尺寸、尾迹长度、行进时间、停留与再次出现频率，使信号清楚但始终从属于路径和节点；长短路径可以采用不同时间，但相同语义事件的速度体感应一致。某个案例中的像素或秒数只能作为当前作品参数，不能写成默认常数。

路径几何、节点边界、文字内容、字体、框线颜色和亮度在关键状态间应保持一致。用户只要求调整饱和度、线宽、字体或间距时，只修改被点名维度，并把已经确认且未受影响的维度列为不变量；修改后重新检查全片，防止一个 CSS 变量或公共类意外改变其它元素。

## 五、验收

静态图在目标画布与约 360 像素宽缩略图检查标题、机制顺序、栏间比较、共享底座和署名。清点标题、节点、栏头、元信息、微文案、SVG 文字和其它可见字符串，确认它们服从同一语言合同。用浏览器真实边界检查所有文字没有碰框或越界，并逐一比较形状内标签与实际承载形状的中心；用户提供标注截图时，直接复查标注标签及其承载形状。图标与标签的光学中心合理、连接端点落在节点边界、虚线和结构线没有重合或无解释片段后才通过。

动态图至少捕获开始、每个语义事件、结果和结束状态，并运行以下检查：静态图层的几何、文字、线宽、颜色和亮度在全部关键状态保持不变；每个事件只沿声明路径发生一次；文字边界、图标间距和字体加载在各状态通过。对每条发生运动的路径，在真实运行 DOM 中读取连线的 stroke、箭头的 fill、光点与尾迹的 fill，并核对实现中的颜色引用；四者必须来自同一个基础颜色源，只有 opacity 可以不同。任何独立信号色或颜色来源不一致都在导出前判定失败，不能靠观感接近、检查记录或技术校验通过放行。随后在最终观看尺寸按正常速度完整播放网页预览和实际编码成品，确认光点与尾迹相对线条和节点不过大、路径行进不过慢或过急、停留与循环不会增加眼部负担。关键帧、联系表、完整解码和格式检查不能代替这次动效体感检查。

最后把网页源帧与实际编码后的 GIF 或视频解码帧并排比较。随机定位得到的异常帧先用顺序完整解码和联系表复核，不能凭一次不准确定位宣称成片损坏。格式、颜色和移动端兼容性继续按主入口已经加载的交付规则检查。
