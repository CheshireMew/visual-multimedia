# 免费可商用且不要求公开署名的 BGM

用于给已有视频、动画、音频或播客查找、下载、添加或更换背景音乐。它负责把内容判断、公开来源检索、许可收口、素材入账、混音预览和试听确认连成一条链；不建立仓库内不明曲库，也不把“找给视频用的 BGM”改写成寻找视频素材。

## 一、先把用户结果说准确

“免费可商用”不等于“不需要署名”。用户要求免署名、平台没有简介或没有可靠的公开署名位置时，自动检索只接受精确 `CC0-1.0`：许可地址必须指向 Creative Commons Zero 1.0，允许商业使用，且公开署名不是使用条件。没有符合条件的曲目时停止并询问用户是否愿意改为公开署名或付费许可，不能静默退回 CC BY、把署名藏在本地账本里冒充已经履约，也不能因为作者写了“欢迎署名”就把礼貌请求误判成法律义务。

某个具体曲目使用其它许可，但逐曲条款明确允许当前商业使用并明确不要求公开署名时，可以在 Agent 重新打开条款页、确认适用对象和限制后沿通用素材导入器采用；自动来源 CLI 仍只处理精确 CC0，不把模糊的 `free`、`royalty-free`、Public Domain Mark、网站首页宣传语或搜索摘要当成免署名许可。

用户明确说“找 BGM”“给它配音乐”且没有提供曲目，已经授权当前任务使用无需账号的公开检索与下载接口。账号注册、登录、API Key、付费、订阅、发送、上传和发布仍需各自授权。所有候选报告、下载、项目、预览和成品继续位于本 Skill 的 `artifacts/<task-id>/`；用户点名外部交付时只复制已经检查的最终文件。

## 二、先读视频，再写音乐需求

不能只凭文件名、封面颜色或一句“科技感”挑音乐。先用 FFprobe 读取真实时长、画幅、帧率、音视频流、采样率和声道；长视频或内容不明确时生成联系表，并查看开场、主要变化、结果和结尾。音轨存在不等于里面有人声或音乐，还要实际试听或检查静音、响度和内容；不能把整段静音误判成需要避让的人声。

根据真实内容形成一段供检索和比较使用的音乐需求，至少说清：

- 音乐在当前成品中的职责，例如承担推进、提供轻微脉冲、托住情绪、建立空间或只填补静音。
- 开场、发展、转折、结果和结尾的能量变化；没有明显阶段时不要编造戏剧高潮。
- 大致速度、节奏密度、明暗、冷暖、主要音色，以及人声、旁白和关键音效需要保留多少空间。
- 是否必须纯音乐、是否需要自然循环、曲目长度与视频时长的关系，以及开头和尾部能否自然裁切。

有人声或必须保留的同期声时，可懂度优先，选择稀疏、无歌词、动态稳定的音乐并规划避让。确认原音轨实际静音的产品演示、录屏或无对白动画，音乐可以承担更多节奏，但仍应服从界面变化和内容结果，不能用音乐掩盖结构问题。只有视频已经确认由强节拍驱动时，才运行 `scripts/analyze-music-beats.mjs`；普通氛围 BGM 不为形式完整生成节拍合同。

## 三、使用公开、可自动化的来源

先建立任务工作区，再运行：

```powershell
node scripts/background-music-sources.mjs list-sources

node scripts/background-music-sources.mjs search `
  --query "restrained futuristic instrumental background music" `
  --duration-min 30 `
  --duration-max 240 `
  --project <项目目录> `
  --output reports/background-music-candidates.json

node scripts/background-music-sources.mjs validate `
  --project <项目目录> `
  --report reports/background-music-candidates.json
```

正式自动来源只有三项：

1. **Openverse Audio API** 用于宽范围发现。它是聚合索引，检索时使用 CC0 过滤，采用前还会重新读取单条来源记录；搜索结果本身不能代替许可复核。
2. **Wikimedia Commons MediaWiki API** 读取原始音频地址、文件页和扩展许可元数据，只保留文件记录明确为 CC0 的结果。
3. **ccMixter Query API** 先查询 public-domain 结果，再只保留实际许可地址为 CC0 1.0 的曲目。目录较小时如实返回少量或空结果，不拿要求署名的音乐补数。

OpenGameArt 可以作为网页后备来源，但没有稳定的公开发现 API；只能打开具体音乐页，确认该曲目明确标注 CC0 和真实下载文件，再用通用素材导入器入账，不能抓取整站或把其它许可混进候选。Incompetech 等 CC BY 来源要求公开署名，不进入免署名默认路径。Coverr 当前免费许可说明与 API 展示要求不足以形成稳定的无账号免署名自动边界，也不进入默认路径。Pixabay Music、Mixkit、YouTube Audio Library 等没有稳定公开下载接口或需要逐次依赖站内条款的来源，不作为 Agent-first 自动来源；用户提供了具体文件和当前有效权利依据时仍可按普通素材处理。

候选报告只是当次发现结果，不是音乐库、采用记录或最终适配结论。它保存查询、来源运行状态、逐条页面和下载地址、时长元数据及精确 CC0 条款；只有 `acquire` 下载并进入 `media-sources.json` 后，曲目才成为项目候选素材，只有活动时间线显式引用 source id 后才进入成品。

## 四、比较候选但不冒充试听

Agent 用视频需求先过滤明显不合适的候选，再比较音乐职责、能量曲线、速度、密度、音色、纯音乐状态、长度、循环可能性和与人声的冲突。来源标签只能帮助缩小范围，不能证明曲目真的好听、没有突兀段落或适合当前画面。

当前环境能够实际试听时，听候选的开头、主体、明显变化、潜在循环点和结尾；不能实际试听时，必须明确自己只完成了元数据和技术预筛。默认选出一个最强候选制作真实合成预览，不把它称为最终合适；用户要求比较或当前候选差异会显著影响方向时再提供少量可听预览。最终适配只有在用户听过当前合成结果并接受后成立。用户否定候选时保留原视频和已入账素材，停止使用该候选，等待用户要求继续比较或提供新的音乐方向。

## 五、下载、复核与素材入账

从候选报告采用一首音乐：

```powershell
node scripts/background-music-sources.mjs acquire `
  --project <项目目录> `
  --report reports/background-music-candidates.json `
  --candidate-id <候选 id> `
  --source-id bgm-main `
  --usage "当前视频背景音乐候选"
```

`acquire` 必须重新读取提供方的单条记录，再次确认精确 CC0，流式下载真实文件，限制最大字节数，用 FFprobe 证明存在可解码音轨和有效时长，然后调用现有 `scripts/import-media-asset.mjs`。素材账本保存 `external-download`、来源页、提供方、`CC0-1.0`、条款页、取得时间、文件字节、SHA-256 和当前用途；公开署名字段保持为空。下载完成但许可复核、解码或入账失败时保留准确文件和错误，不能把失败素材放进时间线。

从 OpenGameArt 或其它逐曲明确免署名的来源人工取得文件时，也必须把来源页、精确许可名称、条款页和取得时间传给同一个导入器。不要另建 `music-license.json`、下载清单或旁路素材目录复制这些事实。

## 六、加入活动时间线并制作预览

简单已有视频修改使用当前 `media-timeline.json`；活动真源已经迁移到 MediaFlow Pro 时只修改 `project.mfp`；素材解说型继续使用其正式 `import-bgm` 和计划投影。不能为了 BGM 建第二条剪辑时间线，也不能直接覆盖用户原片。

音乐轨应显式引用已入账 source id。曲目长于成片时选择语义和乐句都成立的入点与出点；曲目短于成片时只有确认可以自然循环才重复，不能拉伸、减速或在任意采样点硬接。开头和结尾使用与当前音乐和画面相称的淡入淡出，最后一次循环应收在完整乐句或经过试听成立的尾点。已有声音默认保留；只有用户明确要求替换时才能移除。

混音数值来自当前平台、原声和曲目实测，不设置跨项目固定增益。先测实际响度与峰值，再设置音乐基础增益；有人声时按真实说话范围避让并检查句首、句尾和停顿恢复，静音视频则检查音乐是否过强或压过界面信息。普通 MP4 优先使用目标平台支持的音频编码和采样率，常见交付为 AAC、48 kHz，但用户或平台的明确规格覆盖它。每次修改都生成独立预览；短片可以完整合成，长片沿已有分阶段入口选择覆盖开场、主要变化和结尾的综合样片。

## 七、完成检查

交付前分别确认：

- 候选仍能回到具体来源页、单条许可记录和真实下载文件，素材账本的哈希、字节、许可与文件一致。
- 当前活动时间线确实引用音乐 source id，原片和必须保留的原声没有意外丢失。
- 成片时长、音轨、编码、采样率、完整解码、响度、真实峰值、循环接缝、淡入淡出和结尾成立。
- 有人声时完整试听音乐遮挡与避让恢复；没有人声时确认节奏没有抢走内容注意力。
- 技术检查只证明文件和混音边界，Agent 试听只证明当前听音主体的判断；需要用户选择的风格适配在用户听过合成预览前保持候选状态。

需要正式交付时继续走项目合同与审阅交付流程，让权利、完整观看和交付报告绑定同一个成片哈希。完成文件不等于获得上传或发布授权。
