# 外部生成任务与费用合同

用于图片、视频、语音或其它媒体在进入本地素材账本之前，需要调用外部生成服务的任务。`generation-jobs.json` 是远程操作、费用授权、任务恢复和本地化过程的唯一活动状态；`media-sources.json` 只接收已经下载、校验并本地化的最终素材。两者不能合并。

## 一、为什么要单独保存任务

远程任务在产物落地前可能经历排队、超时、重复查询、收费、失败和恢复。此时还没有可靠的本地素材文件，不能提前伪造成 `media-sources.json` 的 source。每个任务必须保存：

- 供应方与操作名称。
- 规范化输入文件、输入哈希和当前来源版本。
- 预估金额、币种和计费依据。
- `off`、`confirm` 或 `auto` 付费策略。
- 授权状态、时间和内容寻址的授权证据。
- 稳定幂等键、远程任务 id、状态、提交锁、查询或重试次数和回执。
- 远程输出位置、实际费用、费用凭据、下载文件与校验结果。
- 本地化后进入 `media-sources.json` 的 source id。

输入文件按规范化 JSON 计算哈希，空格和对象键顺序不会制造新任务；任何实际输入或 `source_version` 改变都会得到不同幂等键。已有 job id 不能改指新输入，必须建立新的任务 id。

## 二、费用策略

- `off`：不允许产生正数费用；零费用任务可以继续。
- `confirm`：预估费用大于零时必须先保存用户或上游明确批准的证据，才能准备提交。
- `auto`：只有当前任务已经明确授权在所记录范围内自动产生费用时使用；初始化时就必须保存这份范围证据。

预估为零不等于无需记录币种和计费依据。实际完成后保存实际金额和供应方凭据；任务声称成功却没有成功回执与费用记录时不能本地化。

## 三、唯一生命周期

按以下顺序推进：

1. **初始化**：从已通过验证的导演计划和规范化请求建立任务。任务反向引用场景，导演计划只引用 job id。
2. **授权**：根据付费策略记录批准证据。没有费用权限时停在可恢复状态。
3. **准备提交**：生产者写入一次性提交锁并返回稳定幂等键。再次运行不会再次授权收费调用，而是要求查询或接回同一远程任务。
4. **记录提交**：实际供应方调用返回后，保存远程 job id 和原始回执。相同 job id 与回执可以幂等复用，其它 job id 被拒绝。
5. **轮询或恢复**：始终查询同一远程 job id。失败、超时或进程重启不创建第二个收费任务；状态回执和查询次数持续追加到同一记录。
6. **下载、校验和本地化**：只有远程状态为成功、成功回执与实际费用凭据齐全时，才下载真实文件并通过正式入口导入 `media-sources.json`。
7. **消费者采用**：网页清单、视频时间线或音频项目显式引用导入后的 source id。任务成功和素材入账都不能自动改动成片。

网络超时发生在“准备提交”之后但还没有远程 job id 时，提交锁保持有效。先使用幂等键到供应方查询，确认是否已经创建；不能因为本地没有收到响应就直接再次付费提交。

## 四、正式生产入口

从任务说明初始化：

```powershell
node scripts/manage-generation-job.mjs init `
  --project <项目目录> `
  --intent <项目内的内容真源或 video-direction-plan.json> `
  --spec <任务说明.json>
```

视频导演计划会自动提供项目 id、来源版本和场景双向引用。其它图片、声音或媒体生成任务再显式提供 `--media-project-id` 与 `--source-version`；`--intent` 仍必须指向项目内当前活动内容或制作说明并绑定文件哈希，不能为了提交任务另写第二份内容真源。任务说明用通用 `intent_refs` 指向场景、素材槽位或其它实际消费者职责。

`confirm` 策略获得批准后：

```powershell
node scripts/manage-generation-job.mjs authorize `
  --project <项目目录> `
  --job-id <任务-id> `
  --evidence <批准证据文件>
```

提交前取得幂等键和一次性提交锁：

```powershell
node scripts/manage-generation-job.mjs prepare-submit `
  --project <项目目录> `
  --job-id <任务-id>
```

实际供应方返回后，用 `record-submit` 保存远程 job id 与提交回执；后续用 `record-status` 保存同一个远程任务的 `running`、`succeeded` 或 `failed` 回执。供应方成功输出下载到本地后，用 `localize` 调用现有素材导入器完成内容寻址、哈希校验、生成回执和 source id 绑定。

完整参数以 `node scripts/manage-generation-job.mjs --help` 为准。每次操作后运行：

```powershell
node scripts/validate-generation-jobs.mjs `
  <项目目录>/generation-jobs.json
```

验证器同时读取导演计划、规范化输入、回执、本地文件和 `media-sources.json`。它会拒绝失效的计划哈希、未知场景、改变后的输入、错误幂等键、越过费用门、成功状态缺少凭据、以及任务声称已导入但账本不存在或哈希不一致。

## 五、生成主持人或声音的预览

只有当前任务确实要外部生成主持人、avatar 画面或声音时，才在付费完整生成前检查一个能暴露风险的短样：

- 身份与用户授权的角色一致，没有静默换人。
- 名称、数字、专有名词和发音表被正确执行。
- 人声自然度、断句、口型或人物动作满足当前用途。
- 画幅、人物位置、背景、服装或形象连续性足以支持后续场景。
- 供应方输出、任务回执、费用和实际文件能够进入同一恢复链。

这项预览只批准外部生成的人物或声音层，不替代本 Skill 原有“最早未确认层”样稿逻辑，也不批准内容、构图、全部版式或最终剪辑。

## 六、停止条件

- 未获得相应费用授权：保留计划、规范化输入和待批准任务，停止提交。
- 已经准备提交但响应未知：保持提交锁，查询同一幂等键，不重新收费提交。
- 远程成功但文件未下载或校验失败：保留回执，停止入账。
- 已入账但消费者未采用：明确报告候选 source id，不声称成片已经更新。
- 输入、来源版本或导演计划哈希变化：旧任务失效，建立新 id，不覆盖旧任务。
