# 合成旁白与语音

用于用户明确要求为视频、网页动画、音频或播客生成合成旁白，或点名 EdgeTTS、GPT-SoVITS 等语音供应方式时。它只负责把已经确认的媒体文案可靠地变成声音并接回活动时间线，不重新决定内容主张。

## 一、确认语义真源与声音要求

确认后的媒体文案是语义真源。根据朗读需要派生一份合成输入，根据阅读需要派生字幕或屏幕文字；三者保留共同的语义片段 ID，修改含义时回到确认文案，发音标记、停顿和字幕压缩则分别留在对应派生层。

生成前确认语言与地区、声音角色、语气、专有名词、数字读法、目标用途、供应方式和现有联网条件。用户明确要求合成语音或点名某个供应方式，表示可以调用当前已经可用的相应服务；安装工具、新增付费账户、调用未授权外部素材或克隆特定真人声音仍需要单独授权。声音克隆还要确认参考音频的使用权、参考音频中的准确文本和语言；只有音频没有准确文本时先转写并听音校正，不能猜提示文本。

同一项目中，用户最后一次明确指定的供应方式、声音、参考音频和语速覆盖更早的选择。这个变化会使旧生成回执、音频、时间标记、旁白包以及依赖它们的口型或成片计划失效；不能因为旧音频已经生成就继续混用，也不能保留两个“活动声音”让下游猜测。

当前任务是带合成旁白的视频、且用户没有另行指定声音或语速时，直接消费 `SKILL.md` 的当前视频默认基线：按其中的精确声音 ID 唯一解析已注册参考声音，并把基线语速作为本次 `speech.synthesize` 的 `speed_factor`。解析不到、出现歧义、人工声音审核未通过或供应能力不可用时停止，不能换成相似声音、最近使用声音或默认速度后继续。

## 二、选择供应方式

- 用户点名 EdgeTTS 时使用 EdgeTTS。
- 用户点名 GPT-SoVITS 或明确要求使用已授权参考音频克隆声音时，使用 MediaFlow Pro 公开的 GPT-SoVITS v2Pro 操作；没有声音克隆授权时不调用。
- 带合成旁白的视频没有另行指定时，使用主入口已经明确的视频默认基线；音频、播客或没有活动视频基线的其它任务，才根据语言、声音角色、自然度、授权、联网条件、目标格式和当前可用工具选择，并在交付说明中记录选择。
- 除主入口已经明确的视频默认基线或用户点名外，不把 GPT-SoVITS 当作普通 TTS 的自动默认值。
- EdgeTTS 是在线语音合成方式，不是声音克隆，也不应成为所有项目的固定默认值。
- 当前环境没有所选工具时保留文案与时间结构，说明缺少的能力；没有安装授权时停在可继续的真源，不自动安装替代工具。

声音身份会明显改变人物感、可信度或系列气质，而且用户尚未确认时，先生成短试听；用户点名多个声音时，用同一小段分别生成，不能凭角色印象替用户决定。试听段覆盖普通陈述、当前必要英文、专名、数字和一个真实停顿，比较情绪、咬字、英文读法、断句和连续听感。用户已经确认声音，或明确授权完整制作时，可以直接生成完整旁白。精确声音身份同时保存供应方声音 ID 和显示名称；声音缺失、歧义或已下架时停止，不能静默替换。

## 三、使用 EdgeTTS 生成原始声音

优先把完整合成输入保存为项目内的 UTF-8 文本文件，再让 EdgeTTS 从文件读取，避免长文在命令行中被截断或转义。可用 CLI 时使用这一类调用：

```powershell
edge-tts --file narration.txt --voice <voice> --rate=<rate> --volume=<volume> --pitch=<pitch> --write-media narration.mp3 --write-subtitles narration.vtt
```

带正负号的 `rate`、`volume` 和 `pitch` 使用 `--参数=值` 的写法，避免负值被解释成新的选项。声音由用户指定；用户没有指定时，根据语言地区和声音角色选择一个当前可用声音，并记录名称。供应方式的可用声音和命令参数以当前工具实际帮助信息为准，不把本机路径或某个案例的声音写成跨项目默认值。

每次生成保留：

- 确认旁白与实际合成输入。
- 供应方式、供应方声音 ID、声音名称、模型、语速、音量、音高和生成时间。
- 未经后期处理的原始音频。
- 供应方式生成的字幕或时间标记。
- 实际合成输入的 SHA-256、原始音频的 SHA-256，以及供应方任务或操作 ID 和私有回执。

远程语音服务在原始音频进入素材账本前，必须先用项目唯一的 `generation-jobs.json` 保存规范化合成请求、当前内容版本、费用策略、授权证据、一次性提交锁、供应方任务或操作 ID、回执和实际费用。同步接口没有供应方 job id 时，使用绑定幂等键且在回执中明确标为供应方未提供的稳定操作 ID；响应未知时仍不能直接再次提交。本机 GPT-SoVITS 不伪装成远程生成任务；它保留公共 CLI 请求、响应、参考音频哈希和输出哈希作为私有生成回执，再由同一素材导入器入账。

原始音频生成后由正式生成任务管理器的 `localize` 动作进入项目唯一的 `media-sources.json`，并通过 `--speech-text` 保存实际合成输入哈希；要求精确声音身份时同时使用 `--voice-id`、`--voice-name` 和 `--exact-voice`。远程返回的临时地址不是项目素材，必须先下载、验证并本地化。生成成功、素材入账和旁白进入成片是三个独立事实，视频时间线或音频项目仍要显式引用对应 source id。

当前视频类型要求逐段冻结旁白时，再建立 `narration-bundle.json`。`schemas/narration-bundle.v1.schema.json` 只索引已经入账的真实音频、准确文本与文本哈希、时间标记与哈希、FFprobe 实际时长、声音身份、参数和听音结论；它不生成声音，也不复制素材文件。合成输入、音频或时间标记变化后，旧旁白包和引用它的计划一起失效，不能只改时长数字继续渲染。

调用失败时保留这些输入和已经成功的中间结果，报告失败发生在供应服务、生成、写入还是读取阶段。

## 四、使用 GPT-SoVITS v2Pro 克隆已授权声音

通过 `scripts/local-media-environment.mjs` 检查本机配置并运行本次 `mediaflow-cli describe`，确认公开操作中存在 `speech.synthesize`，再运行 `runtime.inspect`，确认 `gpt-sovits-v2pro` 为 `ready`。请求参数和结果字段完全以本次 `describe` 返回的 schema 为准；语义上必须提供确认后的目标文本及语言、参考音频、参考音频的准确文本及语言、WAV 输出位置，并按需提供辅助参考音频、语速、随机种子、超时和覆盖选择。Skill 不直接启动 `api_v2.py`，不维持后台服务，也不读取 GPT-SoVITS 内部配置。

用户点名已注册的全局声音，或主入口已经给出当前视频默认声音时，用 `voice-resolve --voice <id、名称或别名>` 从本机配置声明的声音根目录唯一解析。解析结果中的参考音频、准确文本、语言和哈希是本次请求的同一组输入，不从当前项目复制参考音频，也不把视频基线扩展成音频、播客或其它项目的默认。没有匹配或出现歧义时停止；`manual_voice_review` 尚未通过时先交付短试听并等待真实听音，不能因为技术验证通过就直接宣布声音身份已经确认。

只接受 MediaFlow Pro 实际生成并验证过音频帧的 WAV。保存响应中的引擎与版本、输出路径、音频 SHA-256、实际时长、采样率、声道、参考音频 SHA-256 和设备；以参考音频哈希形成稳定声音身份，例如 `gpt-sovits-v2pro:<reference-sha256>`，显示名称继续使用用户确认的角色或声音名称。目标文本、参考音频、参考文本或模型版本变化都视为新的生成输入，不能沿用旧回执或旧声音时间。

长旁白按已经确认的语义句生成或保留可无损重组的句级片段。必要英文先用原写法试听；确实读不好时只修改合成输入中的读法，字幕继续使用正式写法。异常停顿先检查标点、分句、片段边界和声音模型，再考虑语速；不能把“全部改成中文”或整体加速当成通用修复。完整试听后，若只有一句存在发音、情绪或停顿问题，只重新生成那一句，再通过项目音频时间线按原顺序拼接、重新测量时长并更新后续时间边界；不能为一个局部问题重抽整段声音，也不能直接覆盖旧文件却沿用旧哈希。修正后的完整轨必须重新试听，检查句间底噪、音色、响度和停顿是否连续。

为英文、缩写、专名或平台名改写读法时，必须保留确认文案原有的语义停顿；不能为了让合成输入更易读，就在原本连续的位置加入逗号、句号、额外空格或新的片段边界。先用包含替换词前后语境的最短完整短句生成试听，并按成片实际语速试听连接处，再进入完整轨。ASR 只能帮助确认模型大致读成了哪个词，不能证明前后停顿、重音和连续听感自然；当前环境无法直接听音时，把这段局部试听明确交给用户并保持听音状态未确认，不能用识别文本或波形代替。

GPT-SoVITS 不提供 EdgeTTS 式逐字边界。需要字幕、角色口型或精确场景对齐时，先以真实 WAV 为时间真源，再用已经校正的文本完成转写或对齐并实际听音复核；不能把整句平均切分成伪造的字词边界。

## 五、用真实音频建立时间

使用 FFprobe、编辑软件或等价工具读取原始音频的实际时长和格式，再结合试听、波形与时间标记更新语义片段。字幕或 VTT 提供初始定位，最终声音文件才是时间真源。

媒体总时长通常跟随完整旁白。当前视频默认基线或用户明确指定的语速是合成输入，不是为了卡时长临时加速；生成后不能再叠加变速。用户给定固定时长时，先修改信息密度、措辞或视觉安排；需要偏离活动语速时先取得新的明确选择，不能用继续加速掩盖断句、发音或合成缺陷。不能截断尾句，也不能用整条视频循环来填补旁白时间。已有素材怎样延长画面由活动视频时间线决定；网页动画怎样保持状态由已经确认的语义片段和运动职责决定，两者不共用补时规则。

降噪、均衡、响度、采样率、声道和编码属于后期派生层。保留原始音频，由目标载体和平台规格决定处理值，不把单个项目的响度、码率或采样率写成通用默认。

## 六、试听与验收

在真实播放器中从头到尾试听，并检查：

1. 实际声音与确认文案含义一致，名字、数字和专有名词读法正确。
2. 断句、停顿、重音、语速和情绪适合当前受众，不因追求短时长牺牲理解。
3. 开头没有异常空白或截字，最后一句完整结束。
4. 原始音频、字幕或时间标记可以读取；素材账本中的声音 ID、显示名称、文本哈希、音频哈希、供应方式和参数与实际生成一致。
5. 进入视频、动画或播客时间线后，完整旁白仍存在，语义片段边界与当前画面或章节对应。
6. GPT-SoVITS 输出的参考音频哈希、参考文本、目标文本、引擎版本和实际 WAV 一一对应，克隆声音与用户授权的参考声音相符，没有静默换参考或换模型。

技术元数据和波形只能辅助检查，不能代替实际听取。交付时按请求提供确认文案、合成输入、参数记录、原始音频、时间标记，以及从它派生的后期声音或最终媒体。
