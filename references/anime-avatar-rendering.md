# 二次元口播渲染、角色窗与验收

本文件用于已经通过身份、校准素材、视觉口型库和真实语音时间轴质量门的活动任务。程序从不可变计划生成口播轨，按需装配固定角色窗，并用机器报告、联系表和完整观看共同验收；不在渲染器中恢复角色专属判断或另一套素材真源。

## 一、从素材库合成新口播

先生成一次性分段计划。新建 v4 项目默认使用 `384×384 / 24fps` 中等母版、24 秒目标单元、48 秒连续讲话硬上限和 1.2 秒静音切分阈值；实际参数以 `avatar-project.json` 为准。24 秒只控制缓存粒度，不是允许切断讲话的硬切点。分段器只在已复核时间轴的真实静音区间落刀；连续讲话可以在 48 秒内超过目标长度，超过硬上限则明确拒绝，不能把一个词、音节或连续口型拆到两个无上下文单元：

```powershell
python scripts/render-anime-avatar.py plan `
  --project <项目目录> `
  --timeline <speech-timeline.json> `
  --duration-seconds <最终底片时长> `
  --plan-id <计划 id>
```

计划完成后由 Agent 检查每个单元摘要和两帧边界制品。单元内部仍逐条记录原片连续、严格光流、微过渡或拒绝；跨单元边界只由独立 seam bridge 承担。没有拒绝项且结果可接受时，Agent 再执行技术确认；这不是让用户阅读或批准 JSON 计划：

```powershell
python scripts/render-anime-avatar.py confirm-plan `
  --project <项目目录> `
  --plan-id <计划 id>
```

最后编码：

```powershell
python scripts/render-anime-avatar.py render `
  --project <项目目录> `
  --plan-id <计划 id> `
  --output <输出 mp4>
```

最终底片时长已经确定时填写 `--duration-seconds`；省略时角色轨匹配裁切后的完整音频时长。渲染器不会固定追加尾段。前置静音、足够长的句中停顿、音频真实尾静音，以及底片确实长于音频的部分都交给 `closed_motion_clips` 播放闭嘴动态待机。短于一个自然动作窗口的语流微停顿属于协同发音的一部分，不强制插入一次完整闭嘴，否则会重新产生机械“叭叭叭”。待机保留呼吸、眨眼、头发、耳朵、呆毛、饰品和肩部微动，不用静帧补时，也不重新调用口型分类。

渲染器按以下顺序工作：

1. 从素材账本解析校准视频和音频，验证文件、哈希与项目引用。
2. 按时间轴裁切音频，建立普通话拼音韵母到 A/I/U/E/O 的路径；双唇音开头保留短暂 `CLOSED`。
3. 在每个音节内部用真实音频能量决定相对张口强度，并把该音节能量峰作为高权重的视觉口型核心。核心允许在素材覆盖不足时让位于整画面连续性，不能为了逐字满分而让头部、头发或身体瞬移。
4. 素材视频只在建库时视觉分类一次。运行时读取现有标签，不重新识图、不计算嘴型、不要求人工再次确认大张口帧。
5. 每个元音核心先成为一个可追溯的 anchor。调度器用非传递的间隔选择找出彼此至少相距 8 帧的主核心，再把未选核心附着到最近主核心形成显式 `coarticulation cluster`；不能因为一串相邻间隔都小于 8 帧就把整句传递合并成一次张嘴。其它核心标记为 absorbed，不能从报告中消失，也不能伪装成已经逐一命中。
6. 规划器先运行 `standard` 模式。每个主核心只保留同一元音中接近最佳 `peak_strength_level` 的完整动作，严重错误的强度不能因为某条自然转场更便宜而入选；再把低口型入口、发音峰值和低口型出口映射到共同发音窗口。片段内部使用浮点源时间位置做分段线性、单调的时间伸缩；最终拼好的实际路径必须满足源速度不超过 `2.0x`、加速度不超过质量门，接缝间隔在 24fps 下不少于 8 帧。它不交替抽取 `+1/+2` 帧，不倒放，也不靠 8–15 倍跳帧抢口型。已被用户认可的角色与语音组合只要标准模式可行，后来增加恢复能力也必须保持同一份标准规划结果；报告记录 `planned_annotation_planner_mode=standard`。
7. 相邻 gesture 在同一 take 中存在已审核的有向 `natural_transition_span` 时，从入口沿原视频正向播放完整过渡，不把过渡中间帧当成任意双向跳点。其它相邻片段通常在 gesture 或 idle 的显式低口型端点接缝。快速连读若无法在 2 倍速度内让前一个动作完全闭合后再启动下一个动作，可以让相邻动作从 AI 标注且整画面兼容的中等口型连续承接；入口和出口强度分别建模。标准模式优先两端同级的中等口型；只有标准模式无解时，有界恢复才允许内部协同发音边界使用相差不超过一级、最高为 `level 3` 的部分端点。所有承接仍须通过去嘴整画面外观、运动速度与方向及四帧接缝复核；头发、眼睛、下巴、耳朵和身体不连续时必须拒绝，不能因为口型更接近而放行。
8. `standard` 确实无解时，同一个规划器才进入 `bounded-recovery`，不另建长视频或失败兜底路线。恢复只改变视觉动作的可用窗口：一个发音核心过于靠近语音区间起点时，可以从它前面的稳定静音尾部最多借用相当于 24fps 下 5 帧的视觉预备动作；不得跨过已经视觉确认的 `CLOSED` 锚点，借用后保留下来的静音核心仍必须使用动态闭嘴动作。音频、逐字边界、目标总时长、`2.0x` 速度门和加速度门都不变。边界附近的一组过密核心若外侧主核心使整组不可行，恢复模式从组内选择仍能满足路径约束的主核心，其余核心继续以 absorbed anchor 留在报告中，不能让一个边界核心吞掉整句。
9. take 与 clip 的轮换要求进入规划状态，并按当前台词真正用到的元音、强度可用素材数和动作块数量自适应。规划器先在满足连续性的候选中强制可实现的多样性；如果恢复模式只因强制换 take 或 clip 而无解，可以采用 `continuity-first-fallback`，优先保留自然连续路径，同时在报告中把未满足的多样性合同如实标为失败。这个状态只说明机器找到了满足运动边界的路径，不等于视觉效果通过，更不能伪造素材强弱变化。
10. 候选接缝同时比较去嘴整画面外观以及切口前后数帧的运动速度和方向。每个内部接缝和跨单元边界都读取 `boundary-2` 到 `boundary+1` 的四张真实母版尺寸画面：在有界代理尺寸估计双向光流，再回到真实像素复核光度残差、越界和运动包络。严格通过时记录为 `strict_optical_flow`；只有保守亮度警告时可记录两帧 `micro_optical_flow`；人物结构或运动不兼容时必须拒绝。
11. `render-plan.json` 以 `project://` 或 `skill://` 定位符绑定素材库、时间轴、项目、素材文件和运行脚本的 SHA-256；逐帧路线和诊断按单元外置并各自绑定哈希。确认动作把不可变总计划内容哈希写入 `approval`。任一输入、代码或确认后的计划内容发生变化，正式渲染必须拒绝旧计划；这不妨碍新计划按局部语义键复用未变化单元。
12. 已确认计划中的严格光流和微过渡都使用两个输出帧承接。正式编码阶段按计划重新生成同一四帧窗口并逐帧校验预检哈希；最终运动补帧只给已经连续的运动增加时间采样，不能用来掩盖硬切。
13. 全程使用一个固定源裁切和固定中等母版尺寸，不追踪月牙、胸针、眼睛或其它角色专属锚点，也不对每张图重新摆位置。最终视频帧率和窗口尺寸由通用时间线处理；角色轨不再先做 48fps 整轨补帧。
14. 稳定无声区间只调用已审核的 idle clip 连续运动；长静音通过兼容端点连续承接，禁止重复同一帧冻结，也禁止因为某一条接缝成本最低就机械复用同一个待机片段。规划器必须像管理 gesture 一样管理 idle 的已用片段、最近五段重复次数和剩余可达性：素材足够时优先覆盖至少五条不同待机动作，最近五个 idle block 不重复同一片段；如果真实端点兼容性无法支持这一硬约束，才能显式进入 continuity-first fallback，并在计划和机器门中报告未达到的 idle 多样性，不能静默退回单片循环。短于共同发音窗口的微停顿可以被相邻 gesture 的自然回落覆盖，但必须在报告中单列，不能算作稳定停顿闭嘴失败。前置静音、稳定句中停顿和实际尾静音采用同一种规则，不另外追加固定尾段。

校准视频的中等母版与全分辨率原始帧分别使用内容寻址的共享缓存。原始帧身份同时绑定母版内容哈希、裁剪、尺寸、帧数、像素格式和描述符版本；缓存缺失时先核对当前受管用量、预计新增量、容量上限和最低剩余空间，再解码一次并写入带终态清单的共享条目。新的 `plan-id` 或 `task-id` 只复用这一份只读帧存储，不再在各自 working 目录复制 `source-frames-bgr-u8.bin`。计划和渲染在内存中只保留小型描述符视图与固定容量取帧缓存；单元 core 排除边界帧，两帧 seam bridge 独立拥有边界。单元内容变化时只失效该 core；只有边缘动作变化才额外失效相邻 seam。装配时按顺序无重编码拼接画面，并只混入一次连续音频母版。每次规划使用新的 `plan-id`，每次编码使用新的 `task-id`，working、report、计划和输出都拒绝覆盖；失败或不完整的共享缓存保持原位并报告准确路径，不能自动归档后再复制一份。

渲染同时交付一个便于直接观看的完整方形口播轨，以及一份 `avatar-track-clips.json`。完整轨保持原始纯色背景；片段清单用于普通视频或采访视频中的局部导入、编辑和重渲染。圆形、方形、位置、大小和与底片的关系属于最终视频时间线，不烘焙进母版或角色库。

## 二、可选：放进圆形或方形窗口

用户要求讲解视频右下角或其它固定位置出现圆形、方形角色窗时，才进入这一分支。全屏使用方形口播轨时跳过。角色窗是最终视频的构图，不烘焙进母版、校准视频或可复用口型库。

角色窗的大小先服从用户确认的人物存在感和当前视频层级，不能只以“哪里还没挡住内容”反推到一个尽量小的尺寸。底片是可编辑网页、代码画面或其它可重排视觉时，先把角色窗外接矩形交给底片真源作为排除区域，重新安排关键界面、标题、证据和字幕，再生成底片；不能等界面完成后把角色缩进剩余角落。底片是真实录屏或其它不可改写证据时保持证据完整，再在视频时间线选择角色窗位置、镜头裁切或局部放大，并用代表帧确认没有遮住当前语义重点。

先把底片和已经渲染的方形口播形象轨都导入同一个 `media-sources.json`。Agent 直接查看底片代表帧与角色轨代表帧，确定一次固定的正方形 `avatar_crop_xywh`。这块取景要让头顶、耳朵、呆毛和发梢位于安全区，肩部与衣服覆盖下方圆弧，同时尽量减少头部周围的空白。底部生成字幕需要排除时，也在这一次固定裁切中完成。

然后建立角色窗任务：

```powershell
python scripts/compose-anime-avatar-inset.py init `
  --project <项目目录> `
  --job-id <任务 id> `
  --base-source-id <底片 source id> `
  --avatar-source-id <方形口播轨 source id> `
  --avatar-crop <x,y,width,height> `
  --shape circle `
  --x <窗口左上角 x> `
  --y <窗口左上角 y> `
  --size <外圆直径> `
  --border-width <边框宽度> `
  --border-color "#FFFFFF" `
  --shadow `
  --audio-source avatar
```

`x`、`y` 和 `size` 都以底片像素为单位；`size` 是包含边框的外圆直径或方形外边长。1920×1080 画面可先用 224 像素作为评审起点，通常在 200–280 像素内结合人物安全区和信息密度调整；不再使用 150 像素的小头像，也不把 900×900 的内部旧渲染尺寸当作画面窗口。`avatar_crop_xywh` 必须是正方形，并在所有帧使用同一组值。纯圆形使用 `circle`；无需遮罩的方形使用 `square`。纯白角色背景直接保留在圆内，不抠图。音轨使用 `avatar`、`base`、`mix` 或 `none` 明确选择。

任务结构以 `schemas/anime-avatar-inset.v1.schema.json` 为准。它只引用素材账本中的 source id，不另存素材路径。渲染时运行：

```powershell
python scripts/compose-anime-avatar-inset.py render `
  --project <项目目录> `
  --job avatar-insets/<任务 id>.json `
  --output renders/<输出文件>.mp4
```

脚本使用一块固定遮罩、一组固定坐标和一个共同时间范围合成整条角色轨，输出完整底片时长，并在 `reports/avatar-insets/<任务 id>/` 生成联系表和合成报告。命令中的任务和输出相对路径一律相对显式 `--project` 解析，不能随当前工作目录漂移，也不能写到项目外。默认 `end_behavior` 是 `require-full-track`：角色窗持续到底片结束，并要求输入角色轨覆盖这段完整时间。角色轨应在 `render-anime-avatar.py plan` 阶段用 `--duration-seconds <底片时长>` 建立完整成片时间线，再确认计划并编码；有台词时走口型，无台词时播放闭嘴动态待机，因此不会为每个视频额外制造尾段，也不会冻结最后一帧。角色画面、圆底、边框和阴影使用同一个时间范围，不会留下空白圆框。只有用户明确要求在某个时间点隐藏，才使用 `--end-behavior hide`；需要角色窗只覆盖指定区间时填写 `--duration`。底片的其它内容、字幕和结构继续来自原底片。

Agent 必须查看最终联系表并完整播放成品，确认：

- 角色窗直径与当前画面层级匹配，头肩占比充足，周围没有大面积空白。
- 头顶、猫耳、呆毛、发梢和发饰在全片都处于圆内。
- 肩部和衣服覆盖下方圆弧，左右没有白色楔形、黑角或截空。
- 外圆、边框、阴影和人物整体位置全程固定；眨眼、口型、头发和耳朵仍保持角色轨原有连续运动。
- 最终采用的声音与角色窗出现时间一致，底片其它画面保持原有内容关系。

先导出五到十秒真实声音的小样并完整观看，再跑全片。小样要经过“音频 → 时间轴 → 素材库 → 方形口播轨 → 角色窗合成”的完整链路，不能用几张手写状态图代替正式生产者输出。成片确认后再把输出导入素材账本，并进入常规 `media-delivery.json` 检查。

## 三、质量门

### 母版

- 身份与用户确认一致。
- 纯白、不透明、无文字和无抠图残留。
- 固定正面头肩，轮廓和关键饰品处于安全区。
- 服装连续覆盖底边。

### 校准视频

- 约 15 秒、固定机位、固定人物底部、无缩放和重构图。
- 两轮完整而短促的 A/I/U/E/O，前中后有闭嘴连续运动。
- 头部动作克制；头发、耳朵、眼睛、呆毛、饰品和肩膀有连续微动。
- 无字幕、文字和水印；如字幕无法避免，固定裁切能完全排除且不伤构图。

### 视觉素材库

- 标注声明为 `ai-visual-review`，并记录实际查看的联系表。
- A/I/U/E/O 各至少一条视觉成立的完整动作，每条有 rise、peak、fall 和 `0–4`；实际存在的其它 take 也全部标出。
- CLOSED 穷尽所有视觉成立的连续闭嘴运动；前中后各一段是最低覆盖门，不是提取上限。运行状态覆盖全部源帧且没有空洞或越界。
- AI 已复核最大张口、E/O 易混淆帧和每条连续动作。

### 注册与采用

- 注册表、角色包、素材账本和口型库的 id、版本、能力事实与哈希一致；审阅证据真实存在。
- `default_library` 只由独立确认设置；存在一个或多个注册角色时仍可以保持 `null`。
- 全新 Skill 内任务项目通过 `adopt-library` 只保存 id 与版本，并由 `check-anime-avatar-resources.py --deep --project <项目目录>` 证明正式消费者加载了注册包、母版、校准视频和口型库。
- 旧项目只由 `migrate-library` 读取；正常加载器只接受当前活动版本。迁移前的项目和产物不被删除或覆盖。

### 新语音

- 逐字稿精确，裁切明确，时间边界已经听音或由可靠的 TTS boundary 确认。
- 时间轴的汉字序列与文本一致，单位没有重叠或倒序。
- 不用错误自动转写替代用户确认文本。

### 成品

- 每个原始音节核心都有去向；报告如实区分 realized 与 absorbed。主核心口型、大开口和整体语流达到质量门，不为了声称逐音素满分而破坏连续动作。
- 没有相同静帧长时间保持，没有一秒多次无意义“叭叭叭”，也没有一个大口型持续覆盖多个音节。
- 5 秒后没有因为素材耗尽而机械重复同一动作；两条 take 与闭嘴段有实际轮换。
- 切换处没有人物整体瞬移、头部大幅跳变、下巴融化或双重五官。
- 编码消费已经确认且哈希有效的 `render-plan.json`；全部接缝在编码前可见，拒绝项为零，运行时重新规划次数为零。
- 活动项目只使用 v4 项目和 v3 分段计划；报告证明中等母版、单元计划、角色片段、接缝桥和连续音频各自是 `rendered` 还是 `reused`。修改一个中间单元时，未变化单元必须命中；连续音频没有被切碎或重复混入。
- `avatar-track-clips.json` 连续覆盖完整帧数，所有项目相对文件和哈希真实存在，MediaFlow Pro 能将它们作为普通素材批量摆入同一时间线。
- 所有稳定无声区间都保持闭嘴动态待机；计划同时报告 idle 可用片段、实际使用计数、最近五段重复上限和多样性是否成立，素材足够时不得连续机械复用同一条待机。协同发音覆盖的短微停顿单独报告。成片没有固定追加的尾段、空白圆框或静态冻结。
- 音频、口播形象轨和最终视频时长一致，用户完整观看过最终导出。

## 四、出问题时从哪一层重做

| 可见问题 | 根因层 | 正确处理 |
|---|---|---|
| 人物整体上下左右跳 | 独立图片身份/构图不一致，或校准视频有漂移 | 回到同一母版和固定机位校准视频；不逐图加坐标 |
| 下巴变形、嘴位置漂移 | 局部嘴图、局部重绘，或接缝两端人物结构/运动不兼容 | 只用同一源视频完整帧；仅亮度警告可用微过渡，结构或运动不兼容则回到素材库或校准视频层处理 |
| 全是小口型 | 分类把形状当大小，或能量只映射到低级别 | AI 复核每类 0–4 和真实最大开口；检查音节内能量映射 |
| 嘴长时间张大 | 校准源把一个元音喊太久，或运行时保持 peak | 重做短促完整的校准音节；运行时使用 rise/peak/fall |
| 快速反复开合 | 逐帧强制标签、时间轴过碎或把每个微停顿都强制闭嘴 | 检查协同发音 cluster、8 帧动作间隔、`2.0x` 源速度门，并复核字边界和裁切 |
| 5 秒后重复变多 | 每类只有一段素材，或选择器总回同一 take | 校准视频提供两轮；验证报告检查 take 使用 |
| 换台词后失效 | 素材只按原句顺播，没有音素时间轴 | 使用新音频的 `speech-timeline.json` 和现有视觉库重渲染 |
| 圆圈底部露白或黑角 | 母版底边没铺满衣服，或最终圆形裁切错误 | 母版层补足连续衣服；窗口层固定圆形遮罩并复核 |
| 无声处人物空白、张嘴或冻结 | 角色轨短于底片，或无声区间仍走普通口型路径 | 按底片完整时长重渲染角色轨；所有无声区间统一使用连续 CLOSED 动作，并验证交付画面帧数 |

这些修复发生在各自的唯一真源。不要在渲染器里为某个角色、某句话或某个坏帧加入硬编码例外。
