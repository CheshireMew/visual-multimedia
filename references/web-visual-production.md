# 网页优先的视觉媒体制作

用于实际制作图文卡片、封面、图表、概念图、动态图解、GIF、代码生成动画、可手动推进的多场景 HTML 或无实拍视觉画面。所有代码生成视觉都先成为能够直接预览和修改的网页，再从同一网页交互播放或导出静态图、动画和视频。

制作带个人身份标记的网页卡片时读取 `assets/creator-identity/identity.json`，先根据可靠内容依据选择且只选择一个角色：确认原创使用头像与作者署名；确认由本人筛选、核对或整理使用明确的“整理”贡献说明，可带头像；普通非原创或来源不明只使用半透明制作水印，不带头像，也不暗示作者或来源。当前请求提供另一套身份、归因或明确要求不加标记时服从本次要求。身份资源不是创作者工作、生活或教学素材库；需要这类复用素材时从用户指定的注册 `creator-media` 库显式采用。来源项目、赞助者、Skill 元数据、风格参考和案例作者只证明来源或示范结构，不成为当前作品作者。当前内容与纯文字卡、重复字段清单、编辑证据卡、技术机制对比或稳定全貌动态图匹配时，读取 `assets/web-card-cases/catalog.json` 中相应案例的预览、网页、清单和风格档案；技术图解同时读取 `technical-diagram-production.md`。案例只提供 `reuse` 声明的构成结构与制作链，当前内容仍重新决定 `adapt` 中的文案、节点、配色、字体、画布、时间与署名。

## 一、网页作为唯一视觉真源

代码生成视觉默认复制 `assets/web-media-starter/` 整个目录，建立一个由本地 HTTP 服务预览的网页包。网页包由 `editable-media.json`、入口 HTML、`editable-media-runtime.js`、media-sources v4 素材账本和它们引用的全部文件组成；所有引用都必须落在网页包目录内，不能使用 `..`、盘符、绝对路径、URL、反斜杠或符号链接借用包外文件。网页至少包含固定逻辑尺寸的媒体画布；预览、场景导航和编辑控件放在画布外，并能在捕获模式隐藏。

先按 `visual-production-profiles.md` 继承或选择制作配方。项目已有风格档案时，HTML 视觉变量、字体、素材处理和基础图形读取共享视觉核心；静态画布结构只读取静态构图实现，场景主时间线只读取时间运动实现，手动或混合播放控件只读取交互实现。目标载体没有适用实现层时，根据当前内容建立该层，不从其它层猜测。不能只在说明文字里写了配方，网页仍然临场使用另一套颜色、材质、构图或动作。

`schemas/editable-media.v5.schema.json` 是 `editable-media.json` v5 的唯一结构合同，`scripts/editable-media-contract.mjs` 负责执行它和包边界；校验器、HyperFrames 工作副本和 MediaFlow Pro 消费端都只能读取这份合同，不得另写一套宽松字段表。`editable-media.json` 是当前网页包的权威配置。入口 HTML 负责 DOM 结构、CSS 关系、数据怎样投影成画面以及确定性动画算法，不保存另一份场景、尺寸、主题、参数或默认文案。清单中的职责固定为：

- `scenes` 保存有序语义场景；每个场景声明页面职责、内容形态、内容版式、时长、语义步骤、`motion`、数据覆盖和素材槽位绑定。每个步骤都要说明它是开始、变化、结果还是保持状态，是否进入关键状态审阅，以及该状态实际表达什么。
- `playback` 保存 `manual`、`autoplay` 或 `hybrid` 播放方式、帧率、循环和导航能力。手动表示由用户推进；自动表示时钟连续推进；混合表示场景内自动运动、场景边界等待用户。
- `layout_contracts` 保存内容版式的适用页面职责、内容形态、容量、必需字段、必需图层和素材槽位。它回答当前内容应该采用什么结构。
- `variants` 保存方形、竖版、横版等输出比例的画布和局部图层覆盖。没有覆盖的字段继承图层 `default_bounds`；`visible`、字号、透明度和层级与位置尺寸一样属于正式变体字段。
- `parameters` 保存不自然归属于单个图层、但需要由制作端或编辑器调整的共享控制量。每项必须声明稳定 ID、类型、全局或场景作用域、默认值、是否可动画、单位、控件、可选 CSS 变量和数值或选项约束；场景只覆盖 `scope: "scene"` 的参数。
- `data_fields`、`theme_variables`、`resources`、`quality`、`production` 和 `delivery` 分别保存内容默认值、视觉变量、非媒体运行资源、量化验收、来源版本关联和交付方式；场景只写变化的数据，缺省值继承 `data_fields.default`。`media_sources` 唯一指向包内 media-sources v4 素材账本，每个 source 必须明确声明 `browser`、`native-underlay` 或 `native-audio` 管线。

独立素材使用 `scripts/import-media-asset.mjs` 导入当前网页包，并明确传入 `--pipeline`。图片、截图、图标、生成图、需要由 DOM 作为画面元素绘制的视频使用 `browser`；作为网页透明层下方原生视频轨合成的视频使用 `native-underlay`，同时声明 `--fit`、`--playback`、`--audio`、`--source-in-ms` 和 `--gain-db`；独立原生音轨使用 `native-audio`，同时声明 `--loop`、`--source-in-ms` 和 `--gain-db`。导入器读取已有素材账本版本，普通 media-sources v3 工程不能传网页管线，media-sources v4 网页素材账本不能缺少管线；代理只继承原片管线，不能改绑。

入账不等于采用。`browser` 素材由 `media-source` 数据字段及场景素材槽位采用；`native-underlay` 和 `native-audio` 也必须各自由一个 `media-source` 数据字段的默认值或场景数据指向 source id，MediaFlow Pro 才会建立原生片段计划。原生 source 不能绑定到浏览器图片槽位。使用 `native-underlay` 时，输出变体的 `canvas.background_mode` 必须是 `transparent`，背景色使用透明色，HTML 的 body 与媒体画布也必须真正透明；需要显示在原生视频之上的文字、图形和控件继续由网页绘制。

查询参数 `variant=<id>` 选择输出比例，`scene=<id>` 与可选的 `step=<id>` 选择场景状态，`time=<ms>` 表示所选场景内的时间。内容版式和输出比例是两个判断，不共用一个字段。

同一信息只保留一个可编辑位置：

1. 标题、正文、标签、数值、来源和状态数据集中保存；场景只覆盖当前信息单元实际变化的字段。
2. 颜色、字体、字号、线宽、圆角、阴影、间距和背景集中为视觉变量，并与项目风格档案中的实际规则一致。
3. 对象位置、分组、层级和安全区由网页结构负责。
4. 场景与步骤组成一个主时间线，播放、暂停、前进、后退和定位使用同一状态更新逻辑。
5. 回弹强度、错峰间隔、轨道半径、镜头幅度、阈值等共享算法控制量集中为类型化参数；不要把它们藏在 DOM 属性、全局变量或某个编辑器专用状态里。
6. 输出比例、像素尺寸、场景时长、帧率、循环和背景集中配置。

可编辑状态与动画状态必须在同一字段上只有一个控制者。通用编辑运行时需要改写某个图层的位置、旋转或透明度，而主时间线也需要持续改变这些字段时，使用“可编辑外层 + 动画内层”，或者让编辑覆盖值进入主时间线计算；运行时和动画不能在同一个节点上轮流覆盖同一属性。定位到任意时间后，编辑状态、动画状态和捕获画面应同时成立。

承担阅读的卡片、面板、坐标系和标题区默认保持稳定，动画作用于其中真正发生变化的数值、对象、比较状态、强调范围或关系。只有容器自身的移动、拆分、合并确实表达语义时才移动容器；不能用整张卡片持续漂浮、缩放或摇晃掩盖内部没有变化。持续可读文字与装饰运动分层，文字内层不继承装饰外层的旋转、镜像、透视或路径变换，避免圆内文字倒置、流程标签倾斜和动画结束后排版失真。

### 在最终显示尺寸完成界面细修

先让内容版式、风格档案、字体和素材在目标输出变体中真实成立，再处理下面的细节；它们只改善已经选定的视觉关系，不重新选择风格或把媒体制作扩张成应用界面设计。

- 字体加载且最终宽度确定后查看真实换行。标题出现突兀短行或孤字时，可以使用 `text-wrap: balance`；正文、说明和图注只有在 `text-wrap: pretty` 确实改善行尾、又没有破坏版式容量时才使用。动态计数、时间、价格、指标和需要纵向比较的数字列使用等宽数字，避免数值变化推动相邻内容；年份、版本号和普通行文中的静态数字继续服从当前字体排版。
- 嵌套圆角只有在内外层确实表达包含关系时才保留；需要轮廓平行时，根据外层圆角和两层之间的实际间距确定内层圆角。先用网格、基线和共同容器建立几何关系，再在最终显示比例下检查不对称图标、箭头和形状的视觉重心；少量视觉修正不能破坏共享列、安全区或其它已经成立的对齐。
- 阴影主要表达悬浮、遮挡或材质层次，边框和分隔线主要表达结构、范围和状态。图片或截图边缘只有在与底面混在一起时才增加低对比细线，颜色从当前底面和明暗关系中确定，不套固定黑白值。删除阴影、边框或描边后仍不改变层级和识别时，不为装饰继续叠加。
- 图标按最终渲染尺寸检查，过小而细节粘连时改用更简洁的图形；线宽与相邻文字字重、分隔线和图表线条形成同一套视觉力度。内联 SVG 的普通、悬停、选中和禁用状态优先由 `currentColor` 与透明度驱动，不为每个状态复制素材。只有表示前进、返回、开始或结束等阅读方向的图标随 RTL 翻转，播放、刷新、搜索等自身含义不依赖阅读方向的图标保持原样。
- 手动或混合播放的导航控件以及 `data-editable-interactive` 区域，在成品实际显示尺寸和目标输入方式下应当容易命中，相邻点击区域不得重叠。控件状态变化使用可中断的 CSS transition，并明确列出真正变化的属性；画布内承担语义的运动继续只由统一时间线驱动。高频操作保持即时或只使用短促的颜色、透明度等反馈，不让每次操作等待一段完整表演。
- 不使用 `transition: all`。只有真实浏览器已经观察到首次运动卡顿，而且目标属性确实能由合成层受益时才为相应节点增加 `will-change`；不把它设为全局默认，也不让提示长期残留在已经停止运动的节点上。

所有值得用户手动调整的文字、图片、形状、分组和组件都分配稳定 `data-editable-id`，并在清单中声明唯一 ID、选择器、父分组、默认边界、可改字段和约束。图片数据字段只使用 `kind: "media-source"`；旧的 `kind: "image"` 已不存在。普通数组使用 `kind: "list"`，结构化行数据使用 `kind: "table"`。媒体默认值和场景覆盖值只保存 `media-sources.json` 中的 source id；实际文件路径只保存在包内素材账本，不能同时出现在 `data_fields`、`scene.data` 或 `resources`。入口 HTML 不引用某个编辑器的专用代码；消费者通过 `window.editableMedia` 的 `ready`、`getState`、`setState`、`setVariant`、`setScene`、`setTime`、`getPlayback`、`getCamera`、`getParameters` 和 `getBounds` 工作，通过 `getMediaSources` 与 `getMediaSourceUrl` 读取素材记录和解析后的本地文件。播放控制继续使用同一接口的 `play`、`pause`、`next`、`previous` 和 `setPlaybackMode`。

网页包仍是整体制作真源，其中清单负责声明和默认状态，HTML/CSS 负责结构与渲染算法。编辑器导入后保存的是场景实例覆盖值，不回写原始网页包。修改文案、位置、尺寸、旋转、透明度、层级、显隐、图层关键帧、参数、参数关键帧、主题、输出比例、数据或字段锁时优先改场景状态；新增图层、参数定义、改变父子结构、场景顺序、内容版式合同或动画算法时回到网页包。

品牌变量只映射标准 CSS 自定义属性；参数可选映射自己的 CSS 自定义属性，但不能与主题变量重名。各输出变体用稳定图层 ID 声明边界、显隐和必要的内容变体；表格和图表数据由本地快照驱动；质量规则只声明当前项目真正需要的字号、间距、安全区、内容跨度、导航避让和场景测量。入口 HTML 监听 `editablemediadata`、`editablemediaparameters` 与 `editablemediatime` 事件，把当前场景数据、解析后的参数和时间投影成 DOM 画面；数据、参数、场景和播放状态仍由运行时统一控制。需要形成组件库时添加通用 `component` 元数据，不写入某个编辑器的分类或内部 ID；跨项目复用时再按 `reusable-media-resources.md` 注册整个自包含网页包，而不是复制 HTML 片段或截图。

`delivery.preview` 明确网页通过本地服务还是其它已实现方式打开；`remote_dependencies` 决定能否依赖远程脚本、字体和媒体。承诺本地可用时，入口、运行时、字体和必要素材必须真的由本地资源完成，不能在断网后只剩静态降级。

### 全片视频进度条

需要在教程、案例拆解或工作流视频中持续说明全片位置时，使用 `assets/video-progress-bar/`，不要把 starter 里的单场景进度线当成成片包装。先从已确认脚本、字幕或剪辑结构取得真实总时长和章节毫秒起点，填写 `video-progress-bar-spec.json`，再运行 `node scripts/create-video-progress-bar.mjs --spec <参数.json> --output <新网页包目录>`。生成器会把总时长、章节步骤、默认比例和顶部或底部位置一次性投影进清单与网页入口；输出目录必须不存在，已有成品不会被覆盖。

这个组件是透明覆盖层，不是 B-roll。活动形式固定为一条横向矩形导航栏：首格与全部章节并排占满同一外框，章节宽度按实际持续时间分配，底边连续显示全片进度；当前几何游标只是人物素材暂缺时的占位，以后替换人物仍读取同一 `editablemediatime` 全局坐标。章节跳转只使用同一场景 steps，不能再启动第二个计时器，也不能在浏览器里猜测视频时长。横屏、竖屏和方形变体分别重新排版；棋盘格只用于普通预览，捕获模式的 body、画布和变体背景保持真实透明。章节太多导致标签不可读时先合并内容结构，不通过缩小字号把全部节点硬塞进去。

### 解释型 B-roll 活动包

流程、阶段、层级、因果、工具链、比较、拆解、指标、前后证据和视频布局统一由 `assets/explanatory-broll-templates/` 提供真实 v5 网页实现。十类场景共享同一数据字段和确定性时间入口，但每个场景必须让当前关系的开始、变化和结果直接可见；不能因为共用组件就退化成同一种卡片淡入。三种布局与三种比例来自 manifest variants，人物分屏只声明预留边界，真人素材仍由最终视频时间线提供。目录预览读取同一包；项目编辑通过 MediaFlow Pro 的网页片段数据、主题和 variant 操作保存，不能另建浏览器本地状态真源。

作品身份标记只读取当前项目明确采用的用户身份档案和本次内容归属判断。作者署名、整理说明、制作水印与引用来源是不同信息：制作水印不能代替来源，整理说明不能冒充作者，来源仓库、Skill、模板、赞助者、风格参考和案例中的名称、头像或标记也不能自动进入当前作品。

PNG、WebP、GIF、视频封面、帧序列和从同一网页时间线捕获的无声视频都是网页派生结果。它们继承网页中已经成立的共享视觉核心和对应实现层；实拍或剪辑型视频只在采用这些网页画面时消费其结果，不反向把视频镜头、剪辑或声音写进风格档案。用户反馈内容、颜色、位置或节奏时修改网页，再重新导出。

需要用生成模型制作背景、插图、纹理或产品视觉时，把生成结果作为网页引用的视觉素材，不让它成为标题、数字、来源、按钮标签或其它关键文字的编辑入口。最终必须准确显示的文字继续从网页集中的内容字段排版和渲染；生成图里无法可靠修改、核对或复用的文字不承担信息职责。这样修改文案、语言或尺寸时只需更新网页真源，不需要重新生成整张图片来修正文字。

## 二、静态卡片先确定成品

排版前先确定最终交付是一张图片、一组图片，还是网页本身；确定画布尺寸、条目数量和重复字段。“一张卡片”表示一个完整画布，内部可以有多行条目，不拆成多张独立卡片。最终交付是图片时按固定画布制作，网页只承担编辑与导出，不另外为不同设备设计响应式布局；网页本身也是成品时才处理响应式关系。

成品是社交卡、平台封面、轮播图或以静态卡为基础的短动态图时，同时读取 `social-card-production.md`。使用照片、截图、生成图或视频帧时再读取 `visual-asset-placement.md`，并在项目中保存 `media-sources.json`。多比例版本使用同一清单的不同 `variants` 重新构图，不从一个成品裁出其它比例。

多个条目只是在同一清单中重复字段时，用共享列、分隔线、统一底面和留白把它们组织成一个整体；每项确实需要独立浏览、交互或表达分组边界时，才使用彼此独立的卡片容器。

需要对齐的标题、说明、标签、数值或署名放进同一个网格或弹性容器，再按基线、顶部、底部或中心选择一种明确关系。绝对定位只用于独立装饰或已经确定的叠放，不用它拼出本应共同对齐的一行。

先确定大面积背景、内容区和条目层的明暗、冷暖与面积关系，再选择点色。用户认为某个颜色不协调时，检查的是整张图的色块关系；只替换被点名的色相不能解决浅色与深色区域割裂。字号、行距和信息密度按最终画布的实际观看尺寸调整，标题、条目名、说明、链接和辅助数字形成稳定层级。

固定画布网页把制作尺寸与预览尺寸分开：画布保持逻辑尺寸，预览外壳按缩放后的实际宽高占位；普通浏览器窗口先把整张画布居中适配，空间不足时由预览区滚动；捕获模式恢复原尺寸。这样浏览器预览和最终导出始终读取同一张完整画布。

字号按整张图适配到普通浏览器窗口后的真实显示比例验收，不只看原始像素。逐项检查标题、正文、标签、栏头、署名、链接和指标；保留的文字应当无需额外放大即可读清。用户提供标注截图时，先把每个标注区对应到具体文字或布局角色，再逐区修改和复查。

## 三、从内容关系选择画面

先读取 `content-to-media.md` 形成的媒体文案和制作说明，再决定网页结构：

- 数值随时间变化时使用坐标、条形、面积、计数器或对象尺度变化。
- 静态差异使用并列、叠加、矩阵或分组。
- 空间关系使用示意图或可定位对象。
- 真正存在步骤、方向、交互或路径时才使用节点、连线或流程结构。
- 叙事确实需要多个信息单元时在一个网页中组织场景；GIF 仍优先保留持续可见的标题、对象、坐标或其它上下文锚点。

时间型网页先把语义片段表写入场景计划。每个场景至少确定：

- `page_role`：当前场景负责开场、解释、证据、比较、步骤、数据、引用、总结还是行动提示。
- `content_shape`：当前信息实际是主张与支撑、时间变化、并列比较、关系网络、数据证据还是其它可描述结构。
- `layout_id`：从 `layout_contracts` 中选择能够容纳当前内容的结构；内容超过容量时先删减、重组或拆分场景。
- `duration_ms` 与 `steps`：当前场景需要多少阅读或运动时间，以及手动推进时在哪些语义状态停留。
- `asset_slots`：当前版式实际使用哪些图片、截图或视频帧槽位。

先完成“场景顺序 → 页面职责 → 内容形态 → 内容版式 → 选择理由 → 素材槽位 → 步骤”的计划，再写 HTML。场景数量和版式变化由内容推进决定，不为了显得丰富强制凑页数或轮换结构。开场负责建立问题或结果，中段按证据与解释需要推进，收束保留足够阅读时间。

选择内容版式后才处理图片。每个素材槽位在合同中声明比例、`cover` 或 `contain`、是否必须保留完整画面；场景把槽位绑定到实际 image 数据字段。截图、界面证据和必须完整展示的图使用 `contain`；照片或背景可以使用 `cover`，并按 `visual-asset-placement.md` 保存焦点与裁切。生成图片时使用最终槽位比例和安全区，生成结果只承担视觉素材职责。

每个场景再选择自己的视觉命题和运动结构。持续动作可以在该场景内循环；方向性变化先完成演进，再在结果状态停留或循环；反馈关系保留已经累积的结果；结论保留阅读时间。场景时间线负责进入、局部循环、退出和跨场景转场，局部循环不越过当前场景。旁白或同期声进入下一信息单元后，网页也进入对应场景。

连线、箭头和穿过对象的线条只能表达已经明确的方向、因果、流向、对比或突破关系，并且起点、终点和穿越含义都能被观众读懂。没有这种关系时不用连线做装饰。每个旁白信息单元至少要有一个与句意对应的可观察状态；一句包含多个独立变化时拆成多个步骤，一大段只有标题换字时回到媒体文案或场景计划压缩内容，而不是把它硬做成简陋幻灯片。

运动承担主要表达时，先确定贯穿当前段落或相邻场景的运动载体，再实现局部效果。每个承担推进、因果、转折或兑现的场景都要能回答：开始时对象处于什么状态，哪个动作改变了含义，结果状态怎样被保留，前后场景靠什么承接，文字还需要补充什么。没有可见状态变化的场景只能承担结论、证据阅读或刻意停顿；不能用新的标题、卡片、截图和淡入转场冒充叙事推进。

多个场景可以共享一个持续可见的对象、坐标、底板、人物或空间，让前后关系自然承接；共享锚点只负责连续性，每个场景仍按当前信息选择循环、演进、比较、转场或停留。完整网页时间线只有在首尾语义等价且没有持续推进的旁白或结论时才整体循环。

网页 starter 只提供 v5 清单、可编辑画布、场景播放、共享参数、导航控件和中性示范。当前内容的场景、内容版式、输出变体、参数、图表类型和叙事顺序必须重新判断；风格先继承项目档案或选择适用的内置制作配方，不沿用 starter 或参考图的表面结构。

重复字段构成的项目、工具或资源清单先按 `SKILL.md` 路由读取清单式卡片案例。编辑证据内容需要同时制作静态卡和网页动画时读取跨载体案例，先比较它的共享视觉核心，再分别查看静态场景和时间场景怎样实现同一关系。案例中的主题、条目数量、尺寸、配色、页面坐标和时间点都是当前取值，不替当前内容做决定。

## 四、按层制作样稿

- **风格样稿**：只放少量代表元素，检查字体、线条、颜色、纹理、图标、密度、留白和光影。
- **构图样稿**：放入完整信息骨架，检查标题、主体、来源、安全区、层级和容量，不实现完整动效。
- **动效样稿**：在已确认构图中实现一个代表性场景及步骤，并提供播放、暂停、前后推进和时间定位。

样稿都在同一个网页真源中完成。需要方便查看时可以导出截图，但截图不成为编辑入口。必须在真实浏览器和目标画布尺寸查看网页，确认字体、图标和本地素材真实加载。先运行 `scripts/validate-editable-media.mjs` 检查清单、接口、场景合同、素材槽位、输出变体、播放链路、资源、图层和项目声明的量化规则，再查看它从同一网页捕获的场景截图；脚本通过不能代替人工判断内容和风格。样稿未确认时不批量导出媒体。

动效样稿标明它对应的语义片段、验证的运动类型和适用时间窗口。完整制作沿全量语义片段分别设计其它状态；样稿可以复用配方和组件，但它的短时长和局部时间线不作为全片结构。

动效样稿和完整预览都要做一次脱离逐句文字的运动检查：连续查看开始、关键变化和结果状态，确认观众能够从对象关系与状态演进看出哪里发生了推进。若联系表只呈现若干张标题不同、布局近似的静态页面，回到场景计划重做运动载体和状态变化，不用增加更多淡入、滑入或镜头晃动掩盖问题。

## 五、确定性动画接口

交互演示与导出动画必须能从同一已知状态重复播放：

- 等待字体和必要素材加载后再标记为可捕获。
- 能切换场景与步骤，并能播放、暂停、前后推进和定位到指定时间。
- 捕获模式隐藏按钮、调试信息、鼠标指针和画布外元素。
- 相同时间点产生相同的内容、位置、样式和数值。
- 循环动画自然衔接开始状态；非循环视频保留明确收束帧。
- 片段内循环在循环边界保持当前对象、状态和语义连续；方向性演进完成后保持结果，不跳回未发生前的状态。

每个场景的 `motion.complexity` 明确为 `static`、`simple` 或 `complex`，`driver` 明确为 `none`、`object`、`camera` 或 `mixed`，并用自然语言说明运动怎样帮助当前含义。复杂场景在制作完整过渡前先建立语义关键状态板：至少覆盖经实际内容决定的开始、一个或多个变化和结果状态，必要时再增加保持状态；数量由真实变化决定，不用固定张数或模糊完成百分比。清单中的 `step.review=true` 表示该状态必须由真实运行时定位并审阅，不能由消费端手写一张近似图代替。

镜头只在平移、缩放、视差或焦点变化确实帮助解释空间关系、注意力转移或前后状态时启用。静态场景使用 `driver=none` 与 `camera=null`；仅有对象显隐、数值或位置变化时使用 `object`，不为增加“电影感”套镜头。需要镜头时，`camera.root_layer_id` 和 `depth_layers` 必须指向不可手动编辑的外层包装，真实可编辑对象放在其内层，避免镜头与对象动画争夺同一个 transform。标题、字幕和其它必须持续清楚的 `readability_layer_ids` 放在镜头根之外，不能被景深模糊。镜头关键帧只引用当前场景的语义 step id，因此步骤时间仍是唯一时间边界。

运行时由 `setTime` 同时计算对象和镜头状态，`getCamera` 返回当前可复现的镜头、焦点与景深结果。`scripts/validate-editable-media.mjs` 对复杂场景逐个定位 `review=true` 的状态，两次读取同一时间确认确定性，检查外层镜头真实作用、可读性图层未被污染；指定 `--screenshot` 时还会从同一真实画布生成带 step id 的关键状态图。状态图用来审阅开始、变化和结果，不替代完整播放检查。

依赖悬停、滚动、随机数或不可控加载时间的效果改由主时间线控制；必须使用噪声或粒子时固定随机种子。同一状态不能由多个互不知情的计时器控制。

`setState` 接受清单允许的各场景覆盖值，`setTime` 使用整条时间线的毫秒位置，`setScene` 使用场景 ID 和可选步骤。`ready` 必须等待清单、字体和图片完成；`getPlayback` 返回当前模式、场景、步骤、场景时间和全局时间；`getBounds` 返回清单图层的当前像素边界。相同网页源摘要、场景状态、输出变体和时间必须产生相同画面。

网页的第一个可见包装节点必须唯一标记 `data-editable-media-root`，并声明 `data-composition-id="editable-media"`、`data-no-timeline`、总时长秒数、默认输出变体的宽高和帧率；媒体画布和预览控件都放在这个包装节点内，捕获模式隐藏画布外控件。运行时同时暴露 `window.__hf.duration` 和 `window.__hf.seek(seconds)`：它只是 `window.editableMedia.setTime(milliseconds)` 的秒级逐帧入口，不保存第二份时间线。MediaFlow Pro 自有渲染器与 HyperFrames 直接渲染都从这个入口定位，因此同一秒数必须得到同一场景状态和画面。运行时为 HyperFrames 注册的 timeline adapter 也只转发到这个入口，不能重写动画算法。

手动模式不启动自动时钟，前进和后退依次经过步骤与场景。自动模式连续经过全部场景。混合模式只自动推进当前场景，在场景边界停下。键盘、滚轮和触摸导航不接管输入框、按钮、链接、编辑状态或标记为 `data-editable-interactive` 的交互区域；查询参数能够直接打开指定输出变体、场景、步骤和时间。

## 六、从网页派生媒体

先使用网页已有导出能力；没有时再使用能够读取同一画布和时间线的浏览器截图、逐帧捕获或录制方式。导出工具只负责捕获和编码，不重新实现内容。网页视频只有两条明确路径：需要编辑、声音、混剪或项目续改时交给 MediaFlow Pro；用户明确选择 HyperFrames 的独立无声代码动画按 `hyperframes-rendering.md` 直接渲染。不要同时运行两条路径，也不要在失败后静默换路。

- 静态图在指定时间或静态状态捕获目标画布。
- GIF 按固定帧率采样一个短而完整的循环，减少无意义帧和大面积随机变化。
- 无实拍视频从同一时间线导出无声普通视频或帧序列；需要供剪辑软件叠加的透明动效时，使用 `canvas.background_mode=transparent` 的输出变体，并让背景、HTML body 与媒体画布保持真实透明，再通过当前能力合同声明的透明视频或覆盖层格式导出，不预设容器和编码。旁白、音乐和字幕需要后期装配时，把网页画面交给视频时间线。
- HTML 演示直接使用手动或混合播放；需要变成视频时切换到自动播放并从同一时间线连续捕获，不复制页面内容。

当前环境无法稳定导出目标格式时，保留已经验证的网页真源并说明具体阻断，不另写一套平行绘图程序。

需要时间线混剪、声音、字幕或用户希望在编辑器中手动精调时，读取 `structured-media-editor-cli.md`。独立无声代码动画明确选用 HyperFrames 时读取 `hyperframes-rendering.md`。静态卡片、GIF 和独立网页仍可从网页真源直接导出，不要为了使用某个产品而强制导入。

## 七、完成条件

网页能够按清单声明的交付方式打开，场景数据、视觉变量、内容版式、输出变体和播放状态分别从唯一位置修改；`scripts/validate-editable-media.mjs` 对用户要求的每个“输出变体 × 场景”通过，必需素材槽位真实绑定，手动、自动或混合模式按当前成品工作；目标尺寸没有乱码、替换字体、重叠、裁切、溢出、导航侵入、错误层级或失衡空白；开始、核心转折、结束和每个场景的进入、局部循环、结果停留与退出符合媒体文案。实际导出时继续读取 `review-and-export.md` 检查网页与派生媒体的一致性。
