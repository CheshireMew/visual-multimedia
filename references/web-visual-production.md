# 网页优先的视觉媒体制作

用于实际制作技术图解、数据图表、动态图解、GIF、代码生成动画、可手动推进的多场景 HTML 或无实拍视觉画面。代码生成视觉都保留可预览、可修改的 editable-media v6 网页真源；独立静态卡、社交卡、纯文字卡、轮播图和独立封面不在本文恢复轻量实现。

制作带个人身份标记的网页视觉时读取 `assets/creator-identity/identity.json`，先根据可靠内容依据选择且只选择一个角色：确认原创使用头像与作者署名；确认由本人筛选、核对或整理使用明确的“整理”贡献说明，可带头像；普通非原创或来源不明只使用半透明制作水印，不带头像，也不暗示作者或来源。当前请求提供另一套身份、归因或明确要求不加标记时服从本次要求。身份资源不是创作者工作、生活或教学素材库；需要这类复用素材时从用户指定的注册 `creator-media` 库显式采用。来源项目、赞助者、Skill 元数据、风格参考和案例作者只证明来源或示范结构，不成为当前作品作者。

`assets/web-card-cases/catalog.json` 保存真实制作证据，不是模板选择器。只为技术取证时，先读目录项的 `transferable_mechanisms`、`current_project_decisions` 和 `verify`；目录信息不足时，只局部读取清单中的内容版式、容量、质量规则或对应 QA，不读取完整预览、网页、风格档案、案例坐标、案例数据和身份字段来决定当前画面。当前项目已经明确采用某个案例的视觉语言时，才读取采用层需要的视觉文件，并把案例 id、采用层和被替换的活动风格范围写入决定。题材、字段或内容类型相似，以及“看看、参考、分析、借鉴、比较”，都不构成视觉采用。

## 一、先选择与成品相称的网页真源

受支持的技术图解、图表、网页动画和多场景视觉统一建立 editable-media v6 网页包。观众可见文字、数据、画布、颜色、字体和时间状态分别保存在合同规定的唯一位置；本地图片或字体由素材账本和清单引用。固定画布按输出变体渲染，只有用户要求网页本身响应式时才另行实现响应式布局。

出现以下任一真实需求时才进入结构化网页：多场景或动画；结构化浏览器编辑；多个比例需要统一管理；MediaFlow Pro 或 HyperFrames；浏览器媒体与原生视频或音频共同工作；跨项目注册复用的完整网页组件。用户明确要求 React，或已有活动真源就是 React 工程时也进入结构化网页。“网页卡”“完整”“详细”“可编辑”本身不构成进入条件。

结构化网页中，用户明确要求 React 或现有真源为 React 时复制 `assets/react-media-starter/`，其它情况复制 `assets/web-media-starter/`。明确采用已登记布局时才从 `assets/web-layout-templates/catalog.json` 解析并实例化；模板只提供结构和容量，不决定颜色、字体、尺寸或当前文案。DOM 网页包或 React 源码是活动真源，构建产物不成为第二个编辑入口。

结构化入口最终交付由本地 HTTP 服务预览的自包含 editable-media v6 网页包。交付包由清单、网页入口、运行时、media-sources v4 素材账本和全部引用文件组成；引用必须落在包目录内。普通静态 HTML 不受本段合同约束。

先使用作图前确认中已经选定的字体、颜色、结构和表面方向。结构化或系列项目已有风格档案时读取共享视觉核心和适用实现层。不能只在说明文字或档案中写了配方，网页却使用另一套颜色、材质、构图或动作。

网页画面最终会与固定人物窗、讲解者窗口或其它持续覆盖层合成时，先把确认后的覆盖矩形作为当前输出变体的排除区域，再安排标题、关键界面、证据、字幕带和交互提示；所有受影响场景共同遵守，不等成片装配后再靠缩小人物或整体推偏补救。网页能够修改时由网页主动重新构图；真实截图或录屏属于不可改写证据时保持其内容完整，再由最终视频时间线选择覆盖层位置、局部放大或其它不改变证据的处理。

## 二、结构化网页合同

以下合同只适用于已经进入 editable-media v6 的项目。`schemas/editable-media.v6.schema.json` 是唯一结构合同，`scripts/editable-media-contract.mjs` 负责执行它和包边界；校验器、本地渲染器、HyperFrames 工作副本和 MediaFlow Pro 消费端都只能读取这份合同。`editable-media.json` 是当前网页包的权威配置，网页入口负责结构、样式关系和确定性动画算法，不保存另一份场景、尺寸、主题、参数或默认文案。清单中的职责固定为：

- `scenes` 保存有序语义场景；每个场景声明页面职责、内容形态、内容版式、时长、语义步骤、`motion`、数据覆盖和素材槽位绑定。每个步骤都要说明它是开始、变化、结果还是保持状态，是否进入关键状态审阅，以及该状态实际表达什么。
- `playback` 保存 `manual`、`autoplay` 或 `hybrid` 播放方式、帧率、循环和导航能力。手动表示由用户推进；自动表示时钟连续推进；混合表示场景内自动运动、场景边界等待用户。
- `layout_contracts` 保存内容版式的适用页面职责、内容形态、容量、必需字段、必需图层和素材槽位。它回答当前内容应该采用什么结构。
- `variants` 保存方形、竖版、横版等输出比例的画布和局部图层覆盖。没有覆盖的字段继承图层 `default_bounds`；`visible`、字号、透明度和层级与位置尺寸一样属于正式变体字段。
- `parameters` 保存不自然归属于单个图层、但需要由制作端或编辑器调整的共享控制量。每项必须声明稳定 ID、类型、全局或场景作用域、默认值、是否可动画、单位、控件、可选 CSS 变量和数值或选项约束；场景只覆盖 `scope: "scene"` 的参数。
- `data_fields`、`theme_variables`、`resources`、`quality`、`production` 和 `delivery` 分别保存内容默认值、视觉变量、非媒体运行资源、量化验收、来源版本关联和交付方式；场景只写变化的数据，缺省值继承 `data_fields.default`。`media_sources` 唯一指向包内 media-sources v4 素材账本，每个 source 必须明确声明 `browser`、`native-underlay` 或 `native-audio` 管线。

独立素材使用 `scripts/import-media-asset.mjs` 导入当前网页包，并明确传入 `--pipeline`。图片、截图、图标、生成图、需要由 DOM 作为画面元素绘制的视频使用 `browser`；作为网页透明层下方原生视频轨合成的视频使用 `native-underlay`，同时声明 `--fit`、`--playback`、`--audio`、`--source-in-ms` 和 `--gain-db`；独立原生音轨使用 `native-audio`，同时声明 `--loop`、`--source-in-ms` 和 `--gain-db`。导入器读取已有素材账本版本，普通 media-sources v3 工程不能传网页管线，media-sources v4 网页素材账本不能缺少管线；代理只继承原片管线，不能改绑。

入账不等于采用。`browser` 素材由 `media-source` 数据字段及场景素材槽位采用；`native-underlay` 和 `native-audio` 也必须各自由一个 `media-source` 数据字段的默认值或场景数据指向 source id，MediaFlow Pro 才会建立原生片段计划。原生 source 不能绑定到浏览器图片槽位。使用 `native-underlay` 时，输出变体的 `canvas.background_mode` 必须是 `transparent`，背景色使用透明色，HTML 的 body 与媒体画布也必须真正透明；需要显示在原生视频之上的文字、图形和控件继续由网页绘制。

查询参数 `variant=<id>` 选择输出比例，`scene=<id>` 与可选的 `step=<id>` 选择场景状态，`time=<ms>` 表示所选场景内的时间。内容版式和输出比例是两个判断，不共用一个字段。

同一信息只保留一个可编辑位置：

1. 标题、正文、标签、数值、来源和状态数据集中保存；场景只覆盖当前信息单元实际变化的字段。观众能读到的元信息、页码、按钮、微文案和 SVG 文字同样来自这些数据字段。CSS 伪元素只绘制无文字装饰；需要阅读的 `content` 改成绑定数据的真实 DOM 或 SVG 文字层，不能把案例词句硬编码在 HTML、CSS 或脚本里。
2. 颜色、字体、字号、线宽、圆角、阴影、间距和背景集中为视觉变量，并与项目风格档案中的实际规则一致。
3. 对象位置、分组、层级和安全区由网页结构负责。
4. 场景与步骤组成一个主时间线，播放、暂停、前进、后退和定位使用同一状态更新逻辑。
5. 回弹强度、错峰间隔、轨道半径、镜头幅度、阈值等共享算法控制量集中为类型化参数；不要把它们藏在 DOM 属性、全局变量或某个编辑器专用状态里。
6. 输出比例、像素尺寸、场景时长、帧率、循环和背景集中配置。

项目已经把 `style-profile.json` 作为正式资源写入网页包、并在 `theme_variables` 锁定颜色与字体后，`scripts/validate-editable-media.mjs` 会在每个实际输出变体和场景中检查当前可见画布、声明图层及其真实子元素。只有实际生效、且使用了未登记颜色或字体的 CSS 或 SVG 声明才产生 `Q12` 提醒；检查读取 CSSOM 和浏览器解析值，不扫描整份 HTML，也不按颜色数量设通过阈值。提醒保留来源样式表、选择器、属性、声明值、实际值和受影响图层，并写入 JSON 报告的 `visual_variable_drift`；它不改变校验退出码，也不自动改写页面。确认是项目视觉语言的一部分时，把该值收口为有明确职责的主题变量并让页面消费；确认只是临场值时，改用已有变量。不要为了消除提醒批量近似替色或调用模型重做视觉。

可编辑状态与动画状态必须在同一字段上只有一个控制者。通用编辑运行时需要改写某个图层的位置、旋转或透明度，而主时间线也需要持续改变这些字段时，使用“可编辑外层 + 动画内层”，或者让编辑覆盖值进入主时间线计算；运行时和动画不能在同一个节点上轮流覆盖同一属性。定位到任意时间后，编辑状态、动画状态和捕获画面应同时成立。

承担阅读的卡片、面板、坐标系和标题区默认保持稳定，动画作用于其中真正发生变化的数值、对象、比较状态、强调范围或关系。只有容器自身的移动、拆分、合并确实表达语义时才移动容器；不能用整张卡片持续漂浮、缩放或摇晃掩盖内部没有变化。持续可读文字与装饰运动分层，文字内层不继承装饰外层的旋转、镜像、透视或路径变换，避免圆内文字倒置、流程标签倾斜和动画结束后排版失真。

### 在最终显示尺寸完成界面细修

先让内容版式、风格档案、字体和素材在目标输出变体中真实成立，再处理下面的细节；它们只改善已经选定的视觉关系，不重新选择风格或把媒体制作扩张成应用界面设计。

- 字体加载且最终宽度确定后查看真实换行。标题出现突兀短行或孤字时，可以使用 `text-wrap: balance`；正文、说明和图注只有在 `text-wrap: pretty` 确实改善行尾、又没有破坏版式容量时才使用。动态计数、时间、价格、指标和需要纵向比较的数字列使用等宽数字，避免数值变化推动相邻内容；年份、版本号和普通行文中的静态数字继续服从当前字体排版。
- 用户明确要求标题保持单行、指定分行或逐字排版时，把它作为当前构图条件：先调整标题区宽度、字号尺度和周围元素，再检查目标比例与缩略图；自动均衡换行只处理没有明确分行要求的文字。
- 嵌套圆角只有在内外层确实表达包含关系时才保留；需要轮廓平行时，根据外层圆角和两层之间的实际间距确定内层圆角。先用网格、基线和共同容器建立几何关系，再在最终显示比例下检查不对称图标、箭头和形状的视觉重心；少量视觉修正不能破坏共享列、安全区或其它已经成立的对齐。
- 文字放在节点、徽章、圆形、多边形或其它可见容器内时，为文字和承载形状保留可定位的稳定元素。等待字体加载后，在目标输出变体中读取两者实际渲染边界；SVG 非矩形使用可见图形的几何边界并换算到画布坐标，再比较文字块与承载形状的中心。先完成几何居中，再按最终尺寸和缩略图做少量视觉修正。清单边界与 CSS 坐标彼此一致只证明编辑合同一致，不能证明文字相对承载形状已经居中。
- 文字与竖线、边框、色条、图标或其它相邻装饰分别读取真实边界，并在最终显示尺寸检查可见像素间距。父容器存在 `gap`、`padding` 或网格列不能证明实际笔画已经分开；视觉上贴碰时直接调整对应间距，不通过移动整组内容制造新的对齐偏差。
- 阴影主要表达悬浮、遮挡或材质层次，边框和分隔线主要表达结构、范围和状态。图片或截图边缘只有在与底面混在一起时才增加低对比细线，颜色从当前底面和明暗关系中确定，不套固定黑白值。删除阴影、边框或描边后仍不改变层级和识别时，不为装饰继续叠加。
- 图标按最终渲染尺寸检查，过小而细节粘连时改用更简洁的图形；线宽与相邻文字字重、分隔线和图表线条形成同一套视觉力度。内联 SVG 的普通、悬停、选中和禁用状态优先由 `currentColor` 与透明度驱动，不为每个状态复制素材。只有表示前进、返回、开始或结束等阅读方向的图标随 RTL 翻转，播放、刷新、搜索等自身含义不依赖阅读方向的图标保持原样。
- 手动或混合播放的导航控件以及 `data-editable-interactive` 区域，在成品实际显示尺寸和目标输入方式下应当容易命中，相邻点击区域不得重叠。控件状态变化使用可中断的 CSS transition，并明确列出真正变化的属性；画布内承担语义的运动继续只由统一时间线驱动。高频操作保持即时或只使用短促的颜色、透明度等反馈，不让每次操作等待一段完整表演。
- 不使用 `transition: all`。只有真实浏览器已经观察到首次运动卡顿，而且目标属性确实能由合成层受益时才为相应节点增加 `will-change`；不把它设为全局默认，也不让提示长期残留在已经停止运动的节点上。

所有值得用户手动调整的文字、图片、形状、分组和组件都分配稳定 `data-editable-id`，并在清单中声明唯一 ID、选择器、父分组、默认边界、可改字段和约束。图片数据字段只使用 `kind: "media-source"`；旧的 `kind: "image"` 已不存在。普通数组使用 `kind: "list"`，结构化行数据使用 `kind: "table"`。媒体默认值和场景覆盖值只保存 `media-sources.json` 中的 source id；实际文件路径只保存在包内素材账本，不能同时出现在 `data_fields`、`scene.data` 或 `resources`。网页入口实现不引用某个编辑器的专用代码；消费者通过 `window.editableMedia` 的 `ready`、`getState`、`setState`、`setVariant`、`setScene`、`setTime`、`getPlayback`、`getCamera`、`getParameters` 和 `getBounds` 工作，通过 `getMediaSources` 与 `getMediaSourceUrl` 读取素材记录和解析后的本地文件。播放控制继续使用同一接口的 `play`、`pause`、`next`、`previous` 和 `setPlaybackMode`。

活动网页项目仍是整体制作真源，其中清单负责声明和默认状态，当前入口的 HTML/CSS/JavaScript 或 React/TypeScript 源码负责结构与渲染算法。编辑器导入后保存的是场景实例覆盖值，不回写原始网页项目。修改文案、位置、尺寸、旋转、透明度、层级、显隐、图层关键帧、参数、参数关键帧、主题、输出比例、数据或字段锁时优先改场景状态；新增图层、参数定义、改变父子结构、场景顺序、内容版式合同或动画算法时回到活动网页项目。

品牌变量只映射标准 CSS 自定义属性；参数可选映射自己的 CSS 自定义属性，但不能与主题变量重名。各输出变体用稳定图层 ID 声明边界、显隐和必要的内容变体；表格和图表数据由本地快照驱动；质量规则只声明当前项目真正需要的字号、间距、安全区、内容跨度、导航避让和场景测量。网页入口实现监听 `editablemediadata`、`editablemediaparameters` 与 `editablemediatime` 事件，把当前场景数据、解析后的参数和时间投影成画面；数据、参数、场景和播放状态仍由运行时统一控制。需要形成组件库时添加通用 `component` 元数据，不写入某个编辑器的分类或内部 ID；跨项目复用时把整个自包含网页包注册为不可变资源，而不是复制 HTML 片段或截图。

`delivery.preview` 明确网页通过本地服务还是其它已实现方式打开；`remote_dependencies` 决定能否依赖远程脚本、字体和媒体。承诺本地可用时，入口、运行时、字体和必要素材必须真的由本地资源完成，不能在断网后只剩静态降级。

### 全片视频进度条

进度条是数据表达，不是装饰。只有当前内容确实存在有限总量、真实当前位置或完成度，并且观众需要持续看到这项关系时才使用；当前值和总量必须来自活动时间线、步骤或数据真源。没有这些条件时，不在网页底部、卡片边缘或场景之间加入随时间填充的彩色细条、轨道、百分比或其它看起来像进度条的元素，也不在多个场景反复使用这种装饰。普通分隔线、边框和下划线可以承担版式职责，但不能无依据地按时间填充或暗示完成进度。

教程、案例拆解或工作流视频已经确认需要持续说明全片位置时，使用 `assets/video-progress-bar/`，不要把 starter 里的单场景进度线当成成片包装。先从已确认脚本、字幕或剪辑结构取得真实总时长和章节毫秒起点，填写 `video-progress-bar-spec.json`，再运行 `node scripts/create-video-progress-bar.mjs --spec <参数.json> --output <新网页包目录>`。生成器会把总时长、章节步骤、默认比例和顶部或底部位置一次性投影进清单与网页入口；输出目录必须不存在，已有成品不会被覆盖。

这个组件是透明覆盖层，不是 B-roll。活动形式固定为一条横向矩形导航栏：首格与全部章节并排占满同一外框，章节宽度按实际持续时间分配，底边连续显示全片进度；当前几何游标只是人物素材暂缺时的占位，以后替换人物仍读取同一 `editablemediatime` 全局坐标。章节跳转只使用同一场景 steps，不能再启动第二个计时器，也不能在浏览器里猜测视频时长。横屏、竖屏和方形变体分别重新排版；棋盘格只用于普通预览，捕获模式的 body、画布和变体背景保持真实透明。章节太多导致标签不可读时先合并内容结构，不通过缩小字号把全部节点硬塞进去。

### 解释型 B-roll 活动包

流程、阶段、层级、因果、工具链、比较、拆解、指标、前后证据和视频布局统一由 `assets/explanatory-broll-templates/` 提供真实 editable-media v6 网页实现。十类场景共享同一数据字段和确定性时间入口，但每个场景必须让当前关系的开始、变化和结果直接可见；不能因为共用组件就退化成同一种卡片淡入。三种布局与三种比例来自 manifest variants，人物分屏只声明预留边界，真人素材仍由最终视频时间线提供。目录预览读取同一包；项目编辑通过 MediaFlow Pro 的网页片段数据、主题和 variant 操作保存，不能另建浏览器本地状态真源。

作品身份标记只读取当前项目明确采用的用户身份档案和本次内容归属判断。作者署名、整理说明、制作水印与引用来源是不同信息：制作水印不能代替来源，整理说明不能冒充作者，来源仓库、Skill、模板、赞助者、风格参考和案例中的名称、头像或标记也不能自动进入当前作品。

PNG、WebP、GIF、视频封面、帧序列和从同一网页时间线捕获的无声视频都是网页派生结果。它们继承网页中已经成立的共享视觉核心和对应实现层；实拍或剪辑型视频只在采用这些网页画面时消费其结果，不反向把视频镜头、剪辑或声音写进风格档案。用户反馈内容、颜色、位置或节奏时修改网页，再重新导出。

需要用生成模型制作背景、插图、纹理或产品视觉时，把生成结果作为网页引用的视觉素材，不让它成为标题、数字、来源、按钮标签或其它关键文字的编辑入口。最终必须准确显示的文字继续从网页集中的内容字段排版和渲染；生成图里无法可靠修改、核对或复用的文字不承担信息职责。这样修改文案、语言或尺寸时只需更新网页真源，不需要重新生成整张图片来修正文字。

## 三、实现结构化网页的画布与变体

技术图解、图表、网页动画和多场景视觉的内容容量、画布比例、修改重排和缩略图验收由 editable-media v6 清单统一声明。固定逻辑画布不随浏览器窗口重排；不同输出比例使用不同 `variants`，网页本身也是用户要求的响应式成品时才另建响应式布局。

确认后的文字写入清单数据字段和场景覆盖，画布宽高与分区顺序由变体和场景声明，并在 `quality` 中保存图层边界、内容跨度和缩略图代表文字；这些值不再复制到 `style-profile.json`。

使用照片、截图、生成图或视频帧时，为当前画布实现已确认的素材槽位、主体、文字安全区、截图完整性和裁切规则，并保存 `media-sources.json`。多比例统一管理时使用清单的不同 `variants`，不从一个成品裁出其它比例。

多个条目共享字段时，用共享列、分隔线、统一底面和留白把它们组织成一个整体；每项确实需要独立浏览、交互或表达分组边界时，才使用彼此独立的卡片容器。

需要对齐的标题、说明、标签、数值或署名放进同一个网格或弹性容器，再按基线、顶部、底部或中心选择一种明确关系。绝对定位只用于独立装饰或已经确定的叠放，不用它拼出本应共同对齐的一行。

先从当前已经确定的视觉来源取得色彩职责，再确定大面积背景、内容区和条目层的明暗、冷暖与面积关系，最后选择实际点色。未被当前项目采用的仓库旧图、相邻成品和案例预览不参与取色。用户认为某个颜色不协调时，检查的是整张图的色块关系；只替换被点名的色相不能解决浅色与深色区域割裂。字号、行距和信息密度按最终画布的实际观看尺寸调整，标题、条目名、说明、链接和辅助数字形成稳定层级。

固定画布网页把制作尺寸与预览尺寸分开：画布保持逻辑尺寸，预览外壳按缩放后的实际宽高占位；普通浏览器窗口先把整张画布居中适配，空间不足时由预览区滚动；捕获模式恢复原尺寸。这种预览缩放不是响应式布局，不得改变画布内部的分区、换行和相对位置。

字号按整张图适配到普通浏览器窗口后的真实显示比例验收，不只看原始像素。逐项检查标题、正文、标签、栏头、署名、链接和指标；保留的文字应当无需额外放大即可读清。用户提供标注截图时，先把每个标注区对应到具体文字或布局角色，再逐区修改和复查。

完成本文件中的网页真源、清单合同、画布与变体后，才能进入当前任务需要的叙事、动画和派生媒体制作。
