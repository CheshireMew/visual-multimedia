# 已有素材的视频后期制作

用于剪辑用户已经提供的讲课、访谈、实拍、录屏和混合视频。它从现有素材开始，不规划拍摄、器材、场景、人员或拍摄日程。

## 一、确认输入与交付

先确认目标受众、成片用途、媒体文案、目标比例、时长、字幕语言、现有素材、必须保留内容和输出位置。旁白承担主要解释时，还要确认听众只听声音能否知道正在讲什么、它为什么发生以及最后要说明什么。用户只要求剪辑建议或分镜时不处理文件；用户要求成片时才建立编辑项目。

检查每份素材的实际时长、分辨率、帧率、音轨、采样率、旋转信息、时间码和可读性。转写稿、字幕和文件名可以辅助定位，最终剪切点必须回到真实媒体核对。素材缺失、损坏或关键语句无法确认时明确阻断，不估算画面或声音。

输入包含多份图片、录音、实拍或录屏时，按 `media-project-contracts.md` 建立唯一的 `media-sources.json`，并在制作说明或编辑项目中维护采用与未采用判断。每份素材记录实际内容、适合承担的画面或声音职责、用户是否要求保留、采用范围，以及未采用的具体原因。用户点名必须使用的素材和使内容主张成立的关键证据，在进入时间线前标为必用；它们必须以 source id 实际出现在时间线中，或者在继续制作前向用户说明无法使用的原因。原始素材保持只读，代理文件和工作副本继续引用清单中的原始来源。

长视频、访谈、课程、录屏或音频素材需要选取真实区间时建立 `clip-selections.json`。片段数量只设 `maximum_clips` 上限，不设必须凑满的目标数；运行 `scripts/validate-clip-selections.mjs` 检查真实源时长、重复文件与时间段、重复转录文本和完整语义审核。自动标点、字幕时间和转写稿只能提出候选边界，人物表达必须实际听过开头和结尾才能标记通过。

## 二、视频时间线是真源

建立一个活动视频时间线，统一保存：

- 源素材引用、选择范围和同步关系。
- 画面顺序、剪切点、速度和必要转场。
- 同期声、旁白、音乐、环境声和静音。
- 字幕、标题、图形覆盖层和安全区。
- 比例、分辨率、帧率、色彩和导出设置。

剪辑修改回到时间线完成。代理文件、预览文件和最终导出不能替代原素材与项目时间线；`media-sources.json` 也不保存一份镜头顺序。需要代码生成图表、标题版式、数据动画或其它图形时，先按 `web-visual-production.md` 建立网页真源。时间线编辑器通过自描述能力声明支持结构化网页包时，直接导入网页包并保存片段覆盖值；不支持时才把网页派生媒体放入时间线。不要在视频项目里重画同一内容。

## 三、按真实声音建立语义时间线

旁白、同期讲解或访谈承担叙事推进时，先把完整声音按语义拆成片段。每段记录当前信息、声音范围、画面职责、进入和退出方式、运动类型与时长来源。听众只听声音就应能理解对象、机制和结论；画面负责把空间关系、状态变化、数量、证据或情绪变得直观，而不是替一段信息不足的旁白补课。

录音或合成语音生成后，以实际声音文件的时长和停顿更新语义片段，再建立画面时间线。一个片段需要持续运动时，只循环当前片段内部与当前含义一致的周期动作；反馈关系使用保留累积状态的局部循环。随机逐渐同步、数值累积或状态形成等有方向的变化先完成一次演化，再保持结果或进入不抹掉结果的局部循环。不能为了填满旁白，把已经包含开头、转折和结论的整条视频从头重播。

使用合成旁白时读取 `speech-synthesis.md`，保存确认文案、合成输入、原始音频、时间标记、供应方式和参数。真实音频决定时间线；字幕时间可以辅助定位，不能取代试听和波形核对。用户给定固定时长时，先调整信息密度和文案，只在不影响自然度和理解的范围内微调语速。

## 四、从内容建立剪辑

先完成粗剪：保留使主张、故事或演示成立的最小完整段落，移除无信息重复、明显失误和不影响语义的空白。人物表达从完整语义开始并在完整语义结束，不能因为预定时长从半句话切入或截掉尾句。停顿、反应和环境信息能够增加理解或情绪时保留，不以最快节奏为默认目标。

再完成精剪：

1. 每个镜头或段落都新增信息、情绪、证据或必要呼吸。
2. 转场服务时间、空间、因果或语气变化；直接切换能够清楚表达时不添加效果。
3. B-roll、图形和字幕补足口播难以呈现的信息，不逐句装饰。
4. 开头建立问题或情境，核心转折在受众仍保持问题意识时出现，结尾给出明确收束。
5. 需要多平台比例时，只制作用户点名的版本；不同构图必须回到同一时间线或明确的派生序列。

## 五、字幕与声音

字幕从最终语音和时间线生成或校正，保留专有名词、数字、语气和说话人信息。逐字字幕造成阅读负担时可以按语义压缩，但不能改变结论或删除关键条件。先处理字幕与脸、手势、产品关键部位、原视频字幕和其它画面内容的碰撞，再按当前目标平台和发布日期检查界面覆盖风险；平台安全区不是一个能够替代画面检查的固定矩形。

双语或学习视频确有需要时，可以把字幕拆成原语言主句、自然译文和必要注释三个职责层。来源、许可、说话人或课程信息默认留在素材账本和交付说明，不因已有三层就继续堆到画面上。字号、位置和行数按当前画布与手机实际显示检查，不继承其它项目的固定坐标。

优先保证人声可懂、音画同步和段落间响度稳定，再处理降噪、均衡、压缩、音乐和空间效果。无法从严重削波、混响或缺失录音中可靠恢复的信息要明确说明。音乐和素材只在获得使用权时加入，不能用音乐掩盖结构问题或难懂口播。

## 六、样稿与导出

用户只要剪辑样稿时，选择一个能代表某个语义片段的节奏、字幕、画面覆盖层和声音处理的短段落，不提前完成全片。样稿只确认该层方向，不定义整片的信息量、总时长或全部运动结构；确认后沿完整媒体文案和语义片段图扩展。

实际导出时按 `media-project-contracts.md` 建立 `media-delivery.json`。内容迭代使用 `preview`，内部审阅和常规交付前检查使用 `review`，正式交付使用 `final`；档位只改变检查成本与证据范围，不改变活动时间线和已经确认的内容。所有尺寸、帧率、时长、响度、静音和黑场阈值来自当前项目，不从其它案例继承。

导出前检查开头、核心转折、字幕密集段、音画同步点和结尾；导出后使用真实播放器读取文件，并运行 `scripts/verify-media-delivery.py` 检查编码、尺寸、帧率、时长、音轨、字幕、采用素材和实际可播放性。正式交付增加 `--require-delivery-ready`，要求技术检查、人工完整审看和权利复核分别通过。交付编辑项目或时间线、必要网页视觉源、成片、联系表和交付报告后停止。

交付前回到活动素材清单逐项核对：必用素材在最终时间线和导出成片中能够找到，未采用素材有与当前内容和质量要求一致的原因，不能用时间线占位符、文件名或消费端手写记录冒充素材已经进入成片。
