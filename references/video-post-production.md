# 已有素材的视频后期制作

用于剪辑用户已经提供的讲课、访谈、实拍、录屏和混合视频。它从现有素材开始，不规划拍摄、器材、场景、人员或拍摄日程。

## 一、确认输入与交付

先确认目标受众、成片用途、媒体文案、目标比例、时长、字幕语言、现有素材、必须保留内容和输出位置。旁白承担主要解释时，还要确认听众只听声音能否知道正在讲什么、它为什么发生以及最后要说明什么。用户只要求剪辑建议或分镜时不处理文件；用户要求成片时才建立编辑项目。

检查每份素材的实际时长、分辨率、帧率、音轨、采样率、旋转信息、时间码和可读性。转写稿、字幕和文件名可以辅助定位，最终剪切点必须回到真实媒体核对。素材缺失、损坏或关键语句无法确认时明确阻断，不估算画面或声音。

输入包含多份图片、录音、实拍或录屏时，按 `media-project-contracts.md` 建立唯一的 `media-sources.json`，并在制作说明或编辑项目中维护采用与未采用判断。每份素材记录实际内容、适合承担的画面或声音职责、用户是否要求保留、采用范围，以及未采用的具体原因。用户点名必须使用的素材和使内容主张成立的关键证据，在进入时间线前标为必用；它们必须以 source id 实际出现在时间线中，或者在继续制作前向用户说明无法使用的原因。原始素材保持只读；代理由账本中的原片关系生成并通过等价检查，编辑器统一从同一账本解析代理或原片，不能自己维护第二份映射。正式成片始终回到原片。

长视频、访谈、课程、录屏或音频素材需要选取真实区间时，先建立绑定原片和输入哈希的 `transcript.json`，实际听音处理专有名词、数字和不确定词，再建立 `clip-selections.json`。片段数量只设 `maximum_clips` 上限，不设必须凑满的目标数；人物表达片段引用已复核的转写 segment id，不在选段合同中手写第二份逐字稿。运行 `scripts/validate-clip-selections.mjs` 检查原片、真实时长、重复文件与时间段、重复表达、转写覆盖和完整语义审核。自动标点、字幕时间和 ASR 句界只能提出候选边界，人物表达必须实际听过开头和结尾才能标记通过。

实际建立或修改复杂时间线前，先确认当前执行入口能结构化读取素材引用、轨道和片段范围，并把修改保存回同一活动真源。本地制作使用 `media-timeline` v1；选择 MediaFlow Pro 后使用它的工程修订。满足这些条件才执行批量剪切、多轨同步、字幕装配或全片重排。入口只能显示画面并点击坐标时，只用于播放检查、定位和一个边界明确且可撤销的操作；其余工作交付剪辑计划与可导入素材，等结构化入口可用后继续。用户只要操作说明时可以给出步骤，但不能把看见界面当成已经读懂或改完时间线。

## 二、视频时间线是真源

建立一个活动视频时间线，统一保存：

- 源素材引用、选择范围和同步关系。
- 画面顺序、剪切点、速度和必要转场。
- 同期声、旁白、音乐、环境声和静音。
- 字幕、标题、图形覆盖层和安全区。
- 比例、分辨率、帧率、色彩和导出设置。

剪辑修改回到时间线完成。代理文件、预览文件和最终导出不能替代原素材与活动时间线；`media-sources.json` 也不保存一份镜头顺序。先用 `schemas/media-timeline.v1.schema.json` 建立产品无关的可编辑时间线。MediaFlow Pro 的原生导入与导出能力就绪时，默认把它导入空工程；导入成功后 `project.mfp` 成为唯一时间线，后续修改与最终导出都回写该工程，不能长期并行维护两条真源。没有可用 MediaFlow Pro 时，portable timeline 继续由 `scripts/media-timeline.mjs` 本地渲染。需要代码生成图表、标题版式、数据动画或其它图形时，先按 `web-visual-production.md` 建立 v5 网页真源，再由选定时间线采用。带声音、字幕或其它轨道的项目不走 HyperFrames 直接渲染，也不在视频项目里重画同一内容。

已经完成内容筛选，并且成片明确需要“必要背景—采访原声证据—紧接解释—独立总结”时，读取 `interview-explainer-production.md` 并采用其版本化 profile。它只是本 reference 之上的一种可选装配类型；普通访谈剪辑、原声集锦、人物故事、录屏和其它混合视频继续由当前时间线决定结构，不能自动套用该顺序。

当前项目存在 v2 `video-direction-plan.json` 时，时间线读取 `segment_id`、来源引用、内容目的、`visual_plan` 和外部生成 job id。真人、录屏与现有证据使用其中的正式 source id；外部生成任务只有在 `generation-jobs.json` 写回 `imported_source_id` 后才成为候选素材，不能直接采用远程地址、任务 id 或占位记录。解释型 B-roll 与包装画面只消费生产者生成的 shot-recipe selection；真实声音、原片或现有视频时间线形成后，把当前导演计划和实际时间源的文件哈希投影为段落起止帧，再加入当前活动时间线。投影只负责接线，实际轨道仍是唯一可编辑时间真源。

## 三、按真实声音建立语义时间线

旁白、同期讲解或访谈承担叙事推进时，先按实际声音拆成连续语义片段。听众只听声音就应能理解对象、关系和结论；画面负责让动作、界面状态、证据或情绪变得直观，不替信息不足的旁白补课。使用合成旁白时读取 `speech-synthesis.md`；真实音频决定时间，字幕只能辅助定位。

实际剪辑前建立一份可读的语义剪辑表。它是活动视频时间线的规划视图，不是第二条时间线；每段写明：声音范围和需要踩准的词或事件、画面要证明什么、采用的 source id 与真实区间或定格帧、播放还是定格、开始与结束条件、是否已经使用过，以及是否存在需要处理的构图跳变。时间线落实后以真实片段和切点为准，表随之更新。

需要踩词时回到真实音频试听和波形定位，让“跑图、施法、换装、第一张、第二张、完成、失败”等词落在对应动作或状态上。视觉事件有先后时说明词应落在动作开始、完成还是完成后的停顿，不能只让整句大致对上一段画面。没有可靠逐字时间时实际听取边界，不按字数平均分配。

从全部素材中寻找最能承担当前职责的区间，不把录制顺序当成剪辑顺序。素材播放与定格按含义选择：展示操作、动作过程或状态变化时播放完成这件事所需的连续区间；解释一个已经出现的界面、设定图或结果时，动作完成后停在信息最清楚且鼠标不遮挡的画面，直到下一项操作开始。不能让无关鼠标移动、页面漂移或已经结束的动作继续播放，也不能因为允许定格就把需要演示的部分全部换成静止画面。

默认不靠循环、重复素材、重复结果镜头、慢放或反复播放同一动作补时。回顾、对照或结构性复现确实需要旧画面时，必须在当前段提供新的理解价值并在语义剪辑表中说明；用户明确允许的复用可以采用，但不能因此重复整段。素材确实不足时报告缺口，不把重复伪装成新画面。

## 四、从内容建立剪辑

先完成粗剪：保留使主张、故事或演示成立的最小完整段落，移除无信息重复、明显失误和不影响语义的空白。人物表达从完整语义开始并在完整语义结束，不能因为预定时长从半句话切入或截掉尾句。停顿、反应和环境信息能够增加理解或情绪时保留，不以最快节奏为默认目标。

再完成精剪：

1. 每个镜头或段落都新增信息、情绪、证据或必要呼吸。
2. 同一画面能够稳定承担完整解释时继续使用，不按句号或每句话切镜头；只有画面职责、对象、动作或必要视角改变时才切。
3. B-roll、图形和字幕补足口播难以呈现的信息，不逐句装饰。
4. 开头建立问题或情境，核心转折在受众仍保持问题意识时出现，结尾给出明确收束。
5. 需要多平台比例时，只制作用户点名的版本；不同构图必须回到同一时间线或明确的派生序列。

切换让人觉得晃、闪或晕时，先判断原因：当前画面与声音不匹配就换素材；切点早晚不对就重新踩词；前后录屏的缩放、平移或关注区域相差太大就先统一视觉锚点；连续解码也出现异常才检查编码。直接切换清楚时不加效果。只有内容与切点已经正确、构图跳变仍然刺眼时，才试最短且不产生重影的过渡，并逐帧查看前、中、后状态；长交叉溶解和明显幻影不能作为“高级感”。同一动作转定格、同一构图继续讲解通常直接切换，不加过渡。

## 五、字幕与声音

字幕从最终语音和时间线生成或校正，保留专有名词、数字、语气和说话人信息。逐字字幕造成阅读负担时可以按语义压缩，但不能改变结论或删除关键条件。先处理字幕与脸、手势、产品关键部位、原视频字幕和其它画面内容的碰撞，再按当前目标平台和发布日期检查界面覆盖风险；平台安全区不是一个能够替代画面检查的固定矩形。

双语或学习视频确有需要时，可以把字幕拆成原语言主句、自然译文和必要注释三个职责层。来源、许可、说话人或课程信息默认留在素材账本和交付说明，不因已有三层就继续堆到画面上。字号、位置和行数按当前画布与手机实际显示检查，不继承其它项目的固定坐标。

优先保证人声可懂、音画同步和段落间响度稳定，再处理降噪、均衡、压缩、音乐和空间效果。无法从严重削波、混响或缺失录音中可靠恢复的信息要明确说明。音乐和素材只在获得使用权时加入，不能用音乐掩盖结构问题或难懂口播。

## 六、样稿与导出

用户只要剪辑样稿时，选择能够代表实际成片职责的短段落，不提前完成全片。一般视频可以用一个代表性段落验证节奏、字幕、覆盖层和声音处理；人物口播或会反复切换构图的长视频，应覆盖实际会重复出现的版式家族。每个样稿只确认对应层，不定义未展示部分；确认后沿完整媒体文案和语义剪辑表扩展。已经确认的文案、声音、字幕样式或前半段剪辑保持原版本，局部反馈只重做受影响区间与必要下游，并输出新的可回退版本，不能覆盖最后一个可用预览。

综合样片确认后，长视频不再把“整条时间线到一个 MP4”作为最小渲染单位。按已经确认的场景、章节或稳定剪辑边界建立通用 `media-build-plan.json`；单元要足够小，能让一次常见修改只命中一个或少数单元，又不能细到每句话都产生无意义编码和接缝。默认从 10–45 秒或一个完整场景起步，实际边界由语义、转场、网页状态和角色连续动作共同决定，不把这个范围写成硬性时长。

MediaFlow Pro 支持时，按本次 `describe` 调用 `export.sequence.build`。它从真实时间线计算每个区间的画面依赖，缓存画面单元；音频总线、压缩、响度、ducking 和淡入淡出仍作为整条连续母版渲染，再与画面单元装配。只改中间画面时，前后画面单元和音频母版必须命中；只改声音时，所有画面单元必须命中。代理、样片和最终母版使用不同输出规格，规格变化会正确失效，不能用代理缓存冒充最终文件。

二次元角色轨进入普通视频或采访视频时也遵守同一边界：角色生产者提供项目内连续片段和一条连续音频，编辑器用 `timeline.clip.batch.add` 把片段一次摆入覆盖轨，再由 `export.sequence.build` 按通用构建单元消费。角色只改中间一句时，不重新导出前后角色片段，也不切碎连续对白。

实际导出时按 `media-project-contracts.md` 建立 `media-delivery.json`。内容迭代使用 `preview`，内部审阅和常规交付前检查使用 `review`，正式交付使用 `final`；档位只改变检查成本与证据范围，不改变活动时间线和已经确认的内容。所有尺寸、帧率、时长、响度、静音和黑场阈值来自当前项目，不从其它案例继承。

导出前检查开头、核心转折、字幕密集段、音画同步点和结尾；生成 review 文件后先冻结文件并从头到尾观看，把问题写入绑定当前文件哈希的 `media-review.json`。时间码以秒为准，帧号只按当前帧率推导；问题要指向相关时间线元素，并写清可观察证据和具体改法。先完成整轮审阅再修改；修改后媒体哈希变化，旧审阅自动失效，必须重新完整观看。`media-review.json` v3 同时绑定不可变制作依据及清单摘要，把尺寸、时长、帧率、字幕方式等承诺指回依据 JSON Pointer，再分开保存机器检查、Agent 全片审看和所需用户确认；不能用联系表或技术指标替代后两者。导出后使用真实播放器读取文件，并运行 `scripts/verify-media-delivery.py` 检查编码、尺寸、帧率、时长、音轨、字幕、采用原片和实际可播放性。正式交付增加 `--require-delivery-ready`，要求技术检查、当前成片的结构化完整审看和权利复核分别通过。交付编辑项目或时间线、必要网页视觉源、成片、联系表、审阅合同和交付报告后停止。

交付前回到活动素材清单逐项核对：必用素材在最终时间线和导出成片中能够找到，未采用素材有与当前内容和质量要求一致的原因，不能用时间线占位符、文件名或消费端手写记录冒充素材已经进入成片。
