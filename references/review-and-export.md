# 媒体检查、导出与交付

用于用户要求实际生成静态图、GIF、视频、音频或播客成品时，沿活动真源、预览、导出和最终使用检查真实链路。结构完整或命令返回成功不能代替成品可见、可听和可用。

## 一、先检查活动真源

- 网页项目能够按清单声明的交付方式在真实浏览器打开，场景、内容版式、输出变体、数据、视觉变量和播放状态从各自唯一位置修改。
- 可编辑网页包的清单是场景、步骤、播放方式、内容版式合同、输出变体、默认数据、主题、资源与量化质量规则的权威配置，HTML 没有平行保存另一份同名值。
- 项目 `style-profile.json` 记录的视觉来源已经由当前媒体项目或用户确认采用，共享视觉核心与网页字体、颜色、材质、图形和素材处理一致；仓库中未被采用的旧图、相邻成品和案例预览没有成为隐含配色来源。静态、时间和交互实现只在各自声明的成品类型中生效。目标载体不适用的实现层没有被临场继承，实拍或剪辑型视频没有把镜头、剪辑和声音写回视觉档案。
- 对用户要求的每个“输出变体 × 场景”运行 `scripts/validate-editable-media.mjs`；清单、素材槽位、稳定图层 ID、本地资源、`window.editableMedia` 接口、唯一画布根元数据、`window.__hf.duration/seek(seconds)`、三种播放控制、真实边界和项目质量规则全部通过。项目中的场景覆盖值关闭重开后仍存在。
- 使用外部、用户提供或生成素材时能够找到 v3 `media-sources.json`，并通过 `scripts/validate-media-sources.mjs` 证明实际文件、字节数、SHA-256、来源、授权、用途、主体位置、各输出变体裁切以及原片与代理等价关系一致；网页清单里的必需素材槽位绑定有效 source id，浏览器运行时从账本解析实际文件，清单和 `resources` 没有再保存一份媒体路径。
- 使用注册媒体资源时能够找到 `media-resource-adoptions.json`，并证明注册包哈希、采用后的 source id 或完整网页包、项目消费者读取结果一致；只有注册或采用记录，没有活动场景、视频或音频消费者引用时，不算进入当前成品。
- 视频或音频项目能够找到全部原片，时间线没有离线文件、错误代理或丢失效果；预览可以解析代理，正式导出已统一解析回原片。
- 有人物表达的源素材能够找到绑定原片和输入哈希的 `transcript.json`，待确认词已经通过实际听音处理；上屏字幕与语义片段没有复制另一份事实转写。
- 真实视频或音频选段能够找到 `clip-selections.json`，片段不超过 `maximum_clips`，并通过 `scripts/validate-clip-selections.mjs` 证明引用原片和已复核转写，没有越过真实素材时长、无理由重复或跳过人物表达的完整语义审核。
- 跨多轮项目能够找到唯一 `media-project-state.json` v3；通用阶段、成果集合哈希、用户确认、合同入口、活动制作决策、阻塞项和下一步一致。默认逐阶段验收，只有明确用户授权才是全自动；具体 profile 没有平行批准状态。它没有复制内容或时间线，已被替代的决策也不会继续驱动生产。
- 项目或系列声明可复用声音语言时能够找到独立 `sound-profile.json`，其中每条 cue 都解析到已收口的真实 audio source id；视觉档案没有混入音乐、音效或混音规则，声音档案也没有反向复制画面配方。
- 时间型媒体能够找到当前语义片段图；每段的声音范围、画面职责、运动类型和时长来源与活动时间线一致。
- 使用合成语音时能够找到确认文案、合成输入、供应方式、声音参数、原始音频和时间标记；后期文件仍可追溯到这份原始音频。
- 当前文案、网页、字幕、音频和时间线属于同一确认版本，没有从旧样稿恢复用户已经否定的内容。
- 个人或系列内容能够分别找到当前有效的 `editorial_position` 与 `voice_contract`，媒体文案的信息取舍与表达方式各自对应正确输入。
- 系列派生项目能够找到 `source_id`、`source_version`、`content_unit_id`、`media_project_id` 和 `media_script_version`；当前文案、素材与导出物对应同一来源版本。来源已经更新时，受影响项目完成重新核对后再导出。
- 输出规格来自用户、项目规则或目标平台；无法确认且会影响大部分构图或编码时先询问。
- 静态卡和封面的当前完整画布、`quality.thumbnail.width` 对应的最小实际展示预览与用户点名导出物来自同一清单版本。比例、一级分区、主要视觉语言或文案骨架改变后，旧完整画布和旧缩略图立即失效，不得继续作为验收证据。

## 二、检查预览

### 网页视觉

在目标画布尺寸检查字体、中文与符号、图片和图标加载、层级、重叠、裁切、溢出、安全区、导航避让、标题间距、底部空白、背景和捕获控件。清点最终画布中观众能读到的标题、正文、标签、栏头、署名、来源、元信息、页码、按钮、微文案、SVG 文字和伪元素内容，确认它们服从同一语言合同，保留外文的位置属于已经允许的正式名称或专用记法。再把完整画布适配到普通浏览器窗口，确认网页能够看全，并逐项检查这些文字和指标在真实显示比例下是否清楚。对需要共同对齐的左右内容读取实际边界，核对选定的基线、顶部、底部或中心关系；文字位于形状、节点或徽章内时，还要把文字块与实际可见承载形状换算到同一画布坐标并比较中心，清单边界与 CSS 坐标一致不能代替这项检查。同时查看大面积色块的明暗、冷暖和面积是否形成同一套共享视觉核心。社交卡和封面再缩到约 360 像素宽或目标平台实际缩略图尺寸，确认静态构图实现中的标题、主体和主要证据仍可识别；多比例、多场景项目分别打开每个“输出变体 × 场景”，不能只检查默认状态。用户提供标注截图时，把每个标注区域对应到具体文字、承载形状或布局关系后逐项复查。动画逐场景检查时间运动实现中的进入、步骤、核心变化、结果保持、退出、局部循环衔接和相同时间点的确定性；复杂场景先查看由真实运行时生成的开始、全部必要变化和结果关键状态图，再完整播放检查状态之间的运动。使用镜头时核对它确实帮助解释空间或注意力、景深外文字始终清楚、对象运动与镜头外层没有争夺同一 transform。交互演示实际使用键盘、滚轮或触摸完成一遍前后推进，并核对交互实现没有改写画布内语义时间线；自动播放实际连续经过全部场景，混合播放实际在场景边界停下。有方向的变化到达结果后不能被局部循环意外重置；整条时间线只有在内容本身没有叙事推进且首尾含义等价时才检查无缝总循环。

静态卡和封面的结论分开记录：技术检查只说明文件、清单、浏览器画面和量化规则是否工作；内容检查说明活动材料中的核心主张、主要支撑、必要边界和指代是否完整且目标受众能够理解；视觉检查说明阅读顺序、构图、比例、密度与当前风格方向是否成立。`validate-editable-media.mjs` 的 `passed` 和 `technical_passed` 都只属于技术结论，它不输出内容通过或视觉通过。约 360 像素宽或项目声明的更小实际展示检查，至少覆盖标题和每个一级分区的代表文字，不能只选择最容易通过的标题或导语；承担主要理解的文字不得用 10–12px 的技术可见阈值冒充舒适阅读，静态社交卡以 16px 左右为目标、14px 为下限。Agent 必须同时查看当前完整画布和缩略图；技术检查通过不能替代内容与视觉判断，视觉方向尚待用户确认时只能交付为待确认样稿，也不得因为技术通过提前宣称整个视觉问题已经修好。

当前网页实际包含相应元素时，再检查成品细修结果：字体加载后标题与正文的真实换行没有突兀孤行，也没有因为均衡换行超出版式容量；动态数字通过活动数据字段或时间状态读取至少两个真实取值，数值变化没有推动共享列和相邻内容；嵌套圆角、图片边缘、阴影与分隔线能够说明各自的包含、层次或结构职责；不对称图标和形状在最终显示比例下视觉居中，图标细节与线宽没有粘连或压过相邻文字。手动或混合播放控件在目标输入方式下逐个实际使用，相邻命中区域不重叠，中途改变操作时反馈能够立即返回当前状态；浏览器没有因为未限定的过渡属性产生意外位移、尺寸或阴影动画。只检查当前成品真实存在的元素，不为凑齐项目制造嵌套圆角、图标、动态数字或交互控件。

无实拍视频、代码动画或动态图解再把关键状态图按时间顺序连续查看，并暂时忽略逐句标题。承担推进、因果、转折或兑现的场景必须能从运动载体、对象关系和结果状态看出信息确实前进；若主要差异只是换标题、换卡片、换截图或整页淡入，说明动画仍是幻灯片式切换，应回到视觉命题和场景计划重做，不能靠更多装饰动效通过。

实际导出 GIF、代码动画或无实拍视频时，从同一网页真源和时间线捕获开始、一个或多个关键变化以及结束状态，生成带时间和条目标识的关键状态检查图供验收。非循环动画把预期结束状态与实际导出末帧并排比较；循环动画比较首尾状态及衔接所需的持续上下文；批量成品按条目编号组织总览，使用户能够分别确认。检查图只记录和展示真实预览或导出结果，不成为新的制作入口，也不能代替打开最终媒体检查运动过程。

网页动画派生 GIF 或视频时，还要在相同时间点并排比较浏览器源帧与最终文件的解码帧。GIF 只有 256 色调色板，深色背景上的细线、低对比渐变和微弱发光容易在 `palettegen`、`paletteuse` 与抖动阶段被合并，从而显得整体变暗或丢失结构；先针对当前画面调整调色板统计范围、抖动和结构线明度，再重新比较，不能只看网页预览。若 GIF 仍与确认画面存在实质差异，明确说明格式限制，并在用户同意后改交 MP4；不能无声切换用户点名的格式。

本地网页渲染从活动 `editable-media` v6 包读取同一场景状态，并在相同时间点比较浏览器源帧和 `scripts/render-web-media-local.mjs` 的成片解码帧。网页包进入 MediaFlow Pro 后，分别从桌面界面和 CLI 读取同一组场景状态；修改文字和位置后，浏览器预览、重开工程、缓存、时间线预览和最终导出都必须读取这次修改。HyperFrames 直接渲染必须从原网页包建立独立工作副本并核对所选输出变体。三条路径不能混称同一版本，源摘要、状态或修订变化后不能继续引用旧画面。

### 视频

在真实播放器检查开头、核心转折、字幕最密集处、画面比例变化、网页视觉插入点、音画同步、音乐与人声关系、结尾和黑帧。长素材、录屏或关键区间不明确时先运行 `scripts/make-video-contact-sheet.py`，从真实素材的稀疏代表帧选择区间和裁切；最终导出后再生成一张联系表检查黑帧、错误区间、意外停帧和裁切漂移。联系表不能证明动作过程、声音边界或字幕在手机尺寸可读，仍要打开视频检查。旁白主导的视频先做一次只听声音的理解检查，再边听边看每个语义片段：当前画面必须仍在解释当前声音，经过明确允许的复用不能越过当前声音职责，有方向的结果不能突然复位，整片不能因为补时而从头重复。代理预览流畅不能证明最终导出正确。

已有素材剪辑还要按语义剪辑表逐项看关键边界：踩词事件是否落在动作开始、完成或完成后停顿的正确位置；第一项、第二项或前后对照是否聚焦对应素材；操作播放到完整结果，解释段停在清楚且无干扰的画面；未经说明的重复、循环、慢放和无关鼠标移动不存在。逐个切换判断是内容、时间、构图还是编码问题；使用过渡时查看首帧、中间帧和结束帧，确认没有重影或额外晃动。这里不检查网页动画的场景状态机；网页动画只按上一节的场景、步骤和确定性时间线验收。

面向手机微信等常见移动端播放器的普通 MP4，优先使用 H.264、`yuv420p`、`avc1` 标签、BT.709 色彩标记、偶数宽高、常规帧率和 `faststart`，避免把 `yuv444p`、High 4:4:4 Predictive、10 bit 或透明像素格式作为普通交付。FFprobe 通过只能证明编码规格；能够使用真机时还要实际发送并播放，不能真机测试时只写“已按移动端兼容规格验证”，不得声称已通过微信设备测试。随机定位抽出的单帧缺元素或不完整时，先顺序完整解码目标区间并生成联系表；只有连续解码也复现异常，才把问题归因于成片。

透明视频或覆盖层不能用普通播放器显示出的黑底判断成败。先用 FFprobe 读取实际容器、编码和像素格式，再从最终文件解码至少一个本应可见的关键帧以及开始、核心变化和结束帧的透明通道：应透明的区域必须保留非不透明值，应可见的前景不能全透明，边缘不能混入黑边或白边。随后把同一文件导入用户最终采用的剪辑或合成工具，分别叠加到明、暗底片上完整播放，检查透明区域、边缘、闪烁、意外空帧和时间边界。目标工具不可用时，只能说明文件层透明通道已经检查，不能声称目标编辑链路可用；全片黑场扫描也不能把预期透明的 RGB 底色单独判成内容失败。

### 封面与视频首帧

目标平台会自动截取视频首帧作为封面，或用户明确要求首帧就是确认封面时，把确认的封面文件作为时间线输入，并从最终导出视频实际抽取第 0 秒画面核对；时间线里看似放置正确不能代替导出结果一致。目标平台支持独立封面且用户没有要求两者相同时，分别检查封面文件和视频开头，不强制把封面复制成视频首帧。

用户明确要求 Live Photo 时继续执行主入口已经加载的 Live Photo 交付检查，核对匹配元数据、最终 MOV 联系表、`.pvt` 内容和 Apple 设备导入。普通 JPG/MOV 文件对不能作为 Live Photo 完成证据。

### 音频

使用耳机或可用监听从头到尾检查关键人声、说话人切换、噪声处理、停顿、音乐遮挡、声道、开头和结尾。合成旁白逐项核对专有名词、数字、断句、重音、自然度和尾句完整性，并确认实际声音、参数、时长和时间标记与项目记录一致。波形和响度数值只辅助判断，不能替代实际听取。

字幕随最终成片在目标尺寸观看：文字与声音含义一致，必要英文保持正式写法，已确认字号和语言层级没有漂移，每种语言不超过当前样式规定的行数；删句、拼接和镜头边界附近没有残字、半个音节或尾音截断。字幕样式声明居中时，分别查看短句、长句和双语代表 cue，把实际字幕包围盒与完整画布水平中线比较；人物窗或安全区不能通过扩大单侧边距把整组字幕长期推向另一侧。

## 三、执行导出

优先使用选定提供方读取活动真源的正式导出能力：本地网页包由 `scripts/render-web-media-local.mjs` 导出，本地产品无关时间线由 `scripts/media-timeline.mjs` 导出；已经迁移为 MediaFlow Pro 原生工程时只从该工程导出；明确选择 HyperFrames 时只从 editable-media v6 网页包的渲染副本导出。浏览器、FFmpeg、FFprobe 或编辑软件只读取真源并编码，不重新实现内容、布局或时间线。

导出失败时保留可编辑真源，报告具体失败环节、已经成功的状态和缺少的工具或输入。未获安装授权时不安装依赖；不能为了宣称完成而改用另一套不一致的绘制或剪辑逻辑。

视频和音频实际生成文件时建立唯一的 `media-delivery.json`。`preview` 用于迭代，`review` 增加响度、静音和视频联系表，`final` 再增加全片黑场扫描、原片采用、结构化完整审阅和最终证据状态。检查档位不能改变内容真源或偷偷降低用户点名的输出规格。

同一 v3 合同必须把交付物声明为 `native_project`、`source_bundle` 或 `flat_render`。原生工程绑定工程路径、标识、内容修订和 SHA-256；源文件包绑定网页包或产品无关时间线及全部真源哈希；扁平输出明确不能还原哪些图层、轨道、动画参数或合成前素材关系。不能把“另有可编辑真源”和“当前 MP4 本身可编辑”混为一谈。

进入人工审阅前冻结一个不可变媒体文件，并把计划、确认、构建报告、机器报告、交付合同等实际审阅依据以路径、SHA-256 和依据清单摘要写入 `media-review.json` v3。每项承诺检查必须指向其中一份 JSON 依据的准确 JSON Pointer，保存该位置的期望值，再记录真实结果和证据；不能只写一句“符合预期”。随后完整观看或试听并记录问题，不在观看过程中边改边让后续问题失去共同基准。机器报告、Agent 完整审阅和所需用户确认分别保存，机器通过不能自动把 Agent 或用户状态改成通过。时间以秒为规范值，帧范围只按当前帧率推导。失败承诺必须关联 finding；问题要写明相关时间线元素、可观察证据与精确修改要求，动效或层级问题还应说明前后值、持续时间、缓动、层级、不变量和不受影响的对象。依据、承诺值或成片改变后重新建立评审并完整审看，旧通过状态不能迁移。

## 四、检查导出结果

使用最终用户会采用的工具重新打开成品，并检查：

- 文件确实存在、大小合理、可以完整读取和播放。
- 静态图的格式、像素、透明或背景、清晰度和画布内容正确。
- 多比例静态图分别对应清单中的目标输出变体，标题变体、图层显隐和素材裁切没有退回其它比例。
- GIF 的尺寸、帧序、帧率、循环、停留和文件大小符合目标。
- 视频的容器、编码、比例、分辨率、帧率、时长、音轨、字幕和色彩可用。
- 用户要求透明视频或覆盖层时，实际透明通道、可见前景、边缘和目标剪辑软件中的明暗底叠加都通过。
- 音频的容器、编码、采样率、声道、时长、响度变化和头尾完整。
- 音频经过容器转换或重编码时，以完整解码后的时长、采样率、声道、响度、峰值、静音与掉帧检查以及实际听音判断内容是否等价；有损或重新封装的派生音频不要求与源文件字节哈希相同。哈希继续负责绑定各自那个真实文件，不能拿“哈希不同”误判正常重编码，也不能拿“能解码”代替听音。
- 旁白实际时长与视频或音频时间线一致，最后一句没有被固定时长、循环边界或导出尾点截断。
- 派生媒体与活动真源在相同状态表达同一内容，没有丢失字体、颜色、图形、滤镜、蒙版、声音、字幕或关键帧。

能够使用 FFprobe 或等价工具时读取实际文件元数据；元数据检查通过后仍要查看或试听成品。

对视频和音频运行：

```powershell
python scripts/verify-media-delivery.py <项目目录>/media-delivery.json
```

脚本生成 `media-delivery-report.json`，分别报告 `technical_ready`、`human_review_passed`、`rights_review_passed` 和 `delivery_ready`。其中人工状态只从绑定当前成品哈希且通过校验的 `media-review.json` 得出，机器检查不得自行把人工审看或权利复核改成通过。正式交付增加 `--require-delivery-ready`；报告会在失败时保留具体检查结果，不能只交付一个退出码。

## 五、可修改性检查

选择一个用户可见字段或变量，在活动真源中修改并重新预览，确认相关结果由同一真源更新，不需要同步修改派生媒体或平行脚本。已经完成最终导出时，恢复确认内容或保留修改后的正确版本，再重新导出用户点名的格式。

交付带画布外编辑器的 DOM 网页包时，从普通预览入口完成一次真实用户操作：看见编辑器；分别从侧栏和画布直接修改当前场景文字；修改一个颜色变量；选择一组字体与字重并证明浏览器实际命中；确认画布立即更新。刷新页面确认修改仍存在；下载当前数据并重新读取；放大预览后能够返回编辑；恢复初始值后确认清单默认状态重新出现；执行当前画布导出并实际打开文件。随后用捕获参数打开同一入口，确认编辑器、导航和调试控件全部退出画布。Windows 本地包再从交付目录双击或直接运行 BAT 启动器，核对它服务的就是当前包、返回 HTTP 200 且浏览器读到当前清单标识；端口冲突时启动器应选择新的本地端口，不能打开另一份正在运行的项目。用户明确选择 React 时，改动 React 源码或清单中的一个真实字段，重新构建并沿同一浏览器、捕获和导出链核对。

这条用户链只证明编辑、保存、恢复、启动和导出真实工作。完整画布与约 360 像素缩略图仍由 Agent 实际查看并记录可观察问题；机器检查通过时只报告技术结果，视觉方向由用户确认。
