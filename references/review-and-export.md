# 媒体检查、导出与交付

用于用户要求实际生成静态图、GIF、视频、音频或播客成品时，沿活动真源、预览、导出和最终使用检查真实链路。结构完整或命令返回成功不能代替成品可见、可听和可用。

## 一、先检查活动真源

- 网页项目能够按清单声明的交付方式在真实浏览器打开，场景、内容版式、输出变体、数据、视觉变量和播放状态从各自唯一位置修改。
- 可编辑网页包的清单是场景、步骤、播放方式、内容版式合同、输出变体、默认数据、主题、资源与量化质量规则的权威配置，HTML 没有平行保存另一份同名值。
- 对用户要求的每个“输出变体 × 场景”运行 `scripts/validate-editable-media.mjs`；清单、素材槽位、稳定图层 ID、本地资源、`window.editableMedia` 接口、唯一画布根元数据、`window.__hf.duration/seek(seconds)`、三种播放控制、真实边界和项目质量规则全部通过。项目中的场景覆盖值关闭重开后仍存在。
- 使用外部、用户提供或生成素材时能够找到 v3 `media-sources.json`，并通过 `scripts/validate-media-sources.mjs` 证明实际文件、字节数、SHA-256、来源、授权、用途、主体位置、各输出变体裁切以及原片与代理等价关系一致；网页清单里的必需素材槽位绑定有效 source id，浏览器运行时从账本解析实际文件，清单和 `resources` 没有再保存一份媒体路径。
- 使用注册媒体资源时能够找到 `media-resource-adoptions.json`，并证明注册包哈希、采用后的 source id 或完整网页包、项目消费者读取结果一致；只有注册或采用记录，没有活动场景、视频或音频消费者引用时，不算进入当前成品。
- 视频或音频项目能够找到全部原片，时间线没有离线文件、错误代理或丢失效果；预览可以解析代理，正式导出已统一解析回原片。
- 有人物表达的源素材能够找到绑定原片和输入哈希的 `transcript.json`，待确认词已经通过实际听音处理；上屏字幕与语义片段没有复制另一份事实转写。
- 真实视频或音频选段能够找到 `clip-selections.json`，片段不超过 `maximum_clips`，并通过 `scripts/validate-clip-selections.mjs` 证明引用原片和已复核转写，没有越过真实素材时长、无理由重复或跳过人物表达的完整语义审核。
- 跨多轮项目能够找到唯一 `media-project-state.json` v2，当前确认层、合同入口、会改变后续成片的活动制作决策、产物哈希、阻塞项和下一步一致；它没有复制内容或时间线，已被替代的决策也不会继续驱动生产。
- 项目或系列声明可复用声音语言时能够找到独立 `sound-profile.json`，其中每条 cue 都解析到已收口的真实 audio source id；视觉档案没有混入音乐、音效或混音规则，声音档案也没有反向复制画面配方。
- 时间型媒体能够找到当前语义片段图；每段的声音范围、画面职责、运动类型和时长来源与活动时间线一致。
- 使用合成语音时能够找到确认文案、合成输入、供应方式、声音参数、原始音频和时间标记；后期文件仍可追溯到这份原始音频。
- 当前文案、网页、字幕、音频和时间线属于同一确认版本，没有从旧样稿恢复用户已经否定的内容。
- 个人或系列内容能够分别找到当前有效的 `editorial_position` 与 `voice_contract`，媒体文案的信息取舍与表达方式各自对应正确输入。
- 系列派生项目能够找到 `source_id`、`source_version`、`content_unit_id`、`media_project_id` 和 `media_script_version`；当前文案、素材与导出物对应同一来源版本。来源已经更新时，受影响项目完成重新核对后再导出。
- 输出规格来自用户、项目规则或目标平台；无法确认且会影响大部分构图或编码时先询问。

## 二、检查预览

### 网页视觉

在目标画布尺寸检查字体、中文与符号、图片和图标加载、层级、重叠、裁切、溢出、安全区、导航避让、标题间距、底部空白、背景和捕获控件。再把完整画布适配到普通浏览器窗口，确认网页能够看全，并逐项检查标题、正文、标签、栏头、署名、链接和指标在真实显示比例下是否清楚。对需要共同对齐的左右内容读取实际边界，核对选定的基线、顶部、底部或中心关系；同时查看大面积色块的明暗、冷暖和面积是否形成同一套画面。社交卡和封面再缩到约 360 像素宽或目标平台实际缩略图尺寸，确认标题、主体和主要证据仍可识别；多比例、多场景项目分别打开每个“输出变体 × 场景”，不能只检查默认状态。用户提供标注截图时，按标注区域逐项复查。动画逐场景检查进入、步骤、核心变化、结果保持、退出、局部循环衔接和相同时间点的确定性；复杂场景先查看由真实运行时生成的开始、全部必要变化和结果关键状态图，再完整播放检查状态之间的运动。使用镜头时核对它确实帮助解释空间或注意力、景深外文字始终清楚、对象运动与镜头外层没有争夺同一 transform。交互演示实际使用键盘、滚轮或触摸完成一遍前后推进，自动播放实际连续经过全部场景，混合播放实际在场景边界停下。有方向的变化到达结果后不能被局部循环意外重置；整条时间线只有在内容本身没有叙事推进且首尾含义等价时才检查无缝总循环。

无实拍视频、代码动画或动态图解再把关键状态图按时间顺序连续查看，并暂时忽略逐句标题。承担推进、因果、转折或兑现的场景必须能从运动载体、对象关系和结果状态看出信息确实前进；若主要差异只是换标题、换卡片、换截图或整页淡入，说明动画仍是幻灯片式切换，应回到视觉命题和场景计划重做，不能靠更多装饰动效通过。

实际导出 GIF、代码动画或无实拍视频时，从同一网页真源和时间线捕获开始、一个或多个关键变化以及结束状态，生成带时间和条目标识的关键状态检查图供验收。非循环动画把预期结束状态与实际导出末帧并排比较；循环动画比较首尾状态及衔接所需的持续上下文；批量成品按条目编号组织总览，使用户能够分别确认。检查图只记录和展示真实预览或导出结果，不成为新的制作入口，也不能代替打开最终媒体检查运动过程。

网页包进入 MediaFlow Pro 后，分别从桌面界面和 CLI 读取同一组场景状态。修改当前场景的一个文字字段和一个位置字段，确认浏览器预览、关闭重开后的项目、浏览器逐帧缓存、时间线预览和最终导出依次读取了这次修改。源摘要、场景状态或修订号改变后必须生成新的缓存，不能继续引用旧画面。HyperFrames 直接渲染则必须从原网页包建立独立工作副本并核对所选输出变体；它不读取 MediaFlow Pro 项目修改，两条路径的结果不能混称同一版本。

### 视频

在真实播放器检查开头、核心转折、字幕最密集处、画面比例变化、网页视觉插入点、音画同步、音乐与人声关系、结尾和黑帧。长素材、录屏或关键区间不明确时先运行 `scripts/make-video-contact-sheet.py`，从真实素材的稀疏代表帧选择区间和裁切；最终导出后再生成一张联系表检查黑帧、错误区间、意外停帧和裁切漂移。联系表不能证明动作过程、声音边界或字幕在手机尺寸可读，仍要打开视频检查。旁白主导的视频先做一次只听声音的理解检查，再边听边看每个语义片段：当前画面必须仍在解释当前声音，片段内部循环不能越过声音边界，有方向的结果不能突然复位，整片不能因为补时而从头重复。代理预览流畅不能证明最终导出正确。

### 封面与视频首帧

目标平台会自动截取视频首帧作为封面，或用户明确要求首帧就是确认封面时，把确认的封面文件作为时间线输入，并从最终导出视频实际抽取第 0 秒画面核对；时间线里看似放置正确不能代替导出结果一致。目标平台支持独立封面且用户没有要求两者相同时，分别检查封面文件和视频开头，不强制把封面复制成视频首帧。

用户明确要求 Live Photo 时继续按 `live-photo-delivery.md` 检查匹配元数据、最终 MOV 联系表、`.pvt` 内容和 Apple 设备导入。普通 JPG/MOV 文件对不能作为 Live Photo 完成证据。

### 音频

使用耳机或可用监听从头到尾检查关键人声、说话人切换、噪声处理、停顿、音乐遮挡、声道、开头和结尾。合成旁白逐项核对专有名词、数字、断句、重音、自然度和尾句完整性，并确认实际声音、参数、时长和时间标记与项目记录一致。波形和响度数值只辅助判断，不能替代实际听取。

## 三、执行导出

优先使用活动真源已经提供的导出能力。网页视频已经进入 MediaFlow Pro 项目时只从该项目导出；明确选择 HyperFrames 的独立无声代码动画只从 v4 网页包的渲染副本导出。需要浏览器捕获、FFmpeg、FFprobe 或编辑软件时，它们只负责读取真源和编码，不重新实现内容、布局或时间线。

导出失败时保留可编辑真源，报告具体失败环节、已经成功的状态和缺少的工具或输入。未获安装授权时不安装依赖；不能为了宣称完成而改用另一套不一致的绘制或剪辑逻辑。

视频和音频实际生成文件时建立唯一的 `media-delivery.json`。`preview` 用于迭代，`review` 增加响度、静音和视频联系表，`final` 再增加全片黑场扫描、原片采用、结构化完整审阅和最终证据状态。检查档位不能改变内容真源或偷偷降低用户点名的输出规格。

同一合同必须把交付物声明为 `editable_native` 或 `flat_render`。前者绑定真实原生项目文件及其 SHA-256；后者明确说明扁平输出不能还原哪些图层、轨道、动画参数或合成前素材关系。不能把“项目另有可编辑真源”和“当前 MP4 本身可编辑”混为一谈。

进入人工审阅前冻结一个不可变媒体文件，并把计划、确认、构建报告、机器报告、交付合同等实际审阅依据以路径、SHA-256 和依据清单摘要写入 `media-review.json` v3。每项承诺检查必须指向其中一份 JSON 依据的准确 JSON Pointer，保存该位置的期望值，再记录真实结果和证据；不能只写一句“符合预期”。随后完整观看或试听并记录问题，不在观看过程中边改边让后续问题失去共同基准。机器报告、Agent 完整审阅和所需用户确认分别保存，机器通过不能自动把 Agent 或用户状态改成通过。时间以秒为规范值，帧范围只按当前帧率推导。失败承诺必须关联 finding；问题要写明相关时间线元素、可观察证据与精确修改要求，动效或层级问题还应说明前后值、持续时间、缓动、层级、不变量和不受影响的对象。依据、承诺值或成片改变后重新建立评审并完整审看，旧通过状态不能迁移。

## 四、检查导出结果

使用最终用户会采用的工具重新打开成品，并检查：

- 文件确实存在、大小合理、可以完整读取和播放。
- 静态图的格式、像素、透明或背景、清晰度和画布内容正确。
- 多比例静态图分别对应清单中的目标输出变体，标题变体、图层显隐和素材裁切没有退回其它比例。
- GIF 的尺寸、帧序、帧率、循环、停留和文件大小符合目标。
- 视频的容器、编码、比例、分辨率、帧率、时长、音轨、字幕和色彩可用。
- 音频的容器、编码、采样率、声道、时长、响度变化和头尾完整。
- 音频经过容器转换或重编码时，以完整解码后的时长、采样率、声道、响度、峰值、静音与掉帧检查以及实际听音判断内容是否等价；有损或重新封装的派生音频不要求与源文件字节哈希相同。哈希继续负责绑定各自那个真实文件，不能拿“哈希不同”误判正常重编码，也不能拿“能解码”代替听音。
- 旁白实际时长与视频或音频时间线一致，最后一句没有被固定时长、循环边界或导出尾点截断。
- 派生媒体与活动真源在相同状态表达同一内容，没有丢失字体、颜色、图形、滤镜、蒙版、声音、字幕或关键帧。

能够使用 FFprobe 或等价工具时读取实际文件元数据；元数据检查通过后仍要查看或试听成品。

对视频和音频运行：

```powershell
python scripts/verify-media-delivery.py <项目目录>/media-delivery.json
```

脚本生成 `media-delivery-report.json`，分别报告 `technical_ready`、`human_review_passed`、`rights_review_passed` 和 `delivery_ready`。其中人工状态只从绑定当前成品哈希且通过校验的 `media-review.json` 得出，机器检查不得自行把人工审看或权利复核改成通过。正式交付增加 `--require-delivery-ready`；报告会在失败时保留具体检查结果，不能只交付一个退出码。

## 五、可修改性检查

选择一个用户可见字段或变量，在活动真源中修改并重新预览，确认相关结果由同一真源更新，不需要同步修改派生媒体或平行脚本。已经完成最终导出时，恢复确认内容或保留修改后的正确版本，再重新导出用户点名的格式。

## 六、交付清单

按用户请求交付：

1. 采用的媒体形式和已经完成的结果。
2. 当前确认的媒体文案。
3. 可编辑网页、视频时间线或音频项目。
4. 用户点名的预览、样稿或最终媒体。
5. 视频或音频项目的项目状态、事实转写、结构化审阅、`media-delivery.json`、联系表和 `media-delivery-report.json`；只交付当前项目实际存在的合同。
6. 会影响继续修改或发布的必要规格、素材来源和已知限制。
7. 系列派生任务使用的来源版本、内容单元、媒体项目和文案版本。
8. 当前项目实际存在的注册资源采用记录、声音档案和成果晋升候选；原始日志、未采用版本和无关注册库不随成品附送。

用户没有要求发布时停在本地可用成品。不要自动生成其它比例、时长、平台版本、标题变体、标签、排期或上传动作。
