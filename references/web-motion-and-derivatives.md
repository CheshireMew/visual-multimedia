# 网页叙事、动画与派生媒体

本文件用于已经选定网页真源、完成结构化合同和输出变体的任务。它只负责根据内容关系组织场景、制作样稿、建立确定性动画，并从同一活动网页真源派生媒体；不能反向建立第二套内容、时间或导出真源。

## 一、从内容关系选择画面

先读取主入口已经确认的媒体文案和制作说明，再决定网页结构：

- 数值随时间变化时使用坐标、条形、面积、计数器或对象尺度变化。
- 静态差异使用并列、叠加、矩阵或分组。
- 空间关系使用示意图或可定位对象。
- 真正存在步骤、方向、交互或路径时才使用节点、连线或流程结构。
- 叙事确实需要多个信息单元时在一个网页中组织场景；GIF 仍优先保留持续可见的标题、对象、坐标或其它上下文锚点。

时间型网页先把语义片段表写入场景计划。每个场景至少确定：

- `page_role`：当前场景负责开场、解释、证据、比较、步骤、数据、引用、总结还是行动提示。
- `content_shape`：当前信息实际是主张与支撑、时间变化、并列比较、关系网络、数据证据还是其它可描述结构。
- `layout_id`：从 `layout_contracts` 中选择能够容纳当前内容的结构；内容超过容量时先删减、重组或拆分场景。
- `duration_ms` 与 `steps`：当前场景需要多少阅读或运动时间，以及手动推进时在哪些语义状态停留。
- `asset_slots`：当前版式实际使用哪些图片、截图或视频帧槽位。

先完成“场景顺序 → 页面职责 → 内容形态 → 内容版式 → 选择理由 → 素材槽位 → 步骤”的计划，再实现当前 DOM 或 React 网页入口。场景数量和版式变化由内容推进决定，不为了显得丰富强制凑页数或轮换结构。开场负责建立问题或结果，中段按证据与解释需要推进，收束保留足够阅读时间。

选择内容版式后才处理图片。每个素材槽位在合同中声明比例、`cover` 或 `contain`、是否必须保留完整画面；场景把槽位绑定到实际 image 数据字段。截图、界面证据和必须完整展示的图使用 `contain`；照片或背景可以使用 `cover`，并在项目素材记录中保存焦点与裁切。生成图片时使用最终槽位比例和安全区，生成结果只承担视觉素材职责。

每个场景再选择自己的视觉命题和运动结构。只有内容本身表示持续监听、周期、反馈或其它重复事实时才在该场景内循环；方向性变化先完成演进，再在结果状态停留；反馈关系保留已经累积的结果；结论保留阅读时间。场景时间线负责进入、必要的局部循环、退出和跨场景转场，局部循环不越过当前场景。旁白或同期声进入下一信息单元后，网页也进入对应场景。

连线、箭头和穿过对象的线条只能表达已经明确的方向、因果、流向、对比或突破关系，并且起点、终点和穿越含义都能被观众读懂。没有这种关系时不用连线做装饰。每个旁白信息单元至少要有一个与句意对应的可观察状态；一句包含多个独立变化时拆成多个步骤，一大段只有标题换字时回到媒体文案或场景计划压缩内容，而不是把它硬做成简陋幻灯片。

运动承担主要表达时，先确定贯穿当前段落或相邻场景的运动载体，再实现局部效果。每个承担推进、因果、转折或兑现的场景都要能回答：开始时对象处于什么状态，哪个动作改变了含义，结果状态怎样被保留，前后场景靠什么承接，文字还需要补充什么。没有可见状态变化的场景只能承担结论、证据阅读或刻意停顿；不能用新的标题、卡片、截图和淡入转场冒充叙事推进。

先从最终需要读懂的结果态反推运动。准备动作只建立条件，主动作承担唯一的语义变化，依赖对象在主动作已经发生后重叠跟随，最后稳定到可读停顿；一段只保留一个注意力焦点和一个主要峰值。素材的运动服从它在画面中的实际质量与职责：界面、纸张、照片、数字、流体和空间对象不能共享同一套轻飘弹簧。没有语义原因的漂浮、呼吸、背景粒子和永动循环不用于“让画面活起来”。

多个场景可以共享一个持续可见的对象、坐标、底板、人物或空间，让前后关系自然承接；共享锚点只负责连续性，每个场景仍按当前信息选择循环、演进、比较、转场或停留。完整网页时间线只有在首尾语义等价且没有持续推进的旁白或结论时才整体循环。

连续创作组在同一预览中检查相邻场景。共享锚点不等于共享整套画面：相邻段落应根据新信息在构图、进入方式、素材职责或节奏中形成至少一种有意义的变化，避免只换标题、颜色和数据。这个判断由创作者观看连续结果完成，不用构图字符串数量、素材路线计数或机器审美分数代替。

`web-media-starter` 只提供 editable-media v6 清单、可编辑画布、场景播放、共享参数、导航控件、画布外通用编辑器、字体预设、BAT 本地预览和中性 DOM 示范；`react-media-starter` 只提供同一 v6 合同、绝对时间上下文、React renderer adapter 和可复现构建。`web-layout-templates` 只登记可以显式实例化的内容结构，不保存案例视觉。DOM starter 的编辑器从清单与页面语义标记自动建立文字、颜色、字体和其它样式分区，支持画布直接改字、下载当前数据、放大预览、恢复初始值和导出当前画布；当前作品只提供自己的字段、分区语义和视觉变量，不复制某张旧卡的字段表、配色或布局。当前内容的场景、内容版式、输出变体、参数、图表类型和叙事顺序必须重新判断；风格先继承项目档案或选择适用的内置制作配方，不沿用 starter 或参考图的表面结构。

重复字段构成的项目、工具或资源清单先按 `SKILL.md` 选择当前文字结构；需要确认共享列、容量或验收链时，先读清单式案例目录中已经提炼的机制和验证字段。结构化网页同时需要稳定阅读场景和时间场景时，只有项目明确采用相应案例视觉语言，才比较它的共享视觉核心。案例中的主题、条目数量、尺寸、配色、页面坐标和时间点都是案例取值，不替当前内容做决定，也不把案例恢复成独立静态卡入口。

## 二、结构化网页按层制作样稿

本节只适用于结构化网页、动画和其它已经明确需要样稿的高成本路径。

- **风格样稿**：新的或实质变化的方向使用当前真实内容和身份在目标比例的完整画布中呈现，检查字体、线条、颜色、纹理、图标、密度、重心、留白和光影；局部元素板只能辅助说明，不能代替确认。
- **构图样稿**：放入完整信息骨架，检查标题、主体、来源、安全区、层级和容量，不实现完整动效。
- **动效样稿**：在已确认构图中实现一个代表性场景及步骤，并提供播放、暂停、前后推进和时间定位。

样稿都在同一个网页真源中完成。需要方便查看时可以导出截图，但截图不成为编辑入口。必须在真实浏览器和目标画布尺寸查看网页，确认字体、图标和本地素材真实加载。先运行 `scripts/validate-editable-media.mjs` 检查清单、接口、场景合同、素材槽位、输出变体、播放链路、资源、图层和项目声明的量化规则，再查看它从同一网页捕获的场景截图；脚本通过不能代替人工判断内容和风格。样稿未确认时不批量导出媒体。

动效样稿标明它对应的语义片段、验证的运动类型和适用时间窗口。完整制作沿全量语义片段分别设计其它状态；样稿可以复用配方和组件，但它的短时长和局部时间线不作为全片结构。

动效样稿和完整预览都要做一次脱离逐句文字的运动检查：连续查看开始、关键变化和结果状态，确认观众能够从对象关系与状态演进看出哪里发生了推进。若联系表只呈现若干张标题不同、布局近似的静态页面，回到场景计划重做运动载体和状态变化，不用增加更多淡入、滑入或镜头晃动掩盖问题。

## 三、确定性动画接口

交互演示与导出动画必须能从同一已知状态重复播放：

- 等待字体和必要素材加载后再标记为可捕获。
- 能切换场景与步骤，并能播放、暂停、前后推进和定位到指定时间。
- 捕获模式隐藏按钮、调试信息、鼠标指针和画布外元素。
- 相同时间点产生相同的内容、位置、样式和数值。
- 循环动画自然衔接开始状态；非循环视频保留明确收束帧。
- 片段内循环在循环边界保持当前对象、状态和语义连续；方向性演进完成后保持结果，不跳回未发生前的状态。

每个场景的 `motion.complexity` 明确为 `static`、`simple` 或 `complex`，`driver` 明确为 `none`、`object`、`camera` 或 `mixed`，并用自然语言说明运动怎样帮助当前含义。复杂场景在制作完整过渡前先建立语义关键状态板：至少覆盖经实际内容决定的开始、一个或多个变化和结果状态，必要时再增加保持状态；数量由真实变化决定，不用固定张数或模糊完成百分比。清单中的 `step.review=true` 表示该状态必须由真实运行时定位并审阅，不能由消费端手写一张近似图代替。

镜头只在平移、缩放、视差或焦点变化确实帮助解释空间关系、注意力转移或前后状态时启用。静态场景使用 `driver=none` 与 `camera=null`；仅有对象显隐、数值或位置变化时使用 `object`，不为增加“电影感”套镜头。需要镜头时，`camera.root_layer_id` 和 `depth_layers` 必须指向不可手动编辑的外层包装，真实可编辑对象放在其内层，避免镜头与对象动画争夺同一个 transform。标题、字幕和其它必须持续清楚的 `readability_layer_ids` 放在镜头根之外，不能被景深模糊。镜头关键帧只引用当前场景的语义 step id，因此步骤时间仍是唯一时间边界。

运行时由 `setTime` 同时计算对象和镜头状态，`getCamera` 返回当前可复现的镜头、焦点与景深结果。`scripts/validate-editable-media.mjs` 对复杂场景逐个定位 `review=true` 的状态，两次读取同一时间确认确定性，检查外层镜头真实作用、可读性图层未被污染；指定 `--screenshot` 时还会从同一真实画布生成带 step id 的关键状态图。状态图用来审阅开始、变化和结果，不替代完整播放检查。

依赖悬停、滚动、随机数或不可控加载时间的效果改由主时间线控制；必须使用噪声或粒子时固定随机种子。同一状态不能由多个互不知情的计时器控制。

`setState` 接受清单允许的各场景覆盖值，`setTime` 使用整条时间线的毫秒位置，`setScene` 使用场景 ID 和可选步骤。`ready` 必须等待清单、字体和图片完成；`getPlayback` 返回当前模式、场景、步骤、场景时间和全局时间；`getBounds` 返回清单图层的当前像素边界。相同网页源摘要、场景状态、输出变体和时间必须产生相同画面。

网页的第一个可见包装节点必须唯一标记 `data-editable-media-root`，并声明 `data-composition-id="editable-media"`、`data-no-timeline`、总时长秒数、默认输出变体的宽高和帧率；媒体画布和预览控件都放在这个包装节点内，捕获模式隐藏画布外控件。运行时同时暴露 `window.__hf.duration` 和 `window.__hf.seek(seconds)`：它只是 `window.editableMedia.setTime(milliseconds)` 的秒级逐帧入口，不保存第二份时间线。本地渲染器、MediaFlow Pro 与 HyperFrames 都从这个入口定位，因此同一秒数必须得到同一场景状态和画面。timeline adapter 也只转发到这个入口，不能重写动画算法。

手动模式不启动自动时钟，前进和后退依次经过步骤与场景。自动模式连续经过全部场景。混合模式只自动推进当前场景，在场景边界停下。键盘、滚轮和触摸导航不接管输入框、按钮、链接、编辑状态或标记为 `data-editable-interactive` 的交互区域；查询参数能够直接打开指定输出变体、场景、步骤和时间。

## 四、从网页派生媒体

结构化网页先使用已有导出能力；没有时再使用读取同一画布和时间线的浏览器截图、逐帧捕获或录制方式。导出工具只负责捕获和编码，不重新实现内容。网页视频才在 MediaFlow Pro、本地渲染或用户明确选择的 HyperFrames 中使用一条已选路径，不在失败后静默换路。

- 静态图在指定时间或静态状态捕获目标画布。
- GIF 按固定帧率采样一个短而完整的循环，减少无意义帧和大面积随机变化。
- 无实拍视频从同一时间线导出无声普通视频或帧序列；需要供剪辑软件叠加的透明动效时，使用 `canvas.background_mode=transparent` 的输出变体，并让背景、HTML body 与媒体画布保持真实透明，再通过当前能力合同声明的透明视频或覆盖层格式导出，不预设容器和编码。旁白、音乐和字幕需要后期装配时，把网页画面交给视频时间线。
- HTML 演示直接使用手动或混合播放；需要变成视频时切换到自动播放并从同一时间线连续捕获，不复制页面内容。

当前环境无法稳定导出目标格式时，保留已经验证的网页真源并说明具体阻断，不另写一套平行绘图程序。

MediaFlow Pro 可用时优先使用本轮公开 CLI 声明的网页渲染、原生工程和导出能力；不可用时，普通网页视频和 GIF 仍从网页真源本地导出。独立代码动画明确选用 HyperFrames 时使用主入口已经加载的直接渲染能力。

## 五、完成条件

结构化网页完成时，网页包能按清单打开和修改；每个要求的变体、场景与 `quality.thumbnail.width` 实际展示预览没有乱码、替换字体、重叠、裁切、溢出、重复分隔线、错误层级或失衡空白，用户点名的派生物从同一活动真源导出并重新打开检查。

结构化网页完成时，网页能够按清单声明的方式打开，场景数据、视觉变量、内容版式、输出变体和播放状态分别从唯一位置修改；`scripts/validate-editable-media.mjs` 对要求的每个“输出变体 × 场景”通过，必需素材槽位真实绑定，播放方式按当前成品工作，网页与派生媒体保持一致。
