# 从内容真源到媒体方案

用于选择具体媒体、起草媒体文案、组织分镜或节目结构。它从已经确认的内容开始，不负责通读长材料筛选分享候选，也不主动研究事实缺口。

## 一、检查内容真源

制作前把当前允许使用的信息收拢为一个活动内容真源：

- 核心主张：受众最后应当记住的一个判断。
- 支撑：使主张成立的理由、事实、数字、例子、演示或经历。
- 必要语境：离开原材料后仍能理解所需的最少背景。
- 边界：会改变原意、行动或可信度的条件和未知。
- 来源：引语、数字、原始媒体和可核对位置。
- 素材：现有文字、图片、录音、实拍、录屏、字幕、品牌元素和参考样本。

内容真源已经由用户或上游 Skill 确认时直接使用。只有表达顺序不完整时可以重组；缺少核心主张、关键事实或第一人称经历时，指出一个会改变主体的缺口并停在确认，不用通用常识填补。

个人或系列内容已经由用户或上游确认时，活动内容真源再接收两个职责独立的输入：

- **观点取向（`editorial_position`）**：作者确认的判断、评价方向、信息取舍、主张边界及其来源。它决定媒体文案讲什么、强调什么和说到哪里。
- **表达方式（`voice_contract`）**：经过作者身份与版本验证的视角、推进方式、段落与媒体职责、幽默、结尾、稳定特征和当前样稿倾向。它决定选定内容怎样被说出来。

普通单次表达沿核心主张、支撑与边界继续制作。个人或系列输入存在时先完成观点取向，再完成实际表达；修改观点取向时重新检查信息选择和结论，修改表达方式时保持仍然有效的主张与证据。

同一来源准备派生多个成品，或者当前任务属于连续系列时，内容真源另外接收 `source_id`、`source_version` 与 `content_unit_id`。每个媒体项目建立自己的 `media_project_id`，保存当前 `media_script_version` 和实际导出物，并原样保留上游三项来源信息。来源版本变化后，按这组关系找到受影响项目，核对主张、素材和媒体文案后再继续制作或导出。单件、一次性任务不建立这组系列记录。

## 二、选择一个首选载体

先问“这段内容最依赖什么才能成立”：

| 主要依赖 | 首选载体 | 画面或声音承担的任务 |
| --- | --- | --- |
| 一个静态判断、定义、对比、框架或清单 | 图文卡片、封面或静态图表 | 一眼建立层级、分组和差异 |
| 状态、数值、位置、因果或反馈随时间变化 | GIF 或动态图解 | 原位展示变化、方向、数量和循环 |
| 代码画面承载多场景推进、逐步揭示或现场讲解 | 网页动画 | 用同一场景时间线支持手动演示、自动播放和连续导出 |
| 人物表达、故事、悬念、实拍演示或镜头推进 | 视频 | 保留人物、节奏、转折和现场信息 |
| 连续讲述、对谈、访谈或适合伴随收听的内容 | 音频或播客 | 用声音、停顿和段落维持理解与陪伴感 |

已有高质量素材会改变选择：人物表达有价值时保留实拍或原声；素材无法使用时，可以改写成原创口播、网页视觉或静态表达。平台比例、时长和生产成本只在相近方案中取舍，不让固定平台模板替内容做决定。

需要长篇连续论证才能成立的主题应交回文章或 Newsletter 流程。媒体可以承载其中一个独立内容单元，不能把整篇文章压缩成密集小字、快速朗读或连续口号。

## 三、先写媒体文案

媒体文案至少完成四件事。用户最终只要独立纯文字短帖、Thread 或短文案时，不进入本流程；帖子与当前媒体共同完成表达时才作为配套文字处理。

1. 开头让受众立即知道当前问题、反差、情境或收益。
2. 中间给出足以支撑主张的理由、例子、声音或演示。
3. 在合适位置兑现结论，不提前泄尽，也不拖延到问题意识消失。
4. 保留会改变理解的条件、来源和边界。

个人或系列内容先用 `editorial_position` 选择核心判断、评价方向和信息边界，再用 `voice_contract` 完成标题、口播、字幕、节目连接语和配套帖的实际表达。当前媒体的时长、开头任务、信息密度和情绪强度属于本次制作说明，不写回长期观点或声音输入。

按成品拆分：

- **卡片或动态图文**：标题、画面内最少文字、数据标签、来源短注和配套帖子。画面承担结构，配套文字补原因、语境、用途和边界，长度不预设。
- **视频**：标题或开头、口播、同期声位置、字幕文本、镜头或画面职责、结尾和配套帖子。字幕服务观看，不机械复制全部口播。
- **音频或播客**：节目承诺、开场、章节推进、主持或旁白连接语、片头片尾、节目说明、章节标题和必要转写。

文字与媒体共同完成一个表达。画面或声音已经讲清的部分不在配套文字逐句重复；文字无法讲清的空间、数量、状态或情绪关系再交给媒体。

先确定受众在关闭某个通道后还能理解多少。旁白承担主要解释时，单独听旁白应能回答“在讲什么、为什么会这样、结论是什么”；画面承担结构或演示时，制作说明明确标出必须观看才能获得的信息。口播的长度来自完成这项信息职责所需的内容，不从已有动效样稿、固定模板或先做出的画面倒推删减。

需要合成语音时，已确认的媒体文案仍是唯一语义真源，并从中派生两个用途明确的文本字段：面向听感的合成语音文本，以及面向阅读的字幕或画面文字。合成语音文本可以展开缩写、调整数字和符号的读法、增加发音停顿，但不能改变事实、数值、专有名词和原意；字幕与画面文字保持准确、简洁和可读，不照搬为发音服务的拼写。内容发生变化时先修改媒体文案，再重新生成这两个派生文本，不能分别修改到含义不一致。

用户已有确认文案时只做载体所需的确定性拆分。需要改变措辞、结构或声音时先说明修改范围，再由当前模型或用户点名的写作入口修订。

## 四、建立语义片段和运动结构

视频、GIF、动态图解、多场景 HTML、音频和播客先把全量媒体文案拆成语义片段。分段依据是受众当前需要理解的新信息，不按固定秒数、句号数量或画面模板切割。每段至少记录：

- 片段要新增的一个信息单元。
- 对应的旁白、同期声或静音范围。
- 画面或声音额外承担的理解任务。
- 运动或剪辑类型，以及开始、持续、变化和结束状态。
- 时长来源：文本估算、真实语音、原始素材或明确的固定规格。

运动结构按内容关系选择：

| 当前信息怎样成立 | 合适的时间结构 | 延长当前片段的方法 |
| --- | --- | --- |
| 持续存在的动作、节奏或环境状态 | 能回到等价状态的片段内循环 | 延长循环次数，保持上下文锚点 |
| 从分散到同步、从弱到强、从未知到结果 | 一次方向性演进，随后保持结果或进入稳定循环 | 延长演进前后的观察时间，不重置结论 |
| 行动产生反馈且后果不断累积 | 带累积状态的局部反馈循环 | 继续累积或在关键阈值停留 |
| 两种状态或方案需要比较 | 并列保持、交替聚焦或受控切换 | 延长可读停留时间 |
| 前后概念共享对象或结构 | 匹配变形、承接式转场 | 在共享对象上完成转换 |
| 结论、提问或行动提醒 | 稳定停留、轻微强调或声音留白 | 增加阅读与消化时间 |

真实录音或合成语音生成后，以最终音频的实际时长和语义时间标记更新片段边界。旁白推进到下一个信息单元时，画面也切换到对应职责；延长视频时只延长当前片段自己的动作或停留。完整时间线只有在成品本身就是无推进叙事的无缝背景时才作为一个循环单元。

代码生成网页把语义片段保存为场景，把需要用户逐次确认的信息状态保存为场景步骤。手动播放、自动播放和混合播放不改变语义片段本身，只决定时间由用户还是时钟推进。需要演示稿和视频两个结果时先完成这一份场景结构，再分别交互播放和连续捕获。

固定时长要求先影响内容取舍：保留使主张成立的最小完整链条，再修订措辞和停顿。小幅速度调整用于贴合已经接近的时长；明显压缩会降低理解时，回到文案或视觉结构调整。

## 五、把抽象内容转成视觉命题

内容的意义主要依赖观点、概念、反差或不可直接拍摄的关系，而数据、现有画面和具体空间关系又不能直接决定构图时，进入网页视觉或无实拍视频制作前先形成视觉命题。视觉命题说明观众通过什么可见关系理解当前内容，不把口播逐句改成插图，也不让风格名称代替画面意思。

视觉命题至少写清：

- 核心意思：观众最终应当看懂的一个判断或当前段落中的一个信息单元。
- 可见关系：哪些对象通过并列、连接、遮挡、变化、组装、分离、替换或其它动作表达这个意思。
- 必要对象：每个对象承担什么信息，删去后是否仍能理解。
- 状态顺序：开始、关键变化和结束分别呈现什么；静态媒体只写最终状态。
- 误读边界：哪些画面关系会改变原意，必须避免什么歧义。

短而集中的内容优先使用一个清楚的视觉命题；复杂内容可以拆成多个连续状态或场景，但每个状态必须新增可说明的信息。对象数量、具体动作、风格、颜色、比例和时长由当前内容、素材、用户要求及输出规格决定，不预设固定隐喻、固定数量或固定视觉风格。

内容本身已经提供明确数据关系、实拍动作、界面演示、空间结构或用户确认的视觉方案时，直接沿用，不为形式完整再创造隐喻。视觉命题会决定大部分构图且尚未确认时，把它作为最早未确认层交给样稿流程；用户只要方案时把它写入制作说明后停止，用户已经授权制作时交给对应网页或视频流程。

## 六、分镜和节目结构

只有时间型媒体才建立时间结构：

- GIF 使用一个短而完整的变化单元，保留持续可见的上下文锚点。
- 视频按问题建立、推进、转折、兑现和收束组织镜头；每个镜头说明它新增什么信息，并继承语义片段已经确定的运动类型和时长来源。
- 播客按听众在无画面时仍能跟上的逻辑分段，重要名字、数字和引用需要口头语境或节目说明承接。

分镜不等于把每句话配一幅插图。相邻画面没有新增信息时合并；内容只有一个静态关系时改用卡片，不为了动起来制造步骤。

## 七、参考样本

用户提供参考时分别提取：

1. 内容主张和素材。
2. 信息结构与节奏。
3. 视觉或声音风格。
4. 动效、镜头或剪辑方式。
5. 平台包装。

只使用用户明确点名或当前产物必需的层。视觉风格需要具体到字体气质、线条、形状、色彩、明暗、纹理、图标、密度、层级和留白；声音风格需要具体到语速、停顿、动态、空间、音乐和人声关系。样本采用流程图、霓虹、手写、快切或固定音乐，不构成当前内容也采用这些形式的理由。

## 八、交接到制作

进入制作前形成简短的制作说明：

- 成品与受众。
- 已确认媒体文案。
- 时间型媒体的语义片段、信息职责、运动类型和时长来源。
- 抽象内容适用时，已经确认或由当前授权允许继续制作的视觉命题。
- 画面或声音必须额外讲清的关系。
- 现有素材和禁止改动项。
- 制作真源、样稿层、输出规格和保存位置。
- 来源、版权和仍待确认的问题。
- 个人或系列内容已经启用的 `editorial_position` 与 `voice_contract`。
- 系列派生任务的 `source_id`、`source_version`、`content_unit_id`、`media_project_id`、`media_script_version` 和当前导出物。

用户只要方案时交付这份说明后停止；用户已经授权制作时把它传给对应网页、视频或音频流程。
