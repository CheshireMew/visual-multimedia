# 实际媒体制作的运行边界

结构化网页、素材处理、私人库、外部工具、视频、音频或复杂媒体导出进入实际制作时读取本文件。普通静态卡写入自包含 HTML 或用浏览器导出图片不读取本文件，也不检查媒体提供方；它只执行静态卡和导出说明中的轻量检查。

## 工具与动作边界

- 默认允许读取用户提供的本地内容与素材；开始制作前先估算新增与峰值字节，依次运行 `node scripts/media-task-workspace.mjs preflight --task-id <稳定任务-id> --expected-bytes <字节>` 和带相同参数的 `ensure`，只有单任务上限、全部任务产物上限和磁盘安全线都通过才建立 `artifacts/<task-id>/`。全部制作真源、项目、中间文件、预览、报告、渲染和成品都写入这里；可跨任务复用的大型缓存写入本机配置声明的有界缓存根，任务项目只记录缓存身份。结束时运行 `inventory` 与 `finalize`，按真实终态记录实际占用和清理候选；`review` 可列出全部任务、可审查清理候选和缺少旧清单的未知目录，但不会自动删除。
- 当前目录、活动仓库、输入项目和外部交付位置都不是生产根。项目命令接受相对任务、报告或输出路径时，一律相对 Skill 内显式项目根解析并拒绝越界；公共创建、渲染和导出入口还会拒绝 `artifacts/<task-id>/` 之外的路径。用户明确要求外部交付时，真实结果通过后只复制点名成品，不能把外部目录改成活动项目。
- 口播私人库只通过 `scripts/voiceover_reference_library.py` 初始化、接入、定位、保存和验证。正式根目录由用户指定；位于 Skill 目录内时只能使用已经从 Git 排除的 `口播私人库/`，不能与会发布的 references、scripts、assets 或案例混放。普通写作只运行只读 `show`、`voice-candidates` 和文本检索，明确的库维护请求才写入。
- 已经由主入口判定为结构化网页时，复制 `assets/web-media-starter/` 或明确选定的 React starter；`schemas/editable-media.v6.schema.json` 是唯一结构合同，清单、通用运行时、编辑器和预览启动器沿现有合同工作。starter 不决定当前内容、尺寸或风格，也不能被普通静态卡默认复制。
- editable-media v6 网页包必须自包含，并运行 `scripts/validate-editable-media.mjs` 检查要求的每个“输出比例 × 场景”；校验器只测结构、包边界、播放链路和已声明规则，不能代替人工检查。
- editable-media v6 网页必须同时暴露 `window.editableMedia` 与 `window.__hf.duration/seek(seconds)`；这些接口不适用于轻量静态 HTML。
- 复杂网页动画必须在 `scene.steps` 中标记由语义决定的开始、变化和结果审阅状态；`scripts/validate-editable-media.mjs` 从真实运行时逐状态定位并在指定截图时生成关键状态图。只有 `motion.driver=camera|mixed` 才允许 camera；镜头根与景深层使用不可编辑外包装，持续可读文字位于镜头空间之外，运行时通过 `getCamera` 暴露同一确定性状态。
- 图层的文字、颜色、位置、尺寸、旋转、透明度、层级、显隐和进出时间继续使用标准图层字段。只有回弹强度、错峰间隔、轨道半径、镜头幅度、触发阈值等确实影响一组对象或渲染算法、又不能自然归属于单个图层的控制量，才声明为带类型、范围、单位、控件、作用域和可动画能力的 `parameters`。全局默认值、场景覆盖和参数关键帧共同使用现有场景时间线；运行时通过 `getParameters` 暴露解析后的当前值，不增加第二套参数存储或时钟。
- 用户提供、项目自有、外部下载或项目内确定性生成的独立素材使用 `scripts/import-media-asset.mjs` 入账；普通视频、音频和角色工程继续进入通用 media-sources v3 素材账本，editable-media v6 网页包的 media-sources v4 素材账本必须在同一导入器中显式声明 `--pipeline browser|native-underlay|native-audio`，不能互相降级或猜测。外部生成服务的输出只能在费用、任务、回执、下载和校验合同通过后由正式任务管理器调用同一导入器本地化。入账后再由活动网页清单、视频时间线或音频项目显式采用；运行对应合同的校验器证明真实文件、字节数、哈希、权利、管线和代理等价关系与记录一致。代理只由 `scripts/create-media-proxy.mjs` 从已入账原片生成，并继承原片管线；消费者统一用 `scripts/resolve-media-representation.mjs` 选择预览代理或正式原片，不能散落保存第二份映射。
- 共享的创作者媒体、通用制作素材和完整网页包只通过 `scripts/media-resource-library.mjs` 建库、注册、查询、采用和晋升。注册版本不可变且没有全局默认；文件采用必须调用现有素材导入器进入项目 v3 账本，完整网页包采用后必须重新通过真实浏览器。采用和晋升分别用 `media-resource-adoptions.json` 与 `resource-promotion-candidates.json` 记录；原始日志、未确认反馈和一次性修补不得晋升。
- 项目或系列需要复用声音语言时只通过 `scripts/sound-production-profile.mjs` 建立、修改和校验 `sound-profile.json`。它只能引用 v3 素材账本中的真实 audio source id，并与视觉 `style-profile.json` 分开；最终视频或音频时间线仍负责实际逐轨采用和混音，声音档案不能成为第二条时间线。
- 人物表达的事实转写使用 `scripts/import-media-transcript.mjs` 绑定原始音视频及输入哈希，并在实际听音后由 `scripts/validate-media-transcript.mjs` 通过；上屏字幕和语义片段只引用或派生这份事实，不复制另一份逐字稿。需要 Faster-Whisper XXL 时只调用 MediaFlow Pro `describe` 当前声明的 `speech.transcribe`；返回的 SRT 和分段必须由 `scripts/import-media-transcript.mjs` 绑定原片哈希后才成为事实转写。长视频、录屏或关键区间不明确时使用 `scripts/make-video-contact-sheet.py`；它只读取真实素材并生成诊断联系表，不成为新的剪辑真源。选段另用 `scripts/validate-clip-selections.mjs` 检查原片、真实时长、重复、转写覆盖和已经完成的语义边界审核，联系表不能代替试听。
- 只有当前结构化网页、视频、音频或外部工具路径确实需要时，才用 `scripts/local-media-environment.mjs inspect` 检查对应能力。需要 MediaFlow Pro、HyperFrames 或全局声音时，本机配置才定位提供方和资源根目录；普通静态 HTML 不运行该检查。
- 本地视频与音频制作使用 `schemas/media-timeline.v1.schema.json` 保存产品无关活动时间线，并由 `scripts/media-timeline.mjs` 校验、检查和渲染；它不是 MediaFlow Pro 的简化替身。明确选择原生增强时，才经公开导入操作迁移到 `project.mfp`，迁移成功后不能继续让两条时间线同时充当真源。
- 新的或实质重做的长视频、混合视频、音频和播客用 `media-project-state.json` v3 保存通用五阶段、成果哈希、确认依据、合同入口、活动制作决策、阻塞项和下一步，并由 `scripts/media-project.mjs` 与 `scripts/validate-media-project-state.mjs` 读写同一状态逻辑。默认逐阶段展示真实成果并等待用户确认；只有用户明确授权全自动时才连续推进。具体 profile 不得建立第二套批准状态。上游变化只使受影响阶段和下游失效，未受影响的已确认阶段保留。状态不能复制内容或时间线。冻结审阅文件后用 `media-review.json` v3 绑定媒体哈希、不可变制作依据清单及摘要，并把每项承诺指回依据文件中的 JSON Pointer，再记录机器检查、完整观看和精确时间码问题；先完整审阅再修改，修改后重新建立依据并审阅。
- 综合样片之后的多场景或长时媒体只通过 `media-build-plan.json` v1 声明独立构建单元，通过 `media-build-report.json` v2 记录真实命中、渲染、连续音频母版和装配结果。缓存键只绑定当前单元的活动依赖、共享输出与生产模块；不能把整份上游合同哈希塞进每个单元造成一处变化全片失效，也不能让调用端自报一个未变化字符串冒充时间线事实。MediaFlow Pro 时间线由当前 `describe` 声明的 `export.sequence.build` 读取真实区间内容计算指纹，画面单元和整条音频母版分开缓存，确保局部重渲染不会破坏声音连续性。最终文件和构建报告已经用当前构建计划哈希闭合时，在启动浏览器、FFmpeg、能力探测或编辑器工程之前直接返回；缓存命中不能仍支付重型运行时冷启动成本。
- 二次元角色只通过 `scripts/anime-avatar-project.py` 建立、视觉审阅、注册和采用。自然语言中的角色名或别名由 `assets/anime-avatar-libraries/catalog.json` 解析到首选版本；例如“给视频添加夜希数字人”采用别名 `夜希数字人`，无需用户知道内部 id。项目必须位于本 Skill 的 `artifacts/<task-id>/` 内，角色媒体与本次语音都通过 v3 素材账本和真实哈希解析；没有用户点名的角色时不得暗选默认角色。
- 新角色先用 `assets/anime-avatar-prompts/master-image.md` 生成并确认母版，再用 `assets/anime-avatar-prompts/motion-source-video.md` 生成唯一连续校准视频。代码只负责完整解码、固定裁切、带帧号联系表和结构验证；Agent 必须直接查看完整人物帧和嘴部审阅图，标注 A/I/U/E/O/CLOSED、开口强度、连续闭嘴动作和自然过渡。不能用像素阈值、轮廓、聚类或代码推断代替视觉判断，也不能重绘嘴部或替换下半张脸。
- 用户同时提供录音、含原声视频或已经确认的声音文件时，必须提取并使用这条真实原声；用户给出的准确文本只用于转写校正和时间对齐，不构成重新 TTS、换声或变速授权。只有用户明确要求合成语音且没有指定必须保留的现成声音时，才可调用当前已授权且可用的语音入口。用户后来明确改选供应方式、声音、参考音频或语速时，以最后一次明确选择为活动真源，旧音频、时间标记、旁白包、口型计划和成片计划失效。使用 GPT-SoVITS v2Pro 时只调用 MediaFlow Pro `describe` 当前声明的 `speech.synthesize`，并提供确切参考音频、参考音频的准确文本与语言；原声和合成声都必须进入 v3 素材账本，记录实际音频、文本、时间标记、供应方声音身份和生成参数，并经实际听音复核；禁止通过拉长或减慢声音适配画面。
- `scripts/render-anime-avatar.py` 只能按 `plan → confirm-plan → render` 工作。v4 项目使用中等尺寸共享母版，v3 计划把逐帧路线和诊断按语义单元外置，用独立两帧 seam bridge 管理边界；确认后总计划不可变，渲染不重新选帧。缓存根目录只从本机配置读取并位于 D 盘；缓存键绑定单元局部语义与算法版本，完整计划仍绑定真实代码哈希。渲染同时输出完整角色轨和项目内 `avatar-track-clips.json`，后者用普通片段与唯一连续音频交给视频时间线，不能让消费者依赖缓存内部路径。
- 用户要求右下角等固定位置的圆形或方形角色窗时，用 `scripts/compose-anime-avatar-inset.py` 建立、验证和渲染 `schemas/anime-avatar-inset.v1.schema.json` 任务。Agent 从代表帧确定一次正方形裁切、窗口坐标和尺寸，所有帧复用同一组值；角色窗只负责固定裁切、遮罩、坐标和音轨装配，不补救坏角色轨。需要全程存在时角色轨必须覆盖完整时长，无声位置仍播放动态待机；只有用户明确要求时才提前隐藏。只采用底片音轨或角色音轨时默认保持 0 dB，只有明确混音才默认压低底片；初始化后检查任务中的解析增益。
- 采访原声讲解型视频由 `scripts/interview-explainer.mjs` 生产 profile 专用合同，由 `scripts/media-project.mjs` 管理通用阶段。项目必须位于本 Skill 的 `artifacts/<task-id>/` 内；只凭活动的 `interview-explainer@1.4.0` 解析 v2 draft 与 v2 plan，不读取旧项目计划、产物目录或任务脚本。内容确认后才能 `plan`，计划作为 direction 成果等待用户确认，真实综合样片确认后才能完整 `render`；render 输出作为 full-preview 等待确认，finalize 只提交最终阶段，不倒填历史阶段。`plan` 绑定 profile、真实素材、事实转写、复核选段、观众可见原声标题、原声分段译文字幕、旁白音频、时间标记、网页场景和规划/渲染脚本哈希；确认后渲染只消费计划，不重新选段、改字幕、改旁白、选画面或切换渲染路线。制作备注没有画面字段，不得进入成片。
- 素材解说型视频由 `scripts/source-video-commentary.mjs` 和活动的 `source-video-commentary@1.0.0` 生产。它只从项目内已确认完整解说稿、v3 素材账本、v2 片段选择、可选已听音转写、已试听旁白包和可选导演计划建立 production plan；每个 segment 独立选择 `narration-only`、`source-only` 或 `narration-with-source-bed`。源片入点与出点只读取 `clip-selections.json`，计划不复制；计划确认后投影为 portable timeline 和通用 media-build-plan。MediaFlow Pro 对应能力就绪时导入空原生工程并保存项目内工程快照，否则由同一 portable timeline 完整本地渲染。任一路线都先交付综合样片，再经全量预览、完整播放式 Agent 评审和最终交付收口。
- 该类型的旁白段使用各自独立的 `editable-media` v6 场景包和真实旁白时长，原声段使用素材账本中的原片、同期声和画面内来源时间码。每份计划通过公开 `project.create` 把计划的尺寸、帧率、色彩、位深和音频规格作为同一 `profile`，在 MediaFlow Pro 声明的默认工程根目录中创建独立网页捕获工程；调用端只使用返回的真实工程路径，不自行拼接、映射或复制工程目录。重新读取的主序列 profile 必须与计划一致；导入后只按真实 asset id 与 `source_hash` 绑定当前场景包，每个旁白片段使用当前计划帧数和 `source_in=0`。各片段随后进入按 `project_id` 稳定复用的装配工程，由 `export.sequence.build` 缓存画面单元和连续音频母版。烧录字幕由目标画布 `PlayRes` 的 ASS 渲染，并按构建单元落到画面后再装配；中文长句按安全宽度确定性换行，并与交付 SRT 分别绑定哈希。字幕交付方式由计划明确；选择 `sidecar` 时不得称独立 MP4 已经显示字幕。
- 采访原声讲解型的 `render` 先把 profile 计划投影成通用构建计划，再生成并哈希绑定完整预览与 v2 构建报告，最后把同一文件提交到通用 full-preview；`review` 分开记录机器检查、Agent 对同一成片的完整观看和用户确认，机器通过不能写成视觉通过。预览阶段确认后，`finalize` 只接受同一 MP4 哈希并提交 final-delivery；分阶段模式继续等待最终文件确认，批准后再次收口才要求权利、审阅和交付合同全部通过。
- 视频或音频导出后使用 `scripts/verify-media-delivery.py` 生成交付报告；`technical_ready`、当前成品哈希绑定的结构化完整审阅、权利复核和 `delivery_ready` 分开判断，正式交付不得只凭机器报告自动通过，也不得采用代理表示。
- Chrome、Node、Python、FFmpeg、FFprobe 或媒体编辑软件只有完成当前产物确实需要时才使用。缺少依赖时先报告具体能力缺口，不自动安装，也不另写一套与制作真源不一致的实现。
- 长时渲染、转写或合成命令超过调用端等待时间，只表示当前调用没有拿到终态。先检查真实进程、任务回执、输出文件、报告和完整解码结果；能够证明任务仍在运行时继续等待，已经成功时直接消费现有结果，只有确认任务失败且幂等边界允许时才重跑。不能因为超时盲目启动第二个相同任务。
- 同一个活动输出同一时间只能有一个写入者。预览、修订版和最终版使用不同路径；长任务先写唯一临时文件，完整解码和哈希完成后再原子移动到目标路径。重跑前检查现存进程与临时文件，不能让两个 FFmpeg、语音或渲染任务同时写同一个文件，也不能覆盖最后一个已经可播放且获确认的版本。
- 用户明确要求合成语音或点名 EdgeTTS、GPT-SoVITS 等声音入口后，可以调用当前环境已经可用的对应服务生成声音；安装可选组件只通过 MediaFlow Pro 的组件界面并保持单独授权，克隆特定真人声音和获取额外付费服务继续按各自动作边界确认。
- 用户只要求建议、文案、分镜或剪辑方案时不创建网页、不处理素材、不导出媒体。
- 账号操作、上传、发送和发布始终需要单独授权；完成媒体文件不等于获得发布权限。

## 停止条件

- 只要载体建议：首选载体、理由、所需素材和下一步已经清楚时停止。
- 只要媒体文案：已经完成所选动作。只审查时已区分保留项、根因和代表性症状且没有擅自改稿；新写或改写完整口播时已经经过材料净化、声音取证、创作参考、事实核查和根因回读，纯正文符合内容真源、受众与载体时停止。
- 要口播私人库操作：唯一根目录能够从本机配置重新定位；用户要求的声音真源、完整案例或钩子已经写入唯一 Markdown 真源，声音资格、索引与真实资源一致，并返回实际路径时停止。
- 只要样稿：用户点名的样稿层已经在正确真源中可见、可播放或可听时停止。
- 要完整媒体：活动真源可修改，网页清单和实际页面一致，指定成品真实生成、被最终工具读取并通过一致性检查后停止。多场景网页必须证明场景和步骤确实切换，手动、自动或混合模式按当前交付工作；多比例项目必须逐个检查用户要求的输出变体；正式视频或音频必须由 `final` 交付报告分别证明技术就绪、人工完整审看和权利复核；Live Photo 必须按其 reference 到达实际授权范围内的完整验证层级。
- 要参考视频复刻或对齐：真实参考区间、候选区间和还原层级已经明确；精确回放与参数化重建分别交付；当前层级要求的资产、运行时、逐帧交付证据和人工观看全部完成，只声明证据实际证明的层级时停止。
- 要新的二次元口播视频：注册角色资源或完成新角色素材库，验证真实语音时间轴，生成并确认不可变计划，渲染覆盖目标时长的完整人物轨；机器报告、Agent 完整观看和用户确认分开记录。用户还要求角色窗时，固定裁切合成并完整观看最终视频后停止。
- 只要求建立角色复用链路：注册表、版本化角色包、v3 素材账本、真实哈希、固定裁切、AI 视觉口型库和审阅证据全部通过，且一个全新的 Skill 内任务项目能用角色名或别名解析并加载同一资源后停止。
- 要完整的采访原声讲解型视频：Skill 内任务项目已经由活动 profile 建立，原片、事实转写、语义选段、真实旁白与时间标记通过检查；不可变计划已经确认；正式生产者生成成片和构建报告；机器检查、Agent 完整观看、权利复核和所需用户确认分别绑定同一成片哈希；`finalize` 生成可用交付报告后停止。
- 要完整的素材解说型视频：Skill 内任务项目已经确认完整解说稿、逐段声音职责、真实源片 selection、旁白与字幕来源；综合样片和全量预览按五阶段确认；交付同时绑定 portable timeline 或 MediaFlow Pro 原生工程、素材与片段合同、真实构建报告、完整评审和最终文件，不把单独 MP4 或远程任务状态写成项目完成。
- 要修改：修改活动真源并更新用户点名的派生格式后停止，不扩张成其它比例、平台版本或发布方案。
- 用户要求停止或否定方向时立即停止制作，说明当前保留项和最早未确认层；未获继续授权不生成替代版本。

## 交付前检查

- 内容真源是否足以支撑媒体，没有补写未经确认的事实、经历或立场？
- 个人或系列内容是否分别落实已确认的观点取向与表达方式，视觉制作配方是否只承担画面与动效职责？
- 系列派生成品是否能够回到准确的来源版本、内容单元和媒体文案版本？
- 首选载体是否由内容关系和素材决定，而非固定偏好某一种形式？
- 是否先完成媒体文案，再决定视觉、声音、分镜和剪辑？
- 完整口播是否走唯一的 `voiceover-writing` 路径，轻量媒体文字是否留在确定性派生路径，没有重新形成两套写作流程？
- 是否把当前指令、声音样稿、口播声音真源和合格声音候选与完整案例、钩子分开使用，没有用题材相似或 AI 草稿冒充作者声音？
- 私人库可用时，是否实际打开了多份相关全文和钩子来源；声音候选是否按成品语境与资格查找，而没有按主题词模仿？
- 私人库写入是否只由用户明确要求触发；声音真源、完整口播与独立钩子是否由各自入口保存，并由各自索引读取？
- 成稿是否先核查正文事实，再从内容贡献、结构关系、作者与听众、句子听感依次回读；是否处理了问题根因而不是机械替换典型句式？
- 社交卡、封面和轮播图是否有清楚的逐页职责、版式容量和缩略图检查，多比例版本是否分别重新构图？
- 使用照片、截图、生成图、声音或视频帧时，是否通过 v3 素材账本保存真实文件哈希、来源、授权、生成过程、声音身份、主体位置和各输出变体裁切，并由消费者显式采用；代理是否直接关联原片、通过真实等价检查且没有进入正式交付？
- 使用注册媒体资源时，是否绑定不可变库版本，并证明文件经正式导入器进入项目账本或完整网页包被消费者重新验证；注册表、采用记录和项目消费者是否没有各自保存第二份素材事实？
- 时间型媒体是否已经按语义片段分配旁白、画面和运动职责，代码网页是否把它们落实为场景和步骤，最终时长是否来自完整内容、真实声音或明确规格？
- 多场景 HTML 是否仍使用同一网页动画真源，播放方式是否只控制时间推进，没有复制成另一套演示内容或运行时？
- 循环是否发生在当前语义片段内部，方向性变化是否保留演进和结果状态，画面是否随旁白推进？
- 复杂代码动画是否由真实内容确定了开始、全部必要变化和结果审阅状态；镜头是否只在帮助解释时启用，镜头外层、对象内层和持续可读文字是否各有唯一控制边界？
- 无实拍或代码动画中承担推进、因果、转折和兑现的语义片段，是否有连续运动载体和可见状态变化，而不是只有标题、卡片或截图轮流出现？
- 参考复刻任务是否绑定了真实参考区间和明确还原层级，精确回放与参数化重建是否分开，逐帧机器证据与实际观看是否共同支持当前声明？
- 图文卡片及其它代码生成视觉是否确实以网页为可编辑真源？
- 网页清单是否真实提供场景、步骤、播放方式、内容版式合同、输出变体、默认数据、主题、资源和质量规则，HTML 是否已经移除同名重复配置？
- 用户要求的每个“输出变体 × 场景”是否通过 `scripts/validate-editable-media.mjs`；长或不明确的视频素材是否通过真实联系表选择区间，并另行完成真实区间、去重和完整语义审核？
- GIF 是否用动画解释变化；内容不属于流程时是否避免自动做成流程图？
- 已有实拍是否从后期时间线开始，没有扩张成拍摄和制片计划？
- 合成语音是否保留已确认文案、合成文本哈希、供应方声音 ID、声音名称、生成参数、原始音频哈希和实际时长，精确声音缺失时是否停止而非静默换人？
- 使用 MediaFlow Pro、Faster-Whisper XXL、GPT-SoVITS 或全局声音时，是否从唯一的本机配置冷启动；点名声音是否唯一解析并核对真实音频、准确文本与哈希；操作是否先由本轮 `describe` 摘要发现、再读取选中操作的精确合同，`runtime.inspect` 是否报告对应组件可用，真实输出是否被项目合同消费者读取？

- 二次元角色素材是否来自一张用户确认的母版和同一角色的唯一连续固定机位校准视频；两者是否经 v3 素材账本解析到真实哈希；固定人物裁切与嘴部审阅裁切是否应用于整段视频？

- 新语音是否使用准确逐字稿、真实音频 source id 与 sha256、明确静音裁切和已听音复核的 v2 时间轴；是否没有拉长、减速或重写语音？`render-plan.json` 是否在确认后保持不可变，渲染是否没有重新规划？
- 采访原声讲解型是否确实符合进入条件，而不是把普通访谈、纯混剪、人物故事或其它视频强行套进一种结构？
