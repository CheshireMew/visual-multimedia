# 单图二次元口播形象

## 这条流程解决什么

这条流程把一张全新二次元角色图，或一份已经确认的角色设定，变成可以反复用于中文口播的无骨骼素材库。它不要求 Live2D、图层拆分、单独嘴部贴图或逐帧重绘，也不把真人数字人模型当作默认路线。

最终运行链只有一条：

`已确认母版 → 同一母版生成的唯一连续校准视频 → AI 视觉标注的 A/I/U/E/O/CLOSED 素材库包 → 项目按角色名、别名或注册 id 引用 → 绑定真实音频哈希的已复核中文时间轴 → 不可变分段计划 → 中等尺寸共享母版 → 局部角色片段与连续音频 → 按需装配完整角色轨或固定角色窗`

当前台词、语音、时间轴、计划和输出属于可变项目数据。角色身份、母版、校准视频、角色专属裁切和口型帧属于一个版本化的角色素材库包；新角色建库时它先位于项目内，来源与使用权确认、视觉标注和质量门通过后，可以经注册入口迁入 Skill 的共享只读资源库。Skill 不保存某次台词和运行输出，也不把任何已注册角色自动当作默认。

## 能力边界

- 当前内置口型映射面向普通话，使用 `A / I / U / E / O / CLOSED` 六类视觉口型和每类 `0–4` 的相对强度。其它语言需要另建语言到视觉口型的映射，不能直接声称等价。
- 输出使用校准视频中的完整人物画面。嘴、下巴、脸颊、头发、耳朵、饰品和肩膀来自同一源帧，不局部重绘、不拆部件。
- 目标是“看起来大体对得上，同时保持连续自然”，不是逐音素达到影视级精确唇同步。报告必须分别给出音节核心口型命中率、全帧匹配率、跳转次数和人工完整观看结果。
- 一套通过质量门的角色库只建立一次。更换台词或音频时只建立新的 `speech-timeline.json` 并重新渲染，不重新识图、重新分类或人工指定大张口帧。
- 角色身份资源与渲染算法参数分开。注册包保存母版、校准视频、裁切和视觉标注；项目 v4 默认生成 `384×384 / 24fps` 的中等尺寸母版，并按最长约 24 秒的语义区间缓存。最终窗口多大、圆形还是方形属于视频构图，不回写角色库。
- 母版或校准视频需要调用外部图像、视频生成服务时，遵守当前授权边界。用户只要提示词时交付提示词后停止；用户要求完整制作且工具已获授权时才代为提交。

## 先判断用户处在哪一层

| 用户现有内容 | 从哪里开始 | 本轮合理停止点 |
|---|---|---|
| 只有角色文字设定 | 先确认角色规格，再生成母版候选 | 用户确认一张母版，或继续完成校准视频 |
| 有一张角色图 | 检查能否直接做母版；不符合时以它为唯一身份参考重绘 | 用户确认母版 |
| 有母版，没有校准视频 | 给出或提交 15 秒校准视频提示词 | 收到并检查校准视频 |
| 有校准视频，没有素材库 | 抽帧和联系表，AI 视觉标注，验证素材库 | 素材库通过质量门 |
| 想复用已有角色，但还没有项目 | 先列出已注册角色，再按角色名、别名或稳定 id 采用首选版本 | 新外部项目实际解析到共享只读素材库 |
| 旧项目已有可复用母版、校准视频和口型库 | 运行一次性迁移，登记来源、版本和审阅证据 | 注册表能列出，新项目能采用；旧项目保持原样 |
| 有素材库和新文本，没有现成声音 | 用户明确要求合成语音后，生成 TTS 与供应方时间信息，再规范化语音时间轴 | 渲染并检查口播视频 |
| 有素材库和现成录音或含原声视频，也给了准确文本 | 原声优先；文本只用于校正转写和时间对齐，不重新 TTS、不换声、不变速 | 渲染并检查口播视频 |
| 有口播形象视频和底片 | 回到常规视频时间线 | 完成圆形或方形窗口合成与交付 |

用户要求从零完成时，不把“先给提示词”误当成最终交付。母版确认是唯一必须由用户决定的高影响身份检查点；之后按授权继续生成校准素材、建库、合成和验收。

## 项目真源

可变角色媒体项目必须建立在 `visual-multimedia` Skill 源码目录之外。这里的限制只阻止项目把语音、计划、报告和输出反写进 Skill，不禁止 Skill 保存正式注册且只读复用的角色资产。

先查看当前可用资源：

```powershell
python scripts/anime-avatar-project.py list-libraries
```

命令读取 `assets/anime-avatar-libraries/catalog.json`。`default_library: null` 表示没有默认角色；资源出现在列表中只表示可以被显式采用。

从已注册角色建立项目时执行：

```powershell
python scripts/anime-avatar-project.py adopt-library `
  --project <全新项目目录> `
  --library <角色名、别名或注册 id>
```

注册表把角色名和别名解析为稳定 id，并在未指定 `--version` 时采用该角色的 `preferred_version`。例如用户说“给视频添加夜希数字人”，入口直接采用别名 `夜希数字人`，不要求用户知道 `yexi@1.0.0`。项目只保存 `{kind, id, version}` 引用，不复制母版、校准视频或口型库。

从零建立新角色时执行：

```powershell
python scripts/anime-avatar-project.py init `
  --project <项目目录> `
  --character-id <稳定小写 id> `
  --character-name <角色名> `
  --origin reference-image `
  --specification <角色规格文本文件>
```

完成母版、校准视频、AI 视觉标注和素材库质量门后，项目内角色包仍是候选资源。只有用户确认要长期复用时才注册：

```powershell
python scripts/anime-avatar-project.py register-library `
  --source-project <项目目录> `
  --version <x.y.z>
```

注册命令重新读取真实母版、校准视频、素材哈希、口型库和审阅证据，写入共享只读资源及活动注册表，且不改变 `default_library`。

四个根目录的职责固定为：

- Skill 源码：方法、schema、脚本、提示词，以及 `assets/anime-avatar-libraries/` 中已注册、版本化、只读的共享角色资源。
- 角色媒体项目：本次任务的 `avatar-project.json`、语音账本、时间轴、计划、工作文件、报告和输出。
- 角色素材库包：项目内候选包或 Skill 内注册包；保存角色身份、母版、校准视频、裁切和口型标注的唯一真源。
- 配置中的 D 盘缓存根目录：按真实内容保存可复用的中等母版、连续音频、单元计划、角色片段和两帧接缝桥；它不是项目真源，也不进入注册表。
- 任务产物：项目内保存计划、可移交片段、报告和成片；消费者不能直接依赖缓存内部目录。

项目和素材库包中与本流程有关的权威文件是：

- 项目 `media-sources.json`：本次语音、底片和最终输出的唯一真实素材账本。
- `avatar-project.json`：只保存素材库引用和本次渲染规格；v4 不复制角色、校准视频和口型库路径，活动读取器不再接受旧项目合同。
- `library-package.json`：角色身份、版本、状态、能力事实、母版与校准 source id、角色专属裁切、参数来源、验证和迁移来源。
- 素材库包 `media-sources.json`：母版与校准视频的唯一素材账本。
- 素材库包 `visual-viseme-library.json`：AI 视觉标注得到的可复用口型与连续动作区间。
- `speech-timeline.json`：一段具体音频的确认文本、音频 sha256、原素材裁切和以裁切后音频起点为零的逐字时间边界。
- `plans/anime-avatar/<计划 id>/render-plan.json`：v3 不可变分段总计划；顶层只保存输入与代码哈希、单元边界、各单元计划制品、两帧接缝桥和确认状态，逐帧数组留在带哈希的单元制品中。
- `reports/avatar-renders/<任务 id>/avatar-track-clips.json`：项目内可移交的连续片段清单。每个 core 与 seam 都有精确起始帧、时长、文件和哈希；旁白是唯一一条连续 WAV。普通视频与采访视频都把这些文件当作普通时间线素材，不读取角色缓存内部结构。
- `avatar-insets/<任务 id>.json`：某一条成片可选的角色窗形状、固定裁切、位置、尺寸、边框、阴影、出现时间和音轨选择。
- `reports/avatar-source-review/`：供 AI 视觉检查的原始联系表。
- `reports/avatar-library-review/`：由已经完成的标注反向生成的类别、强度和连续动作审查图。
- `reports/avatar-renders/<任务 id>/`：目标口型、实际选帧、切换和技术检查报告。
- `reports/avatar-insets/<任务 id>/`：最终角色窗的联系表和合成报告。

不在 `avatar-project.json` 重复保存角色、裁切、文件路径、哈希、生成供应方或权利信息。注册资源由 id 与版本解析到唯一 `library-package.json`；实际文件和来源再由素材库包自己的 `media-sources.json` 解析。不要把某次台词或某个音频写进角色库。

Skill 仓库可以保存已经注册的具体角色包，但不能保存这个角色某次口播的语音时间轴、`plans/`、`working/`、渲染报告或成片。初始化器与采用入口都会拒绝把可变运行项目建在 Skill 目录内；正式资源检查会从注册表验证包、素材哈希、视觉口型库和审阅证据，不遍历 `artifacts/` 并把旧任务误认成活动资源。

旧版 v1 项目只能由独立迁移入口读取：

```powershell
python scripts/anime-avatar-project.py migrate-library `
  --source-project <旧项目目录> `
  --library-id <注册 id> `
  --display-name <角色名> `
  --version <x.y.z> `
  --confirm-closed-motion-exhaustive-review
```

最后一个参数不是绕过检查：只有 Agent 已完整查看旧源视频与嘴部联系表，并确认旧库没有在达到三段闭嘴后提前停止，才允许传入。迁移再验证旧素材哈希、真实校准视频、口型帧合同和审阅证据，写入 v3 素材账本、v3 视觉口型库、版本化包和注册表；正常项目只接受当前版本，不保留旧运行兼容分支。旧项目不会被删除或覆盖。

`avatar-insets/<任务 id>.json` 不属于角色身份或口型库。相同角色进入不同底片时，窗口大小、位置和声音关系可以各自变化；角色库保持不变。

## 从零建立一个新角色

### 1. 形成角色规格

只有文字设定时，先把以下内容写成项目级角色规格：年龄感与气质、脸型和五官比例、瞳色、发型与发色、动物耳或其它轮廓特征、不可丢失的发饰、服装、关键胸前饰品、色彩、线条和上色方式。只记录用户确认的身份事实，不从参考风格推导新设定。

有参考图时，先检查身份元素是否清楚。参考图可以是倾斜姿态、透明底或全身图，但下游母版必须重新满足固定的头肩构图。参考图进入素材账本，生成母版时是唯一人物身份参考；不要同时加入风格相近但身份不同的人物图。

### 2. 生成并确认母版

初始化命令会把 `assets/anime-avatar-prompts/master-image.md` 复制到项目 `prompts/`。把角色规格和参考方式填入模板后使用。

合格母版必须同时满足：

- 正方形、高分辨率、正面自然头肩构图；头部直立、双肩基本水平、视线看向观众。
- 猫耳、呆毛、发梢、发饰、肩部和胸前关键饰品都在安全边距内。
- 服装在整条画面底边连续铺满。以后使用圆形裁切时，圆弧底部必须仍是衣服，不能露出白色楔形、黑角或截空。
- 纯白不透明背景，背景无渐变、阴影、光晕、暗底残留和抠图毛边。
- 眼睛自然睁开，嘴自然闭合或只有极浅微笑。母版不承担口型素材。
- 线条清楚、稳定的日系二次元赛璐璐上色；无糊化、涂抹感、双重五官。
- 没有圆框、边框、定位点、锚点、辅助线、字幕、文字和水印。

检查母版时看整张图，不只看脸。身份、底边衣服覆盖和轮廓安全区任何一项失败，都在母版层重做；不要期待后续裁切或定位脚本补救。

母版经用户确认后作为 `master_source_id` 写进项目内 `avatar-library/library-package.json`，状态改为 `confirmed`。母版一旦变化，原校准视频和原口型库全部失去身份依据，必须重新生成；不要保留兼容到旧母版的混合库。

### 3. 生成 15 秒校准视频

使用 `assets/anime-avatar-prompts/motion-source-video.md`。母版必须是视频首帧和唯一人物参考。推荐校准语音是两轮短促而完整的：

> 嗯。啊。咿。呜。诶。哦。……嗯。啊。咿。呜。诶。哦。

它不是最终口播，职责只是为同一人物收集六类视觉口型和连续细节运动。每个音节只完成一次自然的“闭合或弱开 → 发音峰值 → 回落”，不能把一个元音持续喊很久，也不能快速反复开合。

15 秒的推荐节奏与正式提示词保持一致：

- `0.0–0.8s`：闭嘴自然停留，保持轻微呼吸。
- `0.8–6.5s`：第一轮中等幅度 A/I/U/E/O，每个音节短促完成并回到闭嘴。
- `6.5–7.5s`：闭嘴停留，可有一次自然眨眼。
- `7.5–13.2s`：第二轮完整幅度 A/I/U/E/O，身份和构图不变，只允许不同的微表情、发梢或耳朵细节。
- `13.2–15.0s`：闭嘴收尾，动作继续但逐渐稳定。

两轮的意义是为同一口型提供不同但连续的头发、耳朵、眼睛、饰品和肩部运动，减少新台词中的机械重复。视频不需要覆盖所有音素排列；运行时保留全部音节核心作为依据，再让过密核心进入可追溯的协同发音 cluster，以主核心和连续动作共同决定实际呈现。

合格校准视频必须固定机位、固定构图、固定缩放和固定人物底部。允许的生命感是克制而连续的眨眼、呼吸、眼神微动、发梢滞后、呆毛小摆动、猫耳偶尔小幅反应和饰品轻微惯性。头部大幅摇摆、点头、身体漂移、镜头运动或自动重新构图都会在换口型时放大成跳变，发现后直接重做校准视频，不用后期坐标追踪掩盖。

纯白背景可以直接保留，不需要抠图或绿幕。生成器自行加在底部的字幕不属于素材；在 `source_crop_xywh` 中用一个固定裁切排除字幕，但不能裁掉耳朵、呆毛、肩膀或底边衣服。

### 4. 先看素材，再建立视觉标注

把母版和校准视频导入项目内素材库包的素材账本后，用公开入口一次绑定身份与固定裁切：

```powershell
python scripts/anime-avatar-project.py configure-source `
  --project <项目目录> `
  --master-source-id <母版 source id> `
  --motion-source-id <校准视频 source id> `
  --source-crop <x,y,width,height> `
  --mouth-review-crop <x,y,width,height>

python scripts/anime-avatar-project.py prepare-review --project <项目目录>
```

脚本只做以下机械工作：

- 用 FFprobe 读取真实帧率、尺寸和时长。
- 按固定裁切抽取带帧号和时间的整帧联系表。
- 按项目中人工指定的嘴部审查区域生成高频局部联系表。
- 保存抽样清单，确保之后的视觉判断可以回到原视频帧。

它不得通过像素阈值、嘴部轮廓面积、人脸关键点、聚类或图像差分推断口型或强度。

Agent 必须直接查看联系表，必要时再查看原始单帧，并写出 `visual-viseme-library.json`。视觉分类依据是口唇形状，不是嘴洞面积：

- `A`：纵向明显、较放松的开口。
- `I`：嘴角横向展开，开口较浅。
- `U`：紧凑、前收、圆或短圆缝；`U4` 仍可能很小。
- `E`：较宽的横向开口，强级别可看到明显口腔和舌面。
- `O`：纵向圆形或高椭圆，不能和横向的 E 混淆。
- `CLOSED`：双唇闭合或自然微笑线，没有可见口腔。

每条动作内部的 `0–4` 阶段只描述它从低口型到自身峰值再回落的相对进程。另用 `peak_strength_level`（`1.0–4.0`）描述这条完整动作的发音力度，以便同一元音的中等幅度 take 和完整幅度 take 按音频强弱选择。不要把 `U4` 和 `E4` 当作几何尺寸相同的嘴；`U` 的完整力度仍可以是很小的前收圆口。

标注时必须给出：

- 覆盖整条校准视频的 `runtime_state_spans`。
- 穷尽标注源视频中所有视觉上成立、具有连续自然次级运动的闭嘴区间；开头、中间和结尾各一段只是最低覆盖门，不是找到三段就停止提取的数量目标。
- 每类元音至少一条视觉成立的完整动作；素材实际存在第二条独立 take 时全部标出。不能用复制 take 或修改数字满足数量。
- 每条 gesture 必须标注 `peak_strength_level`；若两条 take 实际力度相同就如实写相同值并在验证报告中显示缺少强弱变化，不能只凭“take 1 / take 2”假定它们一弱一强。
- rise、fall 各五个代表帧，对应强度 `0–4`。
- 所有阶段帧都必须真实位于 `[start_frame, end_frame_exclusive)`；`fall_frames_by_intensity[0]` 必须就是 `end_frame_exclusive - 1`，不能用不存在的 exclusive 边界充当审核帧。
- peak 的连续帧区间，以及适合人工复核的代表帧。
- 原视频中自然存在的元音到元音相邻过渡区间。`CLOSED` 与元音之间由各动作自身的低口型入口或出口承接，不登记成只靠状态名猜测的 natural span。
- 实际查看过的联系表、标注日期和判断说明。

标注完成后运行：

```powershell
python scripts/anime-avatar-project.py validate-library --project <项目目录>
python scripts/anime-avatar-project.py render-library-review --project <项目目录>
```

校验器只检查协议、source id、真实帧率、帧边界、覆盖、重叠、类别、闭嘴动作、自然过渡和 AI 已标注的强度事实；它不重新判断视觉标签，也不把某个数量标签包装成自然度结论。

然后 Agent 必须查看 `reports/avatar-library-review/` 中的类别强度表、E/O 对比、闭嘴表、每条 rise/peak/fall 连续条带和每条自然过渡条带。自然过渡要同时检查头肩姿态、眼睑阶段、视线，以及头发、耳朵、呆毛和饰品的运动方向；只看切口两张静帧不算完成审核。分类或过渡错了就改标注真源，不在渲染器里添加角色专属例外。

## 为一段新语音建立时间轴

先确定声音真源。用户已经提供录音、含原声视频或确认的声音文件时，后续所有处理必须绑定这条原声；即使用户同时给了准确台词，也不能把台词解释为重新合成声音的授权。只有用户明确要求 TTS，且没有另一条必须保留的现成声音时，才进入文本转语音。

### 文本转语音

用户明确要求合成语音后，按 SKILL 已经路由加载的语音合成流程生成原始 TTS，保留确切合成文本、声音身份和供应方返回的时间信息。优先使用供应方的 word/character boundary；把它规范化为 `schemas/speech-timeline.v2.schema.json`。

使用当前环境已有的 EdgeTTS 且已经获得调用授权时，可直接运行：

```powershell
python scripts/synthesize-avatar-speech.py `
  --text-file <UTF-8 合成文本> `
  --voice <准确声音 id> `
  --audio-source-id <准备写入素材账本的 id> `
  --output-audio <原始 mp3> `
  --output-timeline <speech-timeline.json>
```

脚本会同时保存供应方的原始 `WordBoundary`。当一个供应方边界包含多个汉字时，它只在该真实边界内部依据音频低能量点细分，不把整句平均切开。新时间轴故意以 `timing.reviewed=false` 写出；试听并确认逐字边界后改为 `true`，再把音频以同一个 source id 导入 `media-sources.json`。精确声音不存在时停止，不能静默换声。

用户明确要求使用已授权参考音频克隆声音时，通过 MediaFlow Pro 本轮公开的 `speech.synthesize` 生成并验证真实 WAV，再用返回的参考音频哈希建立稳定声音身份并导入同一个 v3 素材账本。`scripts/synthesize-avatar-speech.py` 仍只负责 EdgeTTS 的供应方边界，不包装 GPT-SoVITS，也不伪造它没有返回的逐字时间。GPT-SoVITS 音频必须以准确目标文本完成音频对齐和逐字听音复核后，才能写入正式 `speech-timeline.json`。

如果其它供应方只返回句级或词级时间，不要把整句平均分给每个字然后直接正式交付。可以用音频对齐工具细化，但必须以确切合成文本为准，并听音复核明显边界。

### 用户录音或视频中的声音

先确认逐字稿，再确定需要裁掉的前置静音和尾部。自动转写只能作为起点；转写结果与用户确认文本不一致时，以确认文本为准重新对齐，不能让错误 ASR 文本进入口型渲染。

`speech-timeline.json` 中：

- `trim_start_seconds` 和可选 `trim_end_seconds` 针对原素材。
- `audio_sha256` 必须与素材账本中的真实音频一致。
- `time_origin` 固定为 `trimmed-audio-start`。
- `units` 的时间从裁切后的 `0` 开始。
- 每个普通话汉字是一项，顺序必须与 `text` 去除标点后的汉字完全一致。
- `timing.reviewed` 正式渲染前必须为 `true`。

录音开头的无声区间要先判断是否属于成片节奏。需要去掉时，实际听音或看波形后把裁切写入时间轴，并让所有字时间相对于裁切后音频；需要保留时不裁切，第一字仍写真实起音时间，角色在此前自动播放闭嘴动态待机。

正式规划前运行 `scripts/validate-avatar-speech-timeline.py`，并传入 `--require-reviewed`。它会从项目素材账本重新解析真实音频、核对 sha256、裁切范围、文本顺序和逐字边界；只输出验证报告，不重写时间轴。

## 从素材库合成新口播

先生成一次性分段计划。新建 v4 项目默认使用 `384×384 / 24fps` 中等母版、24 秒目标单元、48 秒连续讲话硬上限和 1.2 秒静音切分阈值；实际参数以 `avatar-project.json` 为准。24 秒只控制缓存粒度，不是允许切断讲话的硬切点。分段器只在已复核时间轴的真实静音区间落刀；连续讲话可以在 48 秒内超过目标长度，超过硬上限则明确拒绝，不能把一个词、音节或连续口型拆到两个无上下文单元：

```powershell
python scripts/render-anime-avatar.py plan `
  --project <项目目录> `
  --timeline <speech-timeline.json> `
  --duration-seconds <最终底片时长> `
  --plan-id <计划 id>
```

计划完成后检查每个单元摘要和两帧边界制品。单元内部仍逐条记录原片连续、严格光流、微过渡或拒绝；跨单元边界只由独立 seam bridge 承担。没有拒绝项且结果可接受时再确认：

```powershell
python scripts/render-anime-avatar.py confirm-plan `
  --project <项目目录> `
  --plan-id <计划 id>
```

最后编码：

```powershell
python scripts/render-anime-avatar.py render `
  --project <项目目录> `
  --plan-id <计划 id> `
  --output <输出 mp4>
```

最终底片时长已经确定时填写 `--duration-seconds`；省略时角色轨匹配裁切后的完整音频时长。渲染器不会固定追加尾段。前置静音、足够长的句中停顿、音频真实尾静音，以及底片确实长于音频的部分都交给 `closed_motion_clips` 播放闭嘴动态待机。短于一个自然动作窗口的语流微停顿属于协同发音的一部分，不强制插入一次完整闭嘴，否则会重新产生机械“叭叭叭”。待机保留呼吸、眨眼、头发、耳朵、呆毛、饰品和肩部微动，不用静帧补时，也不重新调用口型分类。

渲染器按以下顺序工作：

1. 从素材账本解析校准视频和音频，验证文件、哈希与项目引用。
2. 按时间轴裁切音频，建立普通话拼音韵母到 A/I/U/E/O 的路径；双唇音开头保留短暂 `CLOSED`。
3. 在每个音节内部用真实音频能量决定相对张口强度，并把该音节能量峰作为高权重的视觉口型核心。核心允许在素材覆盖不足时让位于整画面连续性，不能为了逐字满分而让头部、头发或身体瞬移。
4. 素材视频只在建库时视觉分类一次。运行时读取现有标签，不重新识图、不计算嘴型、不要求人工再次确认大张口帧。
5. 每个元音核心先成为一个可追溯的 anchor。调度器用非传递的间隔选择找出彼此至少相距 8 帧的主核心，再把未选核心附着到最近主核心形成显式 `coarticulation cluster`；不能因为一串相邻间隔都小于 8 帧就把整句传递合并成一次张嘴。其它核心标记为 absorbed，不能从报告中消失，也不能伪装成已经逐一命中。
6. 规划器先运行 `standard` 模式。每个主核心只保留同一元音中接近最佳 `peak_strength_level` 的完整动作，严重错误的强度不能因为某条自然转场更便宜而入选；再把低口型入口、发音峰值和低口型出口映射到共同发音窗口。片段内部使用浮点源时间位置做分段线性、单调的时间伸缩；最终拼好的实际路径必须满足源速度不超过 `2.0x`、加速度不超过质量门，接缝间隔在 24fps 下不少于 8 帧。它不交替抽取 `+1/+2` 帧，不倒放，也不靠 8–15 倍跳帧抢口型。已被用户认可的角色与语音组合只要标准模式可行，后来增加恢复能力也必须保持同一份标准规划结果；报告记录 `planned_annotation_planner_mode=standard`。
7. 相邻 gesture 在同一 take 中存在已审核的有向 `natural_transition_span` 时，从入口沿原视频正向播放完整过渡，不把过渡中间帧当成任意双向跳点。其它相邻片段通常在 gesture 或 idle 的显式低口型端点接缝。快速连读若无法在 2 倍速度内让前一个动作完全闭合后再启动下一个动作，可以让相邻动作从 AI 标注且整画面兼容的中等口型连续承接；入口和出口强度分别建模。标准模式优先两端同级的中等口型；只有标准模式无解时，有界恢复才允许内部协同发音边界使用相差不超过一级、最高为 `level 3` 的部分端点。所有承接仍须通过去嘴整画面外观、运动速度与方向及四帧接缝复核；头发、眼睛、下巴、耳朵和身体不连续时必须拒绝，不能因为口型更接近而放行。
8. `standard` 确实无解时，同一个规划器才进入 `bounded-recovery`，不另建长视频或失败兜底路线。恢复只改变视觉动作的可用窗口：一个发音核心过于靠近语音区间起点时，可以从它前面的稳定静音尾部最多借用相当于 24fps 下 5 帧的视觉预备动作；不得跨过已经视觉确认的 `CLOSED` 锚点，借用后保留下来的静音核心仍必须使用动态闭嘴动作。音频、逐字边界、目标总时长、`2.0x` 速度门和加速度门都不变。边界附近的一组过密核心若外侧主核心使整组不可行，恢复模式从组内选择仍能满足路径约束的主核心，其余核心继续以 absorbed anchor 留在报告中，不能让一个边界核心吞掉整句。
9. take 与 clip 的轮换要求进入规划状态，并按当前台词真正用到的元音、强度可用素材数和动作块数量自适应。规划器先在满足连续性的候选中强制可实现的多样性；如果恢复模式只因强制换 take 或 clip 而无解，可以采用 `continuity-first-fallback`，优先保留自然连续路径，同时在报告中把未满足的多样性合同如实标为失败。这个状态只说明机器找到了满足运动边界的路径，不等于视觉效果通过，更不能伪造素材强弱变化。
10. 候选接缝同时比较去嘴整画面外观以及切口前后数帧的运动速度和方向。每个内部接缝和跨单元边界都读取 `boundary-2` 到 `boundary+1` 的四张真实母版尺寸画面：在有界代理尺寸估计双向光流，再回到真实像素复核光度残差、越界和运动包络。严格通过时记录为 `strict_optical_flow`；只有保守亮度警告时可记录两帧 `micro_optical_flow`；人物结构或运动不兼容时必须拒绝。
11. `render-plan.json` 以 `project://` 或 `skill://` 定位符绑定素材库、时间轴、项目、素材文件和运行脚本的 SHA-256；逐帧路线和诊断按单元外置并各自绑定哈希。确认动作把不可变总计划内容哈希写入 `approval`。任一输入、代码或确认后的计划内容发生变化，正式渲染必须拒绝旧计划；这不妨碍新计划按局部语义键复用未变化单元。
12. 已确认计划中的严格光流和微过渡都使用两个输出帧承接。正式编码阶段按计划重新生成同一四帧窗口并逐帧校验预检哈希；最终运动补帧只给已经连续的运动增加时间采样，不能用来掩盖硬切。
13. 全程使用一个固定源裁切和固定中等母版尺寸，不追踪月牙、胸针、眼睛或其它角色专属锚点，也不对每张图重新摆位置。最终视频帧率和窗口尺寸由通用时间线处理；角色轨不再先做 48fps 整轨补帧。
14. 稳定无声区间只调用已审核的 idle clip 连续运动；长静音通过兼容端点连续承接，禁止重复同一帧冻结，也禁止因为某一条接缝成本最低就机械复用同一个待机片段。规划器必须像管理 gesture 一样管理 idle 的已用片段、最近五段重复次数和剩余可达性：素材足够时优先覆盖至少五条不同待机动作，最近五个 idle block 不重复同一片段；如果真实端点兼容性无法支持这一硬约束，才能显式进入 continuity-first fallback，并在计划和机器门中报告未达到的 idle 多样性，不能静默退回单片循环。短于共同发音窗口的微停顿可以被相邻 gesture 的自然回落覆盖，但必须在报告中单列，不能算作稳定停顿闭嘴失败。前置静音、稳定句中停顿和实际尾静音采用同一种规则，不另外追加固定尾段。

校准视频只在共享中等母版缺失时解码和缩放一次。计划和渲染都只在内存中保留小型描述符与固定容量取帧缓存；单元 core 排除边界帧，两帧 seam bridge 独立拥有边界。单元内容变化时只失效该 core；只有边缘动作变化才额外失效相邻 seam。装配时按顺序无重编码拼接画面，并只混入一次连续音频母版。每次规划使用新的 `plan-id`，每次编码使用新的 `task-id`，working、report、计划和输出都拒绝覆盖。

渲染同时交付一个便于直接观看的完整方形口播轨，以及一份 `avatar-track-clips.json`。完整轨保持原始纯色背景；片段清单用于普通视频或采访视频中的局部导入、编辑和重渲染。圆形、方形、位置、大小和与底片的关系属于最终视频时间线，不烘焙进母版或角色库。

## 可选：放进圆形或方形窗口

用户要求讲解视频右下角或其它固定位置出现圆形、方形角色窗时，才进入这一分支。全屏使用方形口播轨时跳过。角色窗是最终视频的构图，不烘焙进母版、校准视频或可复用口型库。

先把底片和已经渲染的方形口播形象轨都导入同一个 `media-sources.json`。Agent 直接查看底片代表帧与角色轨代表帧，确定一次固定的正方形 `avatar_crop_xywh`。这块取景要让头顶、耳朵、呆毛和发梢位于安全区，肩部与衣服覆盖下方圆弧，同时尽量减少头部周围的空白。底部生成字幕需要排除时，也在这一次固定裁切中完成。

然后建立角色窗任务：

```powershell
python scripts/compose-anime-avatar-inset.py init `
  --project <项目目录> `
  --job-id <任务 id> `
  --base-source-id <底片 source id> `
  --avatar-source-id <方形口播轨 source id> `
  --avatar-crop <x,y,width,height> `
  --shape circle `
  --x <窗口左上角 x> `
  --y <窗口左上角 y> `
  --size <外圆直径> `
  --border-width <边框宽度> `
  --border-color "#FFFFFF" `
  --shadow `
  --audio-source avatar
```

`x`、`y` 和 `size` 都以底片像素为单位；`size` 是包含边框的外圆直径或方形外边长。1920×1080 画面可先用 224 像素作为评审起点，通常在 200–280 像素内结合人物安全区和信息密度调整；不再使用 150 像素的小头像，也不把 900×900 的内部旧渲染尺寸当作画面窗口。`avatar_crop_xywh` 必须是正方形，并在所有帧使用同一组值。纯圆形使用 `circle`；无需遮罩的方形使用 `square`。纯白角色背景直接保留在圆内，不抠图。音轨使用 `avatar`、`base`、`mix` 或 `none` 明确选择。

任务结构以 `schemas/anime-avatar-inset.v1.schema.json` 为准。它只引用素材账本中的 source id，不另存素材路径。渲染时运行：

```powershell
python scripts/compose-anime-avatar-inset.py render `
  --project <项目目录> `
  --job avatar-insets/<任务 id>.json `
  --output renders/<输出文件>.mp4
```

脚本使用一块固定遮罩、一组固定坐标和一个共同时间范围合成整条角色轨，输出完整底片时长，并在 `reports/avatar-insets/<任务 id>/` 生成联系表和合成报告。命令中的任务和输出相对路径一律相对显式 `--project` 解析，不能随当前工作目录漂移，也不能写到项目外。默认 `end_behavior` 是 `require-full-track`：角色窗持续到底片结束，并要求输入角色轨覆盖这段完整时间。角色轨应在 `render-anime-avatar.py plan` 阶段用 `--duration-seconds <底片时长>` 建立完整成片时间线，再确认计划并编码；有台词时走口型，无台词时播放闭嘴动态待机，因此不会为每个视频额外制造尾段，也不会冻结最后一帧。角色画面、圆底、边框和阴影使用同一个时间范围，不会留下空白圆框。只有用户明确要求在某个时间点隐藏，才使用 `--end-behavior hide`；需要角色窗只覆盖指定区间时填写 `--duration`。底片的其它内容、字幕和结构继续来自原底片。

Agent 必须查看最终联系表并完整播放成品，确认：

- 角色窗直径与当前画面层级匹配，头肩占比充足，周围没有大面积空白。
- 头顶、猫耳、呆毛、发梢和发饰在全片都处于圆内。
- 肩部和衣服覆盖下方圆弧，左右没有白色楔形、黑角或截空。
- 外圆、边框、阴影和人物整体位置全程固定；眨眼、口型、头发和耳朵仍保持角色轨原有连续运动。
- 最终采用的声音与角色窗出现时间一致，底片其它画面保持原有内容关系。

先导出五到十秒真实声音的小样并完整观看，再跑全片。小样要经过“音频 → 时间轴 → 素材库 → 方形口播轨 → 角色窗合成”的完整链路，不能用几张手写状态图代替正式生产者输出。成片确认后再把输出导入素材账本，并进入常规 `media-delivery.json` 检查。

## 质量门

### 母版

- 身份与用户确认一致。
- 纯白、不透明、无文字和无抠图残留。
- 固定正面头肩，轮廓和关键饰品处于安全区。
- 服装连续覆盖底边。

### 校准视频

- 约 15 秒、固定机位、固定人物底部、无缩放和重构图。
- 两轮完整而短促的 A/I/U/E/O，前中后有闭嘴连续运动。
- 头部动作克制；头发、耳朵、眼睛、呆毛、饰品和肩膀有连续微动。
- 无字幕、文字和水印；如字幕无法避免，固定裁切能完全排除且不伤构图。

### 视觉素材库

- 标注声明为 `ai-visual-review`，并记录实际查看的联系表。
- A/I/U/E/O 各至少一条视觉成立的完整动作，每条有 rise、peak、fall 和 `0–4`；实际存在的其它 take 也全部标出。
- CLOSED 穷尽所有视觉成立的连续闭嘴运动；前中后各一段是最低覆盖门，不是提取上限。运行状态覆盖全部源帧且没有空洞或越界。
- AI 已复核最大张口、E/O 易混淆帧和每条连续动作。

### 注册与采用

- 注册表、角色包、素材账本和口型库的 id、版本、能力事实与哈希一致；审阅证据真实存在。
- `default_library` 只由独立确认设置；存在一个或多个注册角色时仍可以保持 `null`。
- 全新 Skill 外部项目通过 `adopt-library` 只保存 id 与版本，并由 `check-anime-avatar-resources.py --deep --project <项目目录>` 证明正式消费者加载了注册包、母版、校准视频和口型库。
- 旧项目只由 `migrate-library` 读取；正常加载器只接受当前活动版本。迁移前的项目和产物不被删除或覆盖。

### 新语音

- 逐字稿精确，裁切明确，时间边界已经听音或由可靠的 TTS boundary 确认。
- 时间轴的汉字序列与文本一致，单位没有重叠或倒序。
- 不用错误自动转写替代用户确认文本。

### 成品

- 每个原始音节核心都有去向；报告如实区分 realized 与 absorbed。主核心口型、大开口和整体语流达到质量门，不为了声称逐音素满分而破坏连续动作。
- 没有相同静帧长时间保持，没有一秒多次无意义“叭叭叭”，也没有一个大口型持续覆盖多个音节。
- 5 秒后没有因为素材耗尽而机械重复同一动作；两条 take 与闭嘴段有实际轮换。
- 切换处没有人物整体瞬移、头部大幅跳变、下巴融化或双重五官。
- 编码消费已经确认且哈希有效的 `render-plan.json`；全部接缝在编码前可见，拒绝项为零，运行时重新规划次数为零。
- 活动项目只使用 v4 项目和 v3 分段计划；报告证明中等母版、单元计划、角色片段、接缝桥和连续音频各自是 `rendered` 还是 `reused`。修改一个中间单元时，未变化单元必须命中；连续音频没有被切碎或重复混入。
- `avatar-track-clips.json` 连续覆盖完整帧数，所有项目相对文件和哈希真实存在，MediaFlow Pro 能将它们作为普通素材批量摆入同一时间线。
- 所有稳定无声区间都保持闭嘴动态待机；计划同时报告 idle 可用片段、实际使用计数、最近五段重复上限和多样性是否成立，素材足够时不得连续机械复用同一条待机。协同发音覆盖的短微停顿单独报告。成片没有固定追加的尾段、空白圆框或静态冻结。
- 音频、口播形象轨和最终视频时长一致，用户完整观看过最终导出。

## 出问题时从哪一层重做

| 可见问题 | 根因层 | 正确处理 |
|---|---|---|
| 人物整体上下左右跳 | 独立图片身份/构图不一致，或校准视频有漂移 | 回到同一母版和固定机位校准视频；不逐图加坐标 |
| 下巴变形、嘴位置漂移 | 局部嘴图、局部重绘，或接缝两端人物结构/运动不兼容 | 只用同一源视频完整帧；仅亮度警告可用微过渡，结构或运动不兼容则回到素材库或校准视频层处理 |
| 全是小口型 | 分类把形状当大小，或能量只映射到低级别 | AI 复核每类 0–4 和真实最大开口；检查音节内能量映射 |
| 嘴长时间张大 | 校准源把一个元音喊太久，或运行时保持 peak | 重做短促完整的校准音节；运行时使用 rise/peak/fall |
| 快速反复开合 | 逐帧强制标签、时间轴过碎或把每个微停顿都强制闭嘴 | 检查协同发音 cluster、8 帧动作间隔、`2.0x` 源速度门，并复核字边界和裁切 |
| 5 秒后重复变多 | 每类只有一段素材，或选择器总回同一 take | 校准视频提供两轮；验证报告检查 take 使用 |
| 换台词后失效 | 素材只按原句顺播，没有音素时间轴 | 使用新音频的 `speech-timeline.json` 和现有视觉库重渲染 |
| 圆圈底部露白或黑角 | 母版底边没铺满衣服，或最终圆形裁切错误 | 母版层补足连续衣服；窗口层固定圆形遮罩并复核 |
| 无声处人物空白、张嘴或冻结 | 角色轨短于底片，或无声区间仍走普通口型路径 | 按底片完整时长重渲染角色轨；所有无声区间统一使用连续 CLOSED 动作，并验证交付画面帧数 |

这些修复发生在各自的唯一真源。不要在渲染器里为某个角色、某句话或某个坏帧加入硬编码例外。
