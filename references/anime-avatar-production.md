# 单图二次元口播形象

## 这条流程解决什么

这条流程把一张全新二次元角色图，或一份已经确认的角色设定，变成可以反复用于中文口播的无骨骼素材库。它不要求 Live2D、图层拆分、单独嘴部贴图或逐帧重绘，也不把真人数字人模型当作默认路线。

最终运行链只有一条：

`已确认母版 → 同一母版生成的连续校准视频 → AI 视觉标注的 A/I/U/E/O/CLOSED 素材库 → 已确认的中文语音时间轴 → 整帧连续运动匹配 → 口播形象视频 → 常规视频时间线合成`

角色身份、角色设定、母版、校准视频、标注结果和当前台词都属于项目数据。Skill 只保存方法、协议、提示词模板和通用脚本，不保存某个角色的坐标、口型帧或台词。

## 能力边界

- 当前内置口型映射面向普通话，使用 `A / I / U / E / O / CLOSED` 六类视觉口型和每类 `0–4` 的相对强度。其它语言需要另建语言到视觉口型的映射，不能直接声称等价。
- 输出使用校准视频中的完整人物画面。嘴、下巴、脸颊、头发、耳朵、饰品和肩膀来自同一源帧，不局部重绘、不拆部件。
- 目标是“看起来大体对得上，同时保持连续自然”，不是逐音素达到影视级精确唇同步。报告必须分别给出音节核心口型命中率、全帧匹配率、跳转次数和人工完整观看结果。
- 一套通过质量门的角色库只建立一次。更换台词或音频时只建立新的 `speech-timeline.json` 并重新渲染，不重新识图、重新分类或人工指定大张口帧。
- 母版或校准视频需要调用外部图像、视频生成服务时，遵守当前授权边界。用户只要提示词时交付提示词后停止；用户要求完整制作且工具已获授权时才代为提交。

## 先判断用户处在哪一层

| 用户现有内容 | 从哪里开始 | 本轮合理停止点 |
|---|---|---|
| 只有角色文字设定 | 先确认角色规格，再生成母版候选 | 用户确认一张母版，或继续完成校准视频 |
| 有一张角色图 | 检查能否直接做母版；不符合时以它为唯一身份参考重绘 | 用户确认母版 |
| 有母版，没有校准视频 | 给出或提交 15 秒校准视频提示词 | 收到并检查校准视频 |
| 有校准视频，没有素材库 | 抽帧和联系表，AI 视觉标注，验证素材库 | 素材库通过质量门 |
| 有素材库和新文本 | 先生成 TTS 与供应方时间信息，再规范化语音时间轴 | 渲染并检查口播视频 |
| 有素材库和现成录音 | 确认逐字稿、静音裁切和时间对齐 | 渲染并检查口播视频 |
| 有口播形象视频和底片 | 回到常规视频时间线 | 完成圆形或方形窗口合成与交付 |

用户要求从零完成时，不把“先给提示词”误当成最终交付。母版确认是唯一必须由用户决定的高影响身份检查点；之后按授权继续生成校准素材、建库、合成和验收。

## 项目真源

从 `assets/media-project-starter/` 建立普通媒体项目，再执行：

```powershell
python scripts/anime-avatar-project.py init `
  --project <项目目录> `
  --character-id <稳定小写 id> `
  --character-name <角色名> `
  --origin reference-image `
  --specification <角色规格文本文件>
```

项目中与本流程有关的权威文件是：

- `media-sources.json`：唯一真实素材账本。参考图、母版、校准视频、声音和最终输出都先进入这里；其它文件只引用 source id。
- `avatar-project.json`：当前角色、已确认母版、校准视频、固定裁切和渲染规格。
- `visual-viseme-library.json`：AI 视觉标注得到的可复用口型与连续动作区间。
- `speech-timeline.json`：一段具体音频的确认文本、裁切和逐字时间边界。
- `avatar-insets/<任务 id>.json`：某一条成片可选的角色窗形状、固定裁切、位置、尺寸、边框、阴影、出现时间和音轨选择。
- `reports/avatar-source-review/`：供 AI 视觉检查的原始联系表。
- `reports/avatar-library-review/`：由已经完成的标注反向生成的类别、强度和连续动作审查图。
- `reports/avatar-renders/<任务 id>/`：目标口型、实际选帧、切换和技术检查报告。
- `reports/avatar-insets/<任务 id>/`：最终角色窗的联系表和合成报告。

不在 `avatar-project.json` 重复保存文件路径、哈希、生成供应方或权利信息。它只保存 source id；实际文件和来源由 `media-sources.json` 解析。不要把某次台词或某个音频写进角色库。

`avatar-insets/<任务 id>.json` 不属于角色身份或口型库。相同角色进入不同底片时，窗口大小、位置和声音关系可以各自变化；角色库保持不变。

## 从零建立一个新角色

### 1. 形成角色规格

只有文字设定时，先把以下内容写成项目级角色规格：年龄感与气质、脸型和五官比例、瞳色、发型与发色、动物耳或其它轮廓特征、不可丢失的发饰、服装、关键胸前饰品、色彩、线条和上色方式。只记录用户确认的身份事实，不从参考风格推导新设定。

有参考图时，先检查身份元素是否清楚。参考图可以是倾斜姿态、透明底或全身图，但下游母版必须重新满足固定的头肩构图。参考图进入素材账本，生成母版时是唯一人物身份参考；不要同时加入风格相近但身份不同的人物图。

### 2. 生成并确认母版

初始化命令会把 `assets/anime-avatar-prompts/master-image.md` 复制到项目 `prompts/`。把角色规格和参考方式填入模板后使用。

合格母版必须同时满足：

- 正方形、高分辨率、正面自然头肩构图；头部直立、双肩基本水平、视线看向观众。
- 猫耳、呆毛、发梢、发饰、肩部和胸前关键饰品都在安全边距内。
- 服装在整条画面底边连续铺满。以后使用圆形裁切时，圆弧底部必须仍是衣服，不能露出白色楔形、黑角或截空。
- 纯白不透明背景，背景无渐变、阴影、光晕、暗底残留和抠图毛边。
- 眼睛自然睁开，嘴自然闭合或只有极浅微笑。母版不承担口型素材。
- 线条清楚、稳定的日系二次元赛璐璐上色；无糊化、涂抹感、双重五官。
- 没有圆框、边框、定位点、锚点、辅助线、字幕、文字和水印。

检查母版时看整张图，不只看脸。身份、底边衣服覆盖和轮廓安全区任何一项失败，都在母版层重做；不要期待后续裁切或定位脚本补救。

母版经用户确认后作为 `master_source_id` 写进 `avatar-project.json`，状态改为 `confirmed`。母版一旦变化，原校准视频和原口型库全部失去身份依据，必须重新生成；不要保留兼容到旧母版的混合库。

### 3. 生成 15 秒校准视频

使用 `assets/anime-avatar-prompts/motion-source-video.md`。母版必须是视频首帧和唯一人物参考。推荐校准语音是两轮短促而完整的：

> 啊。咿。呜。诶。哦。……啊。咿。呜。诶。哦。

它不是最终口播，职责只是为同一人物收集六类视觉口型和连续细节运动。每个音节只完成一次自然的“闭合或弱开 → 发音峰值 → 回落”，不能把一个元音持续喊很久，也不能快速反复开合。

15 秒的推荐节奏：

- `0.0–1.0s`：闭嘴自然停留，保持轻微呼吸。
- `1.0–6.0s`：第一轮 A/I/U/E/O，每个音节约 `0.55–0.75s`，音节之间留短暂自然回落。
- `6.0–7.5s`：闭嘴停留，可有一次自然眨眼。
- `7.5–12.5s`：第二轮 A/I/U/E/O，身份和构图不变，只允许不同的微表情、发梢或耳朵细节。
- `12.5–15.0s`：闭嘴收尾，动作继续但逐渐稳定。

两轮的意义是为同一口型提供不同但连续的头发、耳朵、眼睛、饰品和肩部运动，减少新台词中的机械重复。视频不需要覆盖所有音素排列；运行时以音节核心硬匹配，周围用共同发音和连续运动软过渡。

合格校准视频必须固定机位、固定构图、固定缩放和固定人物底部。允许的生命感是克制而连续的眨眼、呼吸、眼神微动、发梢滞后、呆毛小摆动、猫耳偶尔小幅反应和饰品轻微惯性。头部大幅摇摆、点头、身体漂移、镜头运动或自动重新构图都会在换口型时放大成跳变，发现后直接重做校准视频，不用后期坐标追踪掩盖。

纯白背景可以直接保留，不需要抠图或绿幕。生成器自行加在底部的字幕不属于素材；在 `source_crop_xywh` 中用一个固定裁切排除字幕，但不能裁掉耳朵、呆毛、肩膀或底边衣服。

### 4. 先看素材，再建立视觉标注

把校准视频导入素材账本，填写 `avatar-project.json` 中的 `motion_source.source_id` 与固定 `source_crop_xywh`，然后运行：

```powershell
python scripts/anime-avatar-project.py prepare-review --project <项目目录>
```

脚本只做以下机械工作：

- 用 FFprobe 读取真实帧率、尺寸和时长。
- 按固定裁切抽取带帧号和时间的整帧联系表。
- 按项目中人工指定的嘴部审查区域生成高频局部联系表。
- 保存抽样清单，确保之后的视觉判断可以回到原视频帧。

它不得通过像素阈值、嘴部轮廓面积、人脸关键点、聚类或图像差分推断口型或强度。

Agent 必须直接查看联系表，必要时再查看原始单帧，并写出 `visual-viseme-library.json`。视觉分类依据是口唇形状，不是嘴洞面积：

- `A`：纵向明显、较放松的开口。
- `I`：嘴角横向展开，开口较浅。
- `U`：紧凑、前收、圆或短圆缝；`U4` 仍可能很小。
- `E`：较宽的横向开口，强级别可看到明显口腔和舌面。
- `O`：纵向圆形或高椭圆，不能和横向的 E 混淆。
- `CLOSED`：双唇闭合或自然微笑线，没有可见口腔。

每个元音的 `0–4` 强度只在本元音内部比较。不要把 `U4` 和 `E4` 当作同样大的嘴；也不要预设最大开口一定是 A。对整条素材视觉检查后，最大开口可能属于 E 或 O。

标注时必须给出：

- 覆盖整条校准视频的 `runtime_state_spans`。
- 至少三段连续闭嘴运动：开头、中间和结尾。
- 每类元音至少两条独立 take；每条都有完整 rise、peak、fall。
- rise、fall 各五个代表帧，对应强度 `0–4`。
- peak 的连续帧区间，以及适合人工复核的代表帧。
- 原视频中自然存在的相邻口型过渡区间。
- 实际查看过的联系表、标注日期和判断说明。

标注完成后运行：

```powershell
python scripts/anime-avatar-project.py validate-library --project <项目目录>
python scripts/anime-avatar-project.py render-library-review --project <项目目录>
```

校验器只检查协议、source id、真实帧率、帧边界、覆盖、重叠、类别和数量；它不重新判断视觉标签。然后 Agent 必须查看 `reports/avatar-library-review/` 中的类别强度表、E/O 对比、闭嘴表和每条 rise/peak/fall 连续条带。分类错了就改标注真源，不在渲染器里添加例外。

## 为一段新语音建立时间轴

### 文本转语音

先按 `references/speech-synthesis.md` 生成原始 TTS，保留确切合成文本、声音身份和供应方返回的时间信息。优先使用供应方的 word/character boundary；把它规范化为 `schemas/speech-timeline.v1.schema.json`。

使用当前环境已有的 EdgeTTS 且已经获得调用授权时，可直接运行：

```powershell
python scripts/synthesize-avatar-speech.py `
  --text-file <UTF-8 合成文本> `
  --voice <准确声音 id> `
  --audio-source-id <准备写入素材账本的 id> `
  --output-audio <原始 mp3> `
  --output-timeline <speech-timeline.json>
```

脚本会同时保存供应方的原始 `WordBoundary`。当一个供应方边界包含多个汉字时，它只在该真实边界内部依据音频低能量点细分，不把整句平均切开。新时间轴故意以 `timing.reviewed=false` 写出；试听并确认逐字边界后改为 `true`，再把音频以同一个 source id 导入 `media-sources.json`。精确声音不存在时停止，不能静默换声。

如果其它供应方只返回句级或词级时间，不要把整句平均分给每个字然后直接正式交付。可以用音频对齐工具细化，但必须以确切合成文本为准，并听音复核明显边界。

### 用户录音或视频中的声音

先确认逐字稿，再确定需要裁掉的前置静音和尾部。自动转写只能作为起点；转写结果与用户确认文本不一致时，以确认文本为准重新对齐，不能让错误 ASR 文本进入口型渲染。

`speech-timeline.json` 中：

- `trim_start_seconds` 和可选 `trim_end_seconds` 针对原素材。
- `units` 的时间从裁切后的 `0` 开始。
- 每个普通话汉字是一项，顺序必须与 `text` 去除标点后的汉字完全一致。
- `timing.reviewed` 正式渲染前必须为 `true`。

录音开头的无声区间要先判断是否属于成片节奏。需要去掉时，实际听音或看波形后把裁切写入时间轴，并让所有字时间相对于裁切后音频；需要保留时不裁切，第一字仍写真实起音时间，角色在此前自动播放闭嘴动态待机。

## 从素材库合成新口播

运行：

```powershell
python scripts/render-anime-avatar.py `
  --project <项目目录> `
  --timeline <speech-timeline.json> `
  --duration-seconds <最终底片时长> `
  --output <输出 mp4>
```

最终底片时长已经确定时填写 `--duration-seconds`；省略时角色轨匹配裁切后的完整音频时长。渲染器不会固定追加尾段，而是把整条目标时间线中没有台词的区间统一交给 `closed_motion_clips`：前置静音、句中停顿、音频真实尾静音，以及底片确实长于音频的部分都播放闭嘴动态待机。待机保留呼吸、眨眼、头发、耳朵、呆毛、饰品和肩部微动，不用静帧补时，也不重新调用口型分类。

渲染器按以下顺序工作：

1. 从素材账本解析校准视频和音频，验证文件、哈希与项目引用。
2. 按时间轴裁切音频，建立普通话拼音韵母到 A/I/U/E/O 的路径；双唇音开头保留短暂 `CLOSED`。
3. 在每个音节内部用真实音频能量决定相对张口强度，并把该音节能量峰作为必须命中的视觉口型核心。这样响亮的音节会调用本类大张口，轻音不会全被抬成大嘴。
4. 素材视频只在建库时视觉分类一次。运行时读取现有标签，不重新识图、不计算嘴型、不要求人工再次确认大张口帧。
5. 有声区间用去掉嘴部审查区域的整帧视觉描述衡量头发、眼睛、耳朵、饰品和身体连续性，沿原视频相邻帧前进，只在音节核心附近允许跳到另一条 take。
6. 音节核心要求类别严格匹配；核心之间允许共同发音和连续动作取得平衡。逐帧强制准确会产生过多整帧跳切，完全顺播又会让台词换掉后口型失效。
7. 跳转处只做一帧整画面光流承接，随后以运动补偿插到交付帧率。光流只能柔化已经较近的两帧，不能挽救大幅转头、缩放或身份漂移的坏素材。
8. 全程使用一个固定源裁切和固定输出尺寸，不追踪月牙、胸针、眼睛或其它角色专属锚点，也不对每张图重新摆位置。
9. 时间轴中的每段无声区间只从素材库的连续闭嘴动作构造；片段起止同时参考前后有声帧，禁止重复同一帧冻结，并在动作段边界使用同一套整帧连续性检查。

渲染结果是一个保持原始纯色背景的方形口播形象轨。圆形、方形、位置、大小和与底片的关系属于最终视频时间线，不烘焙进母版或角色库。

## 可选：放进圆形或方形窗口

用户要求讲解视频右下角或其它固定位置出现圆形、方形角色窗时，才进入这一分支。全屏使用方形口播轨时跳过。角色窗是最终视频的构图，不烘焙进母版、校准视频或可复用口型库。

先把底片和已经渲染的方形口播形象轨都导入同一个 `media-sources.json`。Agent 直接查看底片代表帧与角色轨代表帧，确定一次固定的正方形 `avatar_crop_xywh`。这块取景要让头顶、耳朵、呆毛和发梢位于安全区，肩部与衣服覆盖下方圆弧，同时尽量减少头部周围的空白。底部生成字幕需要排除时，也在这一次固定裁切中完成。

然后建立角色窗任务：

```powershell
python scripts/compose-anime-avatar-inset.py init `
  --project <项目目录> `
  --job-id <任务 id> `
  --base-source-id <底片 source id> `
  --avatar-source-id <方形口播轨 source id> `
  --avatar-crop <x,y,width,height> `
  --shape circle `
  --x <窗口左上角 x> `
  --y <窗口左上角 y> `
  --size <外圆直径> `
  --border-width <边框宽度> `
  --border-color "#FFFFFF" `
  --shadow `
  --audio-source avatar
```

`x`、`y` 和 `size` 都以底片像素为单位；`size` 是包含边框的外圆直径或方形外边长。`avatar_crop_xywh` 必须是正方形，并在所有帧使用同一组值。纯圆形使用 `circle`；无需遮罩的方形使用 `square`。音轨使用 `avatar`、`base`、`mix` 或 `none` 明确选择，混音时再设置底片与角色音量。

任务结构以 `schemas/anime-avatar-inset.v1.schema.json` 为准。它只引用素材账本中的 source id，不另存素材路径。渲染时运行：

```powershell
python scripts/compose-anime-avatar-inset.py render `
  --project <项目目录> `
  --job avatar-insets/<任务 id>.json `
  --output renders/<输出文件>.mp4
```

脚本使用一块固定遮罩、一组固定坐标和一个共同时间范围合成整条角色轨，输出完整底片时长，并在 `reports/avatar-insets/<任务 id>/` 生成联系表和合成报告。默认 `end_behavior` 是 `require-full-track`：角色窗持续到底片结束，并要求输入角色轨覆盖这段完整时间。角色轨应使用 `render-anime-avatar.py --duration-seconds <底片时长>` 按同一成片时间线渲染；有台词时走口型，无台词时播放闭嘴动态待机，因此不会为每个视频额外制造尾段，也不会冻结最后一帧。角色画面、圆底、边框和阴影使用同一个时间范围，不会留下空白圆框。只有用户明确要求在某个时间点隐藏，才使用 `--end-behavior hide`；需要角色窗只覆盖指定区间时填写 `--duration`。底片的其它内容、字幕和结构继续来自原底片。

Agent 必须查看最终联系表并完整播放成品，确认：

- 角色窗直径与当前画面层级匹配，头肩占比充足，周围没有大面积空白。
- 头顶、猫耳、呆毛、发梢和发饰在全片都处于圆内。
- 肩部和衣服覆盖下方圆弧，左右没有白色楔形、黑角或截空。
- 外圆、边框、阴影和人物整体位置全程固定；眨眼、口型、头发和耳朵仍保持角色轨原有连续运动。
- 最终采用的声音与角色窗出现时间一致，底片其它画面保持原有内容关系。

先导出五到十秒真实声音的小样并完整观看，再跑全片。小样要经过“音频 → 时间轴 → 素材库 → 方形口播轨 → 角色窗合成”的完整链路，不能用几张手写状态图代替正式生产者输出。成片确认后再把输出导入素材账本，并进入常规 `media-delivery.json` 检查。

## 质量门

### 母版

- 身份与用户确认一致。
- 纯白、不透明、无文字和无抠图残留。
- 固定正面头肩，轮廓和关键饰品处于安全区。
- 服装连续覆盖底边。

### 校准视频

- 约 15 秒、固定机位、固定人物底部、无缩放和重构图。
- 两轮完整而短促的 A/I/U/E/O，前中后有闭嘴连续运动。
- 头部动作克制；头发、耳朵、眼睛、呆毛、饰品和肩膀有连续微动。
- 无字幕、文字和水印；如字幕无法避免，固定裁切能完全排除且不伤构图。

### 视觉素材库

- 标注声明为 `ai-visual-review`，并记录实际查看的联系表。
- A/I/U/E/O 各至少两条 take，每条有 rise、peak、fall 和 `0–4`。
- CLOSED 至少三段；运行状态覆盖全部源帧且没有空洞或越界。
- AI 已复核最大张口、E/O 易混淆帧和每条连续动作。

### 新语音

- 逐字稿精确，裁切明确，时间边界已经听音或由可靠的 TTS boundary 确认。
- 时间轴的汉字序列与文本一致，单位没有重叠或倒序。
- 不用错误自动转写替代用户确认文本。

### 成品

- 音节核心口型全部命中；报告同时给出整体匹配而不只给核心指标。
- 没有相同静帧长时间保持，没有一秒多次无意义“叭叭叭”，也没有一个大口型持续覆盖多个音节。
- 5 秒后没有因为素材耗尽而机械重复同一动作；两条 take 与闭嘴段有实际轮换。
- 切换处没有人物整体瞬移、头部大幅跳变、下巴融化或双重五官。
- 所有无声区间都保持闭嘴动态待机；成片没有固定追加的尾段、空白圆框或静态冻结。
- 音频、口播形象轨和最终视频时长一致，用户完整观看过最终导出。

## 出问题时从哪一层重做

| 可见问题 | 根因层 | 正确处理 |
|---|---|---|
| 人物整体上下左右跳 | 独立图片身份/构图不一致，或校准视频有漂移 | 回到同一母版和固定机位校准视频；不逐图加坐标 |
| 下巴变形、嘴位置漂移 | 局部嘴图、局部重绘或差异过大的光流 | 只用同一源视频完整帧；坏边界换近邻 take |
| 全是小口型 | 分类把形状当大小，或能量只映射到低级别 | AI 复核每类 0–4 和真实最大开口；检查音节内能量映射 |
| 嘴长时间张大 | 校准源把一个元音喊太久，或运行时保持 peak | 重做短促完整的校准音节；运行时使用 rise/peak/fall |
| 快速反复开合 | 逐帧强制标签、时间轴过碎或静音误判 | 以音节核心硬匹配，周围共同发音；复核字边界和裁切 |
| 5 秒后重复变多 | 每类只有一段素材，或选择器总回同一 take | 校准视频提供两轮；验证报告检查 take 使用 |
| 换台词后失效 | 素材只按原句顺播，没有音素时间轴 | 使用新音频的 `speech-timeline.json` 和现有视觉库重渲染 |
| 圆圈底部露白或黑角 | 母版底边没铺满衣服，或最终圆形裁切错误 | 母版层补足连续衣服；窗口层固定圆形遮罩并复核 |
| 无声处人物空白、张嘴或冻结 | 角色轨短于底片，或无声区间仍走普通口型路径 | 按底片完整时长重渲染角色轨；所有无声区间统一使用连续 CLOSED 动作，并验证交付画面帧数 |

这些修复发生在各自的唯一真源。不要在渲染器里为某个角色、某句话或某个坏帧加入硬编码例外。
