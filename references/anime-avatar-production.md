# 单图二次元口播形象

## 这条流程解决什么

这条流程把一张全新二次元角色图，或一份已经确认的角色设定，变成可以反复用于中文口播的无骨骼素材库。它不要求 Live2D、图层拆分、单独嘴部贴图或逐帧重绘，也不把真人数字人模型当作默认路线。

最终运行链只有一条：

`已确认母版 → 同一母版生成的唯一连续校准视频 → AI 视觉标注的 A/I/U/E/O/CLOSED 素材库包 → 项目按角色名、别名或注册 id 引用 → 绑定真实音频哈希的已复核中文时间轴 → 不可变分段计划 → 中等尺寸共享母版 → 局部角色片段与连续音频 → 按需装配完整角色轨或固定角色窗`

当前台词、语音、时间轴、计划和输出属于可变项目数据。角色身份、母版、校准视频、角色专属裁切和口型帧属于一个版本化的角色素材库包；新角色建库时它先位于项目内，来源与使用权确认、视觉标注和质量门通过后，可以经注册入口迁入 Skill 的共享只读资源库。Skill 不保存某次台词和运行输出，也不把任何已注册角色自动当作默认。

## 能力边界

- 当前内置口型映射面向普通话，使用 `A / I / U / E / O / CLOSED` 六类视觉口型和每类 `0–4` 的相对强度。其它语言需要另建语言到视觉口型的映射，不能直接声称等价。
- 输出使用校准视频中的完整人物画面。嘴、下巴、脸颊、头发、耳朵、饰品和肩膀来自同一源帧，不局部重绘、不拆部件。
- 目标是“看起来大体对得上，同时保持连续自然”，不是逐音素达到影视级精确唇同步。报告必须分别给出音节核心口型命中率、全帧匹配率、跳转次数和人工完整观看结果。
- 一套通过质量门的角色库只建立一次。更换台词或音频时只建立新的 `speech-timeline.json` 并重新渲染，不重新识图、重新分类或人工指定大张口帧。
- 角色身份资源与渲染算法参数分开。注册包保存母版、校准视频、裁切和视觉标注；项目 v4 默认生成 `384×384 / 24fps` 的中等尺寸母版，并按最长约 24 秒的语义区间缓存。最终窗口多大、圆形还是方形属于视频构图，不回写角色库。
- 母版或校准视频需要调用外部图像、视频生成服务时，遵守当前授权边界。用户只要提示词时交付提示词后停止；用户要求完整制作且工具已获授权时才代为提交。

用户同时要求明显人物动作和高精度口型时，不继续把完整帧重组包装成能够稳定兼得。先说明这条路线会把嘴型与同一帧中的头部、头发、饰品和身体动作绑定，让用户决定是否改用音频驱动或分层、骨骼角色系统；未决定前不生成校准视频。

## 用户实际会经历什么

用户只需要提供角色设定或母版、按要求生成的校准视频，以及以后真正要使用的文字或声音。内部素材账本、固定裁切、联系表、`visual-viseme-library.json`、帧号、哈希、计划和命令都由 Agent 与程序消费，不作为用户作业。

- 还没有校准视频时，先把 `assets/anime-avatar-prompts/motion-source-video.md` 的完整提示词和合格条件交给用户，再等待素材；不能只说“生成一段固定机位视频”。用户要求完整制作且外部生成已获授权时，Agent 直接用这份提示词提交。
- 已经收到校准视频时，Agent 先观看整段视频和联系表。素材不合格就给出可观察问题及对应时间段，回到同一母版重做；素材合格就继续完成视觉标注和验证，不能要求用户逐帧查看、重新排列帧、编辑 JSON 或运行下文命令。
- 建库时由用户确认母版身份；写入共享角色库前另行确认是否长期复用。机器 `confirm-plan` 只表示 Agent 已检查不可变技术计划，不要求用户理解计划文件。制作长视频时，用户仍通过真实样片和完整预览判断最终结果。

JSON 负责保存视觉判断和真实帧边界，本身不产生准确性。准确性来自 Agent 查看真实完整人物帧、嘴部图和连续过渡；确定性程序只负责生成联系表、写入或读取机器结构、检查边界并拒绝无效计划。即使当前实现由 Agent 形成结构化文件，也不得把这项内部工作转交用户。

## 先判断用户处在哪一层

| 用户现有内容 | 从哪里开始 | 本轮合理停止点 |
|---|---|---|
| 只有角色文字设定 | 先确认角色规格，再生成母版候选 | 用户确认一张母版，或继续完成校准视频 |
| 有一张角色图 | 检查能否直接做母版；不符合时以它为唯一身份参考重绘 | 用户确认母版 |
| 有母版，没有校准视频 | 完整交付或提交 15 秒校准视频提示词及合格条件 | 收到并检查校准视频 |
| 有校准视频，没有素材库 | Agent 抽帧、看联系表、完成 AI 视觉标注并验证素材库 | 素材库通过质量门；用户不处理帧或 JSON |
| 想复用已有角色，但还没有项目 | 先列出已注册角色，再按角色名、别名或稳定 id 采用首选版本 | 新建 Skill 内任务项目并实际解析到共享只读素材库 |
| 旧项目已有可复用母版、校准视频和口型库 | 运行一次性迁移，登记来源、版本和审阅证据 | 注册表能列出，新项目能采用；旧项目保持原样 |
| 有素材库和已确认新文本，没有现成声音 | 口播视频需要声音，按主入口当前视频声音基线生成 TTS 与供应方时间信息，再规范化语音时间轴 | 渲染并检查口播视频 |
| 有素材库和现成录音或含原声视频，也给了准确文本 | 原声优先；文本只用于校正转写和时间对齐，不重新 TTS、不换声、不变速 | 渲染并检查口播视频 |
| 有口播形象视频和底片 | 回到常规视频时间线 | 完成圆形或方形窗口合成与交付 |

用户要求从零完成时，不把“先给提示词”误当成最终交付。母版确认是建库过程中唯一必须由用户决定的高影响身份检查点；之后按授权继续生成校准素材、建库、合成和验收。只有把候选角色写入共享只读资源库时，再确认是否长期复用。

## 项目真源

可变角色媒体项目必须建立在 `visual-multimedia` Skill 源码目录之外。这里的限制只阻止项目把语音、计划、报告和输出反写进 Skill，不禁止 Skill 保存正式注册且只读复用的角色资产。

先查看当前可用资源：

```powershell
python scripts/anime-avatar-project.py list-libraries
```

命令读取 `assets/anime-avatar-libraries/catalog.json`。`default_library: null` 表示没有默认角色；资源出现在列表中只表示可以被显式采用。

从已注册角色建立项目时执行：

```powershell
python scripts/anime-avatar-project.py adopt-library `
  --project <全新项目目录> `
  --library <角色名、别名或注册 id>
```

注册表把角色名和别名解析为稳定 id，并在未指定 `--version` 时采用该角色的 `preferred_version`。例如用户说“给视频添加夜希数字人”，入口直接采用别名 `夜希数字人`，不要求用户知道 `yexi@1.0.0`。项目只保存 `{kind, id, version}` 引用，不复制母版、校准视频或口型库。

从零建立新角色时执行：

```powershell
python scripts/anime-avatar-project.py init `
  --project <项目目录> `
  --character-id <稳定小写 id> `
  --character-name <角色名> `
  --origin reference-image `
  --specification <角色规格文本文件>
```

完成母版、校准视频、AI 视觉标注和素材库质量门后，项目内角色包仍是候选资源。只有用户确认要长期复用时才注册：

```powershell
python scripts/anime-avatar-project.py register-library `
  --source-project <项目目录> `
  --version <x.y.z>
```

注册命令重新读取真实母版、校准视频、素材哈希、口型库和审阅证据，写入共享只读资源及活动注册表，且不改变 `default_library`。

四个根目录的职责固定为：

- Skill 源码：方法、schema、脚本、提示词，以及 `assets/anime-avatar-libraries/` 中已注册、版本化、只读的共享角色资源。
- 角色媒体项目：本次任务的 `avatar-project.json`、语音账本、时间轴、计划、工作文件、报告和输出。
- 角色素材库包：项目内候选包或 Skill 内注册包；保存角色身份、母版、校准视频、裁切和口型标注的唯一真源。
- 配置中的 D 盘缓存根目录：按真实内容保存可复用的中等母版、连续音频、单元计划、角色片段和两帧接缝桥；它不是项目真源，也不进入注册表。
- 任务产物：项目内保存计划、可移交片段、报告和成片；消费者不能直接依赖缓存内部目录。

项目和素材库包中与本流程有关的权威文件是：

- 项目 `media-sources.json`：本次语音、底片和最终输出的唯一真实素材账本。
- `avatar-project.json`：只保存素材库引用和本次渲染规格；v4 不复制角色、校准视频和口型库路径，活动读取器不再接受旧项目合同。
- `library-package.json`：角色身份、版本、状态、能力事实、母版与校准 source id、角色专属裁切、参数来源、验证和迁移来源。
- 素材库包 `media-sources.json`：母版与校准视频的唯一素材账本。
- 素材库包 `visual-viseme-library.json`：AI 视觉标注得到的可复用口型与连续动作区间。
- `speech-timeline.json`：一段具体音频的确认文本、音频 sha256、原素材裁切和以裁切后音频起点为零的逐字时间边界。
- `plans/anime-avatar/<计划 id>/render-plan.json`：v3 不可变分段总计划；顶层只保存输入与代码哈希、单元边界、各单元计划制品、两帧接缝桥和确认状态，逐帧数组留在带哈希的单元制品中。
- `reports/avatar-renders/<任务 id>/avatar-track-clips.json`：项目内可移交的连续片段清单。每个 core 与 seam 都有精确起始帧、时长、文件和哈希；旁白是唯一一条连续 WAV。普通视频与采访视频都把这些文件当作普通时间线素材，不读取角色缓存内部结构。
- `avatar-insets/<任务 id>.json`：某一条成片可选的角色窗形状、固定裁切、位置、尺寸、边框、阴影、出现时间和音轨选择。
- `reports/avatar-source-review/`：供 AI 视觉检查的原始联系表。
- `reports/avatar-library-review/`：由已经完成的标注反向生成的类别、强度和连续动作审查图。
- `reports/avatar-renders/<任务 id>/`：目标口型、实际选帧、切换和技术检查报告。
- `reports/avatar-insets/<任务 id>/`：最终角色窗的联系表和合成报告。

不在 `avatar-project.json` 重复保存角色、裁切、文件路径、哈希、生成供应方或权利信息。注册资源由 id 与版本解析到唯一 `library-package.json`；实际文件和来源再由素材库包自己的 `media-sources.json` 解析。不要把某次台词或某个音频写进角色库。

Skill 源码可以保存已经注册的具体角色包；某次口播的语音时间轴、`plans/`、`working/`、渲染报告和成片必须保存在当前 `artifacts/<task-id>/`，不能进入 `assets/`、`scripts/` 或 `references/`。初始化器与采用入口都会拒绝 Skill 任务工作区之外的可变运行项目；正式资源检查只从注册表验证长期包、素材哈希、视觉口型库和审阅证据，不遍历 `artifacts/` 并把旧任务误认成活动资源。

旧版 v1 项目只能由独立迁移入口读取：

```powershell
python scripts/anime-avatar-project.py migrate-library `
  --source-project <旧项目目录> `
  --library-id <注册 id> `
  --display-name <角色名> `
  --version <x.y.z> `
  --confirm-closed-motion-exhaustive-review
```

最后一个参数不是绕过检查：只有 Agent 已完整查看旧源视频与嘴部联系表，并确认旧库没有在达到三段闭嘴后提前停止，才允许传入。迁移再验证旧素材哈希、真实校准视频、口型帧合同和审阅证据，写入 v3 素材账本、v3 视觉口型库、版本化包和注册表；正常项目只接受当前版本，不保留旧运行兼容分支。旧项目不会被删除或覆盖。

`avatar-insets/<任务 id>.json` 不属于角色身份或口型库。相同角色进入不同底片时，窗口大小、位置和声音关系可以各自变化；角色库保持不变。

## 从零建立一个新角色

### 1. 形成角色规格

只有文字设定时，先把以下内容写成项目级角色规格：年龄感与气质、脸型和五官比例、瞳色、发型与发色、动物耳或其它轮廓特征、不可丢失的发饰、服装、关键胸前饰品、色彩、线条和上色方式。只记录用户确认的身份事实，不从参考风格推导新设定。

有参考图时，先检查身份元素是否清楚。参考图可以是倾斜姿态、透明底或全身图，但下游母版必须重新满足固定的头肩构图。参考图进入素材账本，生成母版时是唯一人物身份参考；不要同时加入风格相近但身份不同的人物图。

### 2. 生成并确认母版

初始化命令会把 `assets/anime-avatar-prompts/master-image.md` 复制到项目 `prompts/`。把角色规格和参考方式填入模板后使用。

合格母版必须同时满足：

- 正方形、高分辨率、正面自然头肩构图；头部直立、双肩基本水平、视线看向观众。
- 猫耳、呆毛、发梢、发饰、肩部和胸前关键饰品都在安全边距内。
- 服装在整条画面底边连续铺满。以后使用圆形裁切时，圆弧底部必须仍是衣服，不能露出白色楔形、黑角或截空。
- 纯白不透明背景，背景无渐变、阴影、光晕、暗底残留和抠图毛边。
- 眼睛自然睁开，嘴自然闭合或只有极浅微笑。母版不承担口型素材。
- 线条清楚、稳定的日系二次元赛璐璐上色；无糊化、涂抹感、双重五官。
- 没有圆框、边框、定位点、锚点、辅助线、字幕、文字和水印。

检查母版时看整张图，不只看脸。身份、底边衣服覆盖和轮廓安全区任何一项失败，都在母版层重做；不要期待后续裁切或定位脚本补救。

母版经用户确认后作为 `master_source_id` 写进项目内 `avatar-library/library-package.json`，状态改为 `confirmed`。母版一旦变化，原校准视频和原口型库全部失去身份依据，必须重新生成；不要保留兼容到旧母版的混合库。

### 3. 生成 15 秒校准视频

使用 `assets/anime-avatar-prompts/motion-source-video.md`。用户尚未生成视频时，先原样交付这份完整提示词和本节合格条件；已经授权完整制作时直接提交，不再让用户转述内部要求。母版必须是视频首帧和唯一人物参考。推荐校准语音是两轮短促而完整的：

> 嗯。啊。咿。呜。诶。哦。……嗯。啊。咿。呜。诶。哦。

它不是最终口播，职责只是为同一人物收集六类视觉口型和连续细节运动。每个音节只完成一次自然的“闭合或弱开 → 发音峰值 → 回落”，不能把一个元音持续喊很久，也不能快速反复开合。

15 秒的推荐节奏与正式提示词保持一致：

- `0.0–0.8s`：闭嘴自然停留，保持轻微呼吸。
- `0.8–6.5s`：第一轮中等幅度 A/I/U/E/O，每个音节短促完成并回到闭嘴。
- `6.5–7.5s`：闭嘴停留，可有一次自然眨眼。
- `7.5–13.2s`：第二轮完整幅度 A/I/U/E/O，身份和构图不变，只允许不同的微表情、发梢或耳朵细节。
- `13.2–15.0s`：闭嘴收尾，动作继续但逐渐稳定。

两轮的意义是为同一口型提供不同但连续的头发、耳朵、眼睛、饰品和肩部运动，减少新台词中的机械重复。视频不需要覆盖所有音素排列；运行时保留全部音节核心作为依据，再让过密核心进入可追溯的协同发音 cluster，以主核心和连续动作共同决定实际呈现。

合格校准视频必须固定机位、固定构图、固定缩放和固定人物底部。允许的生命感是克制而连续的眨眼、呼吸、眼神微动、发梢滞后、呆毛小摆动、猫耳偶尔小幅反应和饰品轻微惯性。头部大幅摇摆、点头、身体漂移、镜头运动或自动重新构图都会在换口型时放大成跳变，发现后直接重做校准视频，不用后期坐标追踪掩盖。

纯白背景可以直接保留，不需要抠图或绿幕。生成器自行加在底部的字幕不属于素材；在 `source_crop_xywh` 中用一个固定裁切排除字幕，但不能裁掉耳朵、呆毛、肩膀或底边衣服。

### 4. 先看素材，再建立视觉标注

本节全部是 Agent 内部生产。用户不负责选择帧、判断口型、填写强度、编写 `visual-viseme-library.json` 或重新排列校准视频。

把母版和校准视频导入项目内素材库包的素材账本后，用公开入口一次绑定身份与固定裁切：

```powershell
python scripts/anime-avatar-project.py configure-source `
  --project <项目目录> `
  --master-source-id <母版 source id> `
  --motion-source-id <校准视频 source id> `
  --source-crop <x,y,width,height> `
  --mouth-review-crop <x,y,width,height>

python scripts/anime-avatar-project.py prepare-review --project <项目目录>
```

脚本只做以下机械工作：

- 用 FFprobe 读取真实帧率、尺寸和时长。
- 按固定裁切抽取带帧号和时间的整帧联系表。
- 按 Agent 在项目中确定的嘴部审查区域生成高频局部联系表。
- 保存抽样清单，确保之后的视觉判断可以回到原视频帧。

它不得通过像素阈值、嘴部轮廓面积、人脸关键点、聚类或图像差分推断口型或强度。

Agent 必须直接查看联系表，必要时再查看原始单帧，并写出 `visual-viseme-library.json`。视觉分类依据是口唇形状，不是嘴洞面积：

- `A`：纵向明显、较放松的开口。
- `I`：嘴角横向展开，开口较浅。
- `U`：紧凑、前收、圆或短圆缝；`U4` 仍可能很小。
- `E`：较宽的横向开口，强级别可看到明显口腔和舌面。
- `O`：纵向圆形或高椭圆，不能和横向的 E 混淆。
- `CLOSED`：双唇闭合或自然微笑线，没有可见口腔。

每条动作内部的 `0–4` 阶段只描述它从低口型到自身峰值再回落的相对进程。另用 `peak_strength_level`（`1.0–4.0`）描述这条完整动作的发音力度，以便同一元音的中等幅度 take 和完整幅度 take 按音频强弱选择。不要把 `U4` 和 `E4` 当作几何尺寸相同的嘴；`U` 的完整力度仍可以是很小的前收圆口。

标注时必须给出：

- 覆盖整条校准视频的 `runtime_state_spans`。
- 穷尽标注源视频中所有视觉上成立、具有连续自然次级运动的闭嘴区间；开头、中间和结尾各一段只是最低覆盖门，不是找到三段就停止提取的数量目标。
- 每类元音至少一条视觉成立的完整动作；素材实际存在第二条独立 take 时全部标出。不能用复制 take 或修改数字满足数量。
- 每条 gesture 必须标注 `peak_strength_level`；若两条 take 实际力度相同就如实写相同值并在验证报告中显示缺少强弱变化，不能只凭“take 1 / take 2”假定它们一弱一强。
- rise、fall 各五个代表帧，对应强度 `0–4`。
- 所有阶段帧都必须真实位于 `[start_frame, end_frame_exclusive)`；`fall_frames_by_intensity[0]` 必须就是 `end_frame_exclusive - 1`，不能用不存在的 exclusive 边界充当审核帧。
- peak 的连续帧区间，以及适合人工复核的代表帧。
- 原视频中自然存在的元音到元音相邻过渡区间。`CLOSED` 与元音之间由各动作自身的低口型入口或出口承接，不登记成只靠状态名猜测的 natural span。
- 实际查看过的联系表、标注日期和判断说明。

标注完成后运行：

```powershell
python scripts/anime-avatar-project.py validate-library --project <项目目录>
python scripts/anime-avatar-project.py render-library-review --project <项目目录>
```

校验器只检查协议、source id、真实帧率、帧边界、覆盖、重叠、类别、闭嘴动作、自然过渡和 AI 已标注的强度事实；它不重新判断视觉标签，也不把某个数量标签包装成自然度结论。

然后 Agent 必须查看 `reports/avatar-library-review/` 中的类别强度表、E/O 对比、闭嘴表、每条 rise/peak/fall 连续条带和每条自然过渡条带。自然过渡要同时检查头肩姿态、眼睑阶段、视线，以及头发、耳朵、呆毛和饰品的运动方向；只看切口两张静帧不算完成审核。分类或过渡错了就改标注真源，不在渲染器里添加角色专属例外。

## 为一段新语音建立时间轴

先确定声音真源。用户已经提供录音、含原声视频或确认的声音文件时，后续所有处理必须绑定这条原声；即使用户同时给了准确台词，也不能把台词解释为重新合成声音的授权。口播视频需要声音但没有另一条必须保留的现成声音时，按主入口当前视频默认声音和语速进入文本转语音；用户明确指定其它声音或读法时覆盖默认。

### 文本转语音

进入文本转语音后，按 SKILL 已经路由加载的语音合成流程生成原始 TTS，保留确切合成文本、声音身份和供应方返回的时间信息。优先使用供应方的 word/character boundary；把它规范化为 `schemas/speech-timeline.v2.schema.json`。

使用当前环境已有的 EdgeTTS 且已经获得调用授权时，可直接运行：

```powershell
python scripts/synthesize-avatar-speech.py `
  --text-file <UTF-8 合成文本> `
  --voice <准确声音 id> `
  --audio-source-id <准备写入素材账本的 id> `
  --output-audio <原始 mp3> `
  --output-timeline <speech-timeline.json>
```

脚本会同时保存供应方的原始 `WordBoundary`。当一个供应方边界包含多个汉字时，它只在该真实边界内部依据音频低能量点细分，不把整句平均切开。新时间轴故意以 `timing.reviewed=false` 写出；试听并确认逐字边界后改为 `true`，再把音频以同一个 source id 导入 `media-sources.json`。精确声音不存在时停止，不能静默换声。

用户明确要求使用已授权参考音频克隆声音时，通过 MediaFlow Pro 本轮公开的 `speech.synthesize` 生成并验证真实 WAV，再用返回的参考音频哈希建立稳定声音身份并导入同一个 v3 素材账本。`scripts/synthesize-avatar-speech.py` 仍只负责 EdgeTTS 的供应方边界，不包装 GPT-SoVITS，也不伪造它没有返回的逐字时间。GPT-SoVITS 音频必须以准确目标文本完成音频对齐和逐字听音复核后，才能写入正式 `speech-timeline.json`。

如果其它供应方只返回句级或词级时间，不要把整句平均分给每个字然后直接正式交付。可以用音频对齐工具细化，但必须以确切合成文本为准，并听音复核明显边界。

### 用户录音或视频中的声音

先确认逐字稿，再确定需要裁掉的前置静音和尾部。自动转写只能作为起点；转写结果与用户确认文本不一致时，以确认文本为准重新对齐，不能让错误 ASR 文本进入口型渲染。

`speech-timeline.json` 中：

- `trim_start_seconds` 和可选 `trim_end_seconds` 针对原素材。
- `audio_sha256` 必须与素材账本中的真实音频一致。
- `time_origin` 固定为 `trimmed-audio-start`。
- `units` 的时间从裁切后的 `0` 开始。
- 每个普通话汉字是一项，顺序必须与 `text` 去除标点后的汉字完全一致。
- `timing.reviewed` 正式渲染前必须为 `true`。

录音开头的无声区间要先判断是否属于成片节奏。需要去掉时，实际听音或看波形后把裁切写入时间轴，并让所有字时间相对于裁切后音频；需要保留时不裁切，第一字仍写真实起音时间，角色在此前自动播放闭嘴动态待机。

正式规划前运行 `scripts/validate-avatar-speech-timeline.py`，并传入 `--require-reviewed`。它会从项目素材账本重新解析真实音频、核对 sha256、裁切范围、文本顺序和逐字边界；只输出验证报告，不重写时间轴。

角色素材库和新语音时间轴通过各自质量门后，本阶段完成；渲染、角色窗合成与最终验收由活动任务的独立制作路径继续执行。
