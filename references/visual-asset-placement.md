# 视觉素材选择、放置与来源

用于网页卡片、封面、GIF 或视频画面中实际使用照片、产品图、网页截图、应用截图、录屏帧、图标和生成素材。目标是让素材承担证据或视觉职责，同时保留来源、裁切和后续替换能力。

## 一、先确认能否使用

只使用用户提供、项目已有或用户明确允许获取的素材。每项外部、用户提供或生成素材都按 `media-project-contracts.md` 记录到项目唯一的 `media-sources.json`；完全由 HTML、CSS 或内联 SVG 在项目中生成的图形也记录为 `generated-in-project`，但完整性为 `null`，不虚构外部文件或来源。

用户提供、项目自有、外部下载或已经在项目内确定性生成的独立文件使用 `scripts/import-media-asset.mjs` 导入。需要调用外部生成服务时，先在 `generation-jobs.json` 完成规范化输入、费用授权、提交锁、远程任务、回执和下载校验，再由任务管理器调用同一导入器本地化。导入器按内容哈希保存文件并记录取得方式、权利、实际字节数、MIME、SHA-256、生成信息与回执；合成声音再记录声音身份和实际输入文本哈希。导入完成只表示候选素材已进入项目，不能自动写入网页场景、视频时间线或音频项目。

向 editable-media v5 网页包的 media-sources v4 素材账本导入文件时，必须额外传入 `--pipeline browser|native-underlay|native-audio`。普通图片和 DOM 内媒体使用 `browser`；MediaFlow Pro 需要在网页透明层下方原生合成的视频使用 `native-underlay`；独立音轨使用 `native-audio`。导入器不会根据扩展名猜测视觉职责，也不会把通用 media-sources v3 素材账本升级成网页账本。

坐标使用原素材中的归一化位置，具体输出变体裁切保存在 `crops` 对应变体项中。`media-sources.json` 负责来源、唯一文件路径和素材级判断；网页清单的 `media-source` 数据字段只保存 source id，负责该素材进入哪个场景槽位和图层。文件路径变化时只修改来源记录，采用关系变化时只修改 source id；HTML 和 `resources` 不再保存同一媒体路径。

未知授权、需要付费、带水印或明显属于不可公开使用的素材不能先放进成品再补问。找不到合格素材时使用当前内容能够支持的无图版式，或说明缺少哪类素材。

## 二、先确定槽位，再处理素材

场景先在 `layout_contracts` 选择内容版式，再处理或生成图片。每个素材槽位声明比例、`cover` 或 `contain`、是否必须保留完整画面；场景的 `asset_slots` 把槽位绑定到实际 image 数据字段。网页运行时、校验器和结构化编辑器都读取这次绑定，不另存一份图片用途。

截图、界面证据和必须完整展示的图使用 `contain`；照片、纹理或背景可以使用 `cover`，再读取素材主体位置和当前输出变体裁切。生成图片时把最终槽位比例、主体安全区和构图方向写入生成要求；先生成通用横图再强裁成窄槽，只在主体安全区已经证明适配时使用。

## 三、先分类，再选择处理方法

照片和产品图使用“主体优先”的裁切；网页、应用、代码、仪表盘和对话截图使用“信息完整”的容器。不能把截图当普通照片直接 `cover` 裁切，也不能为了保留照片全部边缘而让主体小到失去作用。

先记录素材真正的阅读对象：

- 人物照片：脸、视线、手势和身体方向。
- 产品图：产品轮廓、功能部位和品牌识别区域。
- 场景照片：主要物体、地平线、动线和可放文字的低干扰区域。
- 截图：用户需要核对的窗口、面板、代码段、数值或操作结果。
- 录屏帧：当前语义片段中的关键状态，以及状态变化会经过的范围。

只有这些对象清楚，才决定图片槽位、裁切、缩放和文字位置。

### 真人创作者封面的参考职责

制作真人创作者封面时，先按消费者职责区分输入素材，并在后续任务中通过 source id 保持这些职责：

- **人物身份参考**只负责保持当前创作者的脸部、发型和稳定身份特征。它来自用户本次提供的素材、当前项目已经入账的 source，或项目显式采用的 `creator-media`；署名头像不承担出镜素材职责，库中存在的资源也不会自动成为本次人物。
- **证据参考**负责保留产品、界面、数据、前后对象或作品成果的真实内容。需要观众核对的界面和文字作为网页中的独立素材槽位使用，不交给生成模型重绘。
- **视觉参考**只影响用户明确要求的构图、材质、色彩或光线层。参考中的人物身份、标题、品牌、观点和固定场景不随风格一起进入当前作品。

需要外部模型生成新的人物、道具或场景素材时，任务说明使用实际 source id 和上述职责，写清人物朝向、视线、双手动作、与主要对象的距离、目标输出变体以及必须留出的标题区域。人物身份只由当前授权的身份参考决定；产品或界面证据继续由独立素材承担。生成层保持标题区无文字、无水印、无伪造界面和无需要逐字读取的信息，准确标题、数字、标签和来源由网页图层完成。

生成结果下载并校验后仍按普通独立文件进入项目素材账本，再由当前人物或场景槽位显式采用。目标包含多个输出比例时，先判断同一人物素材能否在各比例中保持脸部、手势、主要道具和标题空间；不能成立的比例使用独立构图或分层素材，不从已经合成的单一比例成品硬裁。

## 四、照片与文字叠放

全画布照片在进入排版前做两项检查：

1. 主体和重要细节在目标比例裁切后仍完整。
2. 至少有一块足以容纳标题的低干扰区域；标题区域不能跨过脸、产品关键部位、高对比边缘或密集纹理。

默认处理顺序：

1. 选择更适合目标比例、光线和文字位置的素材。
2. 调整图片槽位和 `object-position`，让主体与文字各自成立。
3. 移动标题到合格的安全区。
4. 仍然不足时，只在文字附近增加局部色调、轻微渐变或文字底色。
5. 以上方法都无法成立时改成图文分栏，不用整张黑色蒙版掩盖错误素材。

文字叠放通常只使用一个主要安全区。标题不环绕主体，也不把一句话拆到三个互不相连的位置。人物视线前方优先保留呼吸空间；脸在上方时不要把裁切继续推向顶部。每个输出变体把最终 `object-position`、焦点或裁切矩形写入可编辑状态，不能依赖浏览器默认居中。

全画布预览通过后，再缩到约 360 像素宽或目标平台实际缩略图尺寸检查。标题需要第一眼可读，主体仍可识别；看不清时先换图、换位置或改短标题，不直接加重蒙版。

## 五、截图与界面证据

截图先裁出真正需要展示的窗口、面板或结果。无关浏览器标签栏、桌面、状态栏、Dock、光标残影、通知、被截断的旁页文字和背景界面不进入成品，除非它们本身就是证据。

截图容器默认：

- 使用 `object-fit: contain`，保留关键界面完整性。
- 使用稳定内边距、安静底面和清楚边界，让截图与画布分开。
- 不添加透视、斜切、旋转或 3D 倾斜，除非用户明确要求设备场景或广告样机。
- 需要设备外框时只增加一层浏览器或手机框，不把截图自身圆角、窗口边框和外部容器重复叠加。
- 同一页有多张截图时统一缩放基准、边框、底面和说明位置。

只有截图四周本来就是可裁区域，而且裁切不会丢失菜单、标签、数值或操作结果时，才允许 `cover`。最终整图缩小时仍看不清界面文字的截图，改成局部放大、重点框选或“截图 + 摘要”结构，不能假装完整截图仍可阅读。

## 六、录屏帧和运动素材

先用 FFprobe 或等价工具读取真实分辨率、时长、帧率和音轨。素材较长或关键时刻不明确时，用 `scripts/make-video-contact-sheet.py` 抽取少量代表帧，只看最终联系表决定区间和裁切；不要默认把大量单帧加载进上下文。

选定片段后先抽取静态代表帧，在目标内容版式和输出变体中确认主体、裁切、标题和边界。正式视频、GIF 或 Live Photo 必须沿用相同几何关系。素材会滚动、切换面板或改变主体位置时，检查整个选定区间，不能只让首帧正确。

## 七、检查顺序

1. 运行 `scripts/validate-media-sources.mjs`，核对来源记录、文件、字节数、哈希和授权范围。
2. 在原比例查看主体和关键界面。
3. 在每个目标输出变体检查裁切、焦点和文字安全区。
4. 在完整画布检查层级、对齐和图片色调。
5. 在缩略图检查标题、主体和证据是否还能识别。
6. 导出后重新打开最终文件，确认浏览器预览中的裁切和资源没有丢失。

用户更换素材时以新的 source id 导入，再更新清单引用和受影响输出变体裁切；不能让原 id 静默改指其它内容，也不在 HTML、导出脚本和说明文档中分别替换同一路径。
