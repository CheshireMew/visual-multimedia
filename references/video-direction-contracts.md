# 视频导演语义合同

用于两类视频任务：用户明确把一份已经确认的长文或长内容改成视频；任何视频在制作前需要决定“谁出现在画面里”。本合同只保存内容到视听表达的导演意图，不保存剪辑顺序、素材文件事实或第二份时间线。

## 一、启用条件

只有用户同时提供或指向一份已经确认的长内容，并明确要求把它制作成视频时，才建立 `video-direction-plan.json`。普通短视频、已有脚本的直接后期、只要分镜建议或尚未确认内容的请求，不为形式完整增加此文件。

任何视频都先确定出镜方式：

- `human`：使用已经授权并进入 `media-sources.json` 的真人实拍、访谈、讲课或录屏素材。导演计划只引用 source id，不复制素材事实。
- `none`：无人物出镜。画面由证据、产品、界面、网页视觉、图形或环境素材承担。

出镜方式会改变大部分画面而当前上下文无法判断时，只确认这一项。真人必须带有效 source id；无人物模式不得偷偷加入生成主持人。角色生成或数字人口播当前没有活动生产入口，因此导演合同不提供这类出镜模式。

## 二、唯一内容边界

长内容本身仍是唯一内容真源。正式计划必须保存其不可变快照、字节数、SHA-256、`source_id`、`source_version` 与 `content_unit_id`，并记录当前 `media_script_version`。快照用于证明当时读取了什么，不是可以继续编辑的第二份内容。

进入导演计划前形成内容简报：

- 受众是谁，已经知道什么。
- 视频对受众承诺解决什么问题。
- 核心主张是什么。
- 哪些支撑点使主张成立，每一点回到哪些 `source_refs`。
- 必须保留的事实、数字、名称和条件。
- 容易夸大、误读、失去语境或需要额外核对的风险。

旁白必须处于 `confirmed`，并保存文本哈希和来源引用。对原内容发生的主要删减、重排、合并、措辞变化或立场边界变化逐项说明，并记录确认状态与证据；纯断句、发音拼写和字幕压缩不算主要编辑变化。内容含义发生变化时先更新媒体文案和版本，再重建计划，不能直接改分镜掩盖变化。

发音表把三件事分开保存：原文写法、实际读法和必要说明。原文、字幕和屏幕文字继续使用准确写法；合成输入可以采用实际读法。发音表只解决朗读，不得改变名称、数字或事实。

## 三、场景计划不是剪辑时间线

每个语义场景至少保存：

- 稳定的 `segment_id`。
- 一个或多个 `source_refs`。
- 当前场景的内容目的。
- 对确认旁白的 `voiceover_ref`。
- 画面职责与 `graphic_type`。
- 当前出镜布局。
- 时长来源，以及仅供估算的秒数。
- 需要外部生成时引用的 `generation_job_ids`。

场景计划不保存绝对起止时间、轨道、转场参数、素材入点、素材出点、音量曲线或最终镜头顺序。真实语音、原片或固定规格到位后，视频时间线才决定这些值；MediaFlow Pro 或当前视频项目仍是时序和装配的唯一真源。导演计划可以说明“这一段为什么存在、画面要讲清什么”，不能变成另一套可播放时间线。

每个场景必须至少引用一个当前来源版本的位置。引用格式统一为 `<source_id>@<source_version>#<位置>`，例如章节、段落、时间码或内容单元。外部生成任务必须反向引用使用它的 `segment_id`，没有任务引用时使用空数组。

## 四、正式生产入口

先准备一个只含导演判断的 JSON 输入，再由正式生产者绑定真实长内容：

```powershell
node scripts/create-video-direction-plan.mjs `
  --project <项目目录> `
  --source <已确认长内容文件> `
  --draft <导演输入.json>
```

生产者把源文件复制到项目内的内容寻址快照目录，计算输入与旁白哈希，写入唯一的 `video-direction-plan.json`，再调用与 `schemas/video-direction-plan.v1.schema.json` 同边界的验证器。相同来源和相同导演输入重复执行只复用现有计划；来源、版本或导演输入变化时拒绝静默覆盖，先建立新的明确版本。

校验命令：

```powershell
node scripts/validate-video-direction-plan.mjs `
  <项目目录>/video-direction-plan.json
```

## 五、进入制作

导演计划通过后：

1. 现有真人、证据、界面、图片和声音仍先由 `media-sources.json` 管理，再由视频时间线显式采用。
2. 需要外部模型或服务生成的场景，先建立 `generation-jobs.json`，完成费用与任务状态闭环；本文件只保留 job id。
3. 真实声音或原片到位后，用实际时长更新视频时间线，不回写一套绝对时间到导演计划。
4. 用户改变核心主张、确认旁白、来源版本或出镜方式时，当前计划失效；只改变剪辑参数时修改活动时间线。

## 六、检查

- 源快照、导演输入和确认旁白的哈希是否与真实文件或文本一致？
- 核心主张、支撑点、必要事实和风险是否都能回到当前来源版本？
- 主要编辑变化是否已经记录并确认，而不是被分镜悄悄改写？
- 每个场景是否只描述语义和导演职责，没有复制剪辑时间线？
- 真人是否引用已授权素材；无人物模式是否没有暗中加入生成主持人？
- 发音表是否只改变读法，没有污染原文、字幕和事实？
- 外部生成场景是否只引用任务 id，任务状态与费用是否留在独立合同？
