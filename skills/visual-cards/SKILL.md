# Visual Cards

## 目标

把已经成立的内容做成真正看得清、改得动、能导出的静态社交卡、封面、信息图或轮播图。普通单卡默认交付一份轻量、自包含、固定画布的 HTML，以及用户点名的 PNG；不为了一张卡先搭建完整媒体工程。

本 Skill 不研究主题、不补充事实、不从零写文章，也不制作动画、视频或音频。仓库内引用的 `references/`、`assets/` 和 `scripts/` 路径都相对于 Visual Multimedia 套件根目录；只读取当前任务列出的资源，不加载整个套件。

## 工作方式

先确认内容真源、目标受众、最终图片的实际展示位置、用户要求的格式，以及已有网页或图片是否必须沿用。用户要求“在当前基础上优化”时，先打开现有真源和真实预览，保留仍然成立的内容与结构；没有证据支持整体改版时，只做内容重排或局部换装，不能从空白重建。

### 文案进入画面前

用户已经明确确认观众可见文案时，逐字沿用，不再重新清理。用户给的是草稿、长稿或尚未确认的上图文字时，先形成一份只做取舍、不增加新事实的候选文案，再使用 `$clean-copy` 检查主次、重复、指代和 AI 式空话；遵守它先列修改、等待确认、再执行一次的边界，不在本 Skill 内复制第二套废话筛选器。删除后仍不影响核心对象、必要支撑、意义边界和实际行动的信息才允许退出。

### 独立的作图前确认

正式作图前一次提交：逐字可核对的最终上图文字；信息层级和阅读顺序；必要数据、来源、图片与图标；最小实际展示宽度；由内容量推导的方向、宽度、高度和比例；字体角色、配色职责与表面方向。提交后停止。确认前不得创建网页、套模板、画画布或导出图片。只有用户明确要求“跳过确认，直接作图”才跳过这道视觉确认；这不会自动跳过 `$clean-copy` 自己的内容确认。

先按最终展示宽度确定可读字号，再反推源画布。没有平台依据时按约 360px 宽检查：主要正文以约 16px 为舒适目标，承担核心理解的标题、正文、表格和分区代表文字不得低于 14px；来源和页码可以更小，但不能承载关键解释。画布宽高由筛选后的内容、阅读字号、平台限制与实际展示宽度共同决定。固定画布只表示成品不会随窗口响应式重排，不表示预先锁死竖版、横版或旧比例。内容放不下时，依次删掉已确认可删的重复与次要信息、重排、增宽或增高、改变方向，必要时拆页；不得靠缩字、压字距或保留大片无理由空白解决。

### 默认轻量制作

普通单卡、单封面和结构简单的信息图使用一份自包含 HTML：文案、结构和 CSS 变量都在同一文件，固定画布只等比缩放预览。不要创建 `editable-media.json`、场景清单、风格档案、编辑器、启动器、代理素材、MediaFlow Pro 工程或多套导出脚本。只有用户明确需要多场景、多比例批量、画布外表单编辑、可复用模板、结构化图层 API 或后续动画时，才升级到 `editable-media` v6，并读取完整网页生产资源。

版式由信息关系决定，不从模板尺寸反推内容。标题、摘要、指标、表格和提醒只有承担不同职责时才同时存在；同一事实只有一个主要位置。首屏可以横向放在同一行的内容不要因模板列强行拆开；线条、边框和色块都必须说明结构，重复横线和无作用容器直接去掉。配色先读取用户指定的配色卡、品牌或当前项目视觉；没有指定时再从调色板与制作配方中选一组职责清楚的颜色，不按“技术内容必然蓝色”之类关键词机械套色。“看看、参考、分析”等要求只提供证据，不等于采用案例；自动选择只决定待确认样稿。新的或实质变化的视觉方向确认后才写入风格档案并进入这些下游。

修改现有卡片时，把反馈定位为内容重排、局部换装或整体改版。“太丑”本身不等于整体改版；先从实际预览指出字号过小、主次同权、色块面积失衡、无理由空白、重复分隔线或对齐错误。删除、移动或增加可见内容后重新计算受影响分区和整张画布，不能只把文字设为空后留下旧占位。

制作后打开真实 HTML，分别查看原尺寸完整画布和最小展示宽度预览；检查字体加载、中文与符号、溢出、裁切、来源、阅读顺序、颜色面积、空白与对齐。用户给出标注截图时逐个对应标注区域复查。PNG 必须由同一 HTML 的当前版本导出并重新打开；技术可打开不等于视觉已经成立。

## 输出与完成

交付当前活动 HTML、用户点名的 PNG、实际展示宽度与画布尺寸，以及真实查看后发现并已解决的问题。高级路径再交付网页清单和对应检查结果。没有用户要求时不自动生成其它比例、轮播页、动画或发布文件。
