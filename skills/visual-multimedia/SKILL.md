# Visual Multimedia

<!-- 多 Skill 仓库中的活动编排入口 -->

## 作用

这是 Visual Multimedia 套件的轻量编排入口，不直接承担作图、动画、剪辑、声音或角色制作。单一成品直接进入对应子 Skill；只有请求确实需要选择载体、两类以上成品或跨媒体装配时，才使用本入口。

不要为了“完整”同时读取全部子 Skill。先确定最少路线，只打开被选中子 Skill 的 `SKILL.md` 和它明确列出的资源。仓库中的共享 `references/`、`assets/`、`schemas/` 与 `scripts/` 是一份公共程序层，不复制进每个子 Skill，也不因存在于仓库中就自动加载。

## 内容进入制作前

先确认允许使用的内容真源、目标受众、实际交付物、已有素材和不能改变的事实边界。

- 观众可见文案已经被用户明确确认：按原文传给下游，不重新改写。
- 用户提供的是初稿、成稿或尚未确认的上图/口播文案：制作前先使用 `$clean-copy`。它先给读者、编辑和 Clean Copy 三轮具体意见并停止，只有用户确认后才执行一次；本套件不复制第二套“AI 废话筛选器”。
- 用户只有确认过的来源材料、没有载体文案：先由被选中的子 Skill 做不新增事实的载体取舍，形成准确候选稿，再进入 `$clean-copy`。
- 用户只修改画面、动效、剪辑、声音或角色，当前可见文案没有变化：不为形式重跑 `$clean-copy`。

内容确认与视觉确认是两道不同的门。`$clean-copy` 负责文案是否成立；静态卡和其它正式视觉在实现前仍按对应子 Skill 提交一次可见文案、层级、尺寸和视觉方向。用户明确跳过视觉确认，不等于授权自动采用尚未确认的文字修改。

## 选择最少路线

| 需求 | 直接使用 | 交付边界 |
| --- | --- | --- |
| 静态社交卡、封面、信息图、轮播图 | `$visual-cards` | 轻量 HTML 或明确需要的高级网页包，以及指定图片 |
| 网页动画、动态图解、GIF、解释型 B-roll | `$web-motion` | 一份网页真源、一条确定性时间线和指定动态媒体 |
| 实拍、访谈、录屏、产品宣传片、GitHub 介绍、素材解说 | `$video-production` | 视频时间线或原生工程、成片和审阅证据 |
| 录音、旁白、对谈、播客、合成语音 | `$audio-production` | 音频时间线、声音文件和试听证据 |
| 二次元口播角色、口型、方向、角色窗 | `$avatar-video` | 版本化角色资源、角色轨或透明角色窗 |

单项任务即使由用户点名 `$visual-multimedia`，也只读取对应一个子 Skill 并按它完成，不保留总入口的旧流程。

## 组合任务

组合任务只在真实接口处协作：

- 网页动画插入实拍视频：`$web-motion` 先交付实际片段和时间边界，`$video-production` 再装配。
- 二次元角色进入完整节目：`$avatar-video` 先交付角色轨或透明角色窗；只有需要生成或编辑声音时才加 `$audio-production`，最后由 `$video-production` 装配。
- 视频另需独立封面：视频与静态封面分别由 `$video-production` 和 `$visual-cards` 完成，共用同一确认文案版本，不让封面模板反向改变视频主张。
- 同一内容同时要静态卡与动画：两个子 Skill 共用内容版本和视觉身份，但分别按静态构图与时间运动重新组织；不复制坐标或把静态页面机械加淡入。

每次交接传真实文件路径、内容版本、素材 ID、时间边界、画布规格、哈希或采用记录。不要把另一个子 Skill 的完整说明重新塞进提示词，也不要让下游根据摘要猜测上游实际产物。

## 修改与失败

用户要求在现有成品上优化时，优先回到创建它的子 Skill 和活动真源。只让最早受影响层及必要下游失效；视觉反馈不是自动重做，删改内容后要重新计算相关画布，改声音后要重新投影受影响时间，换角色资源后要重新检查角色轨。

某个子 Skill 缺少素材、工具或授权时，保留已经成立的上游成果并准确报告缺口。不要因此加载所有其它路线或静默换成不一致的制作真源。

## 完成

组合任务完成时，列清每个子 Skill 实际交付的文件、它们之间的采用关系、最终成品和真实检查结果。只交付用户点名的载体、比例、时长和格式；不自动发布，也不扩张为其它平台版本。
